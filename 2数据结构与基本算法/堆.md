  - #### https://zhuanlan.zhihu.com/p/1935095532931487460

当一个程序启动运行时，操作系统会为其精心规划一片内存空间，这片空间被巧妙地划分为五个独特的区域，各区域各司其职，共同保障程序的顺畅运作

- 1、栈区（stack）：由编译器自动分配释放 ，存放为运行函数而分配的局部变量、函数参数、返回数据、返回地址等。其操作方式类似于数据结构中的栈。
- 2、堆区（heap）：一般由程序员分配释放， 若程序员不释放，程序结束时可能由OS回收 。分配方式类似于链表。
- 3、静态区，亦称全局区。全局变量、静态变量和常量都是存储在该区的，程序结束后该区的变量由系统释放。该区具体又可以三部分：①已初始化的全局变量和静态变量；②未初始化的全局变量和静态变量；③常量数据区。
- 4、文字常量区：程序代码中使用的常量字符串，程序结束后由系统释放。
- 5、程序代码区：存放函数体的二进制代码。

```c++
int a = 0;	//全局初始化区
char *p1;	//全局未初始化区

int main()
{
	int b;	//局部变量，栈区

	char s[] = "abc";		//局部变量，栈区, abc在常量区
	char *p2;				//局部变量，栈区
	char *p3 = "123456";	//123456在常量区，p3栈区。

	static int c =0;		//静态变量，全局初始化区

	//动态函数分配的区域就在堆区。
	p1 = (char *)malloc( sizeof(char) * 10 );
	p2 = (char *)malloc( sizeof(char) * 20 );
	
	strcpy(p1, "123456"); //123456放在常量区

	return 0;
}
```

## ==栈区 (Stack)==

### 什么是栈区？

栈区是一种**后进先出 (Last In First Out, LIFO)** 的内存结构，由编译器自动管理，主要用于存储函数的调用信息和局部变量。

当一个函数被调用时，系统会在堆栈的顶部为其分配一块内存空间，用于存储该函数的局部变量和相关信息，这个过程称为 “压栈”（Push）。当函数执行结束后，这块内存空间会被自动释放，数据从堆栈中移除，这个过程称为 “出栈”（Pop）。由于堆栈的操作非常简单，只需要在栈顶进行压栈和出栈操作，所以它的速度非常快，就像在一摞盘子的顶部快速地放上或拿走盘子一样。

### 栈区的特点

1. **自动管理**：编译器自动分配和释放
2. **速度快**：内存分配只是移动栈指针
3. **大小有限**：通常较小（几MB）
4. **生命周期明确**：与函数调用周期一致
5. **连续内存**：内存地址是连续的

### 栈区的使用示例

```cpp
#include <iostream>
using namespace std;

void functionA() {
    int localVar = 10;           // 局部变量，在栈上分配
    char buffer[100];            // 字符数组，在栈上分配
    // 函数结束时自动释放
}

void functionB() {
    int x = 5;                   // 在栈上分配
    functionA();                 // 调用函数时，新的栈帧被压入栈
    // functionA返回时，其栈帧被弹出
}

int main() {
    int mainVar = 20;            // 主函数的局部变量，在栈上
    functionB();
    return 0;
}
```

### 栈的内存分配过程

```cpp
void example() {
    int a = 10;        // 在栈上分配4字节
    double b = 3.14;   // 在栈上分配8字节
    char c[5];         // 在栈上分配5字节
    // 函数结束时，所有这些自动释放
}
```

## ==堆区 (Heap)==

### 什么是堆区？

堆区是供程序员**手动管理**的动态内存区域，可以在程序运行时按需分配和释放。

在程序运行时，如果我们需要创建一个对象或者分配一块内存空间，就可以从堆中申请。例如，在 `C++` 中，我们使用`new`关键字来从堆中分配内存；在 `Java` 中，使用`new`操作符创建对象时，对象也会被分配到堆中。堆的优点是可以灵活地分配和释放内存，适合存储生命周期较长、大小不确定的数据。但是，由于堆的内存管理相对复杂，需要进行内存的分配和释放操作，所以它的速度相对较慢。

### 堆区的特点

1. **手动管理**：需要程序员显式分配和释放
2. **速度较慢**：需要寻找合适的内存块
3. **大小较大**：受限于系统可用内存
4. **生命周期灵活**：由程序员控制
5. **内存不连续**：可能产生内存碎片

### 堆区的使用示例

```cpp
#include <iostream>
using namespace std;

int main() {
    // 在堆上分配内存
    int* heapInt = new int(42);          // 分配一个int
    double* heapArray = new double[10];  // 分配double数组
    
    // 使用堆内存
    *heapInt = 100;
    heapArray[0] = 3.14;
    
    // 必须手动释放！
    delete heapInt;      // 释放单个对象
    delete[] heapArray;  // 释放数组
    
    return 0;
}
```



## 栈 vs 堆 详细对比

| 特性         | 栈区 (Stack)       | 堆区 (Heap)            |
| ------------ | ------------------ | ---------------------- |
| **管理方式** | 自动（编译器）     | 手动（程序员）         |
| **分配速度** | 快（移动指针）     | 慢（查找合适内存块）   |
| **内存大小** | 较小（通常几MB）   | 较大（可达GB级别）     |
| **生命周期** | 函数作用域         | 直到手动释放           |
| **内存布局** | 连续               | 可能碎片化             |
| **访问安全** | 相对安全           | 容易内存泄漏、悬空指针 |
| **使用场景** | 局部变量、函数调用 | 动态数据结构、大对象   |

## 实际代码示例对比

```cpp
#include <iostream>
using namespace std;

// 栈上创建的对象
class StackObject {
public:
    StackObject() { cout << "栈对象构造" << endl; }
    ~StackObject() { cout << "栈对象析构" << endl; }
};

// 堆上创建的对象  
class HeapObject {
public:
    HeapObject() { cout << "堆对象构造" << endl; }
    ~HeapObject() { cout << "堆对象析构" << endl; }
};

void demonstrate() {
    cout << "=== 进入函数 ===" << endl;
    
    // 栈上分配 - 自动管理
    StackObject stackObj;
    int stackArray[100];
    
    // 堆上分配 - 手动管理
    HeapObject* heapObj = new HeapObject();
    int* heapArray = new int[100];
    
    cout << "=== 函数执行中 ===" << endl;
    
    // 必须手动释放堆内存
    delete heapObj;
    delete[] heapArray;
    
    cout << "=== 离开函数 ===" << endl;
    // stackObj 和 stackArray 自动释放
}

int main() {
    demonstrate();
    return 0;
}
```

```
堆对象构造
=== 函数执行中 ===
堆对象析构
=== 离开函数 ===
栈对象析构
```

## 常见问题与陷阱

### 1. 栈溢出 (Stack Overflow)

```cpp
void recursiveFunction(int n) {
    int largeArray[1000];  // 在栈上分配大数组
    recursiveFunction(n + 1);  // 深度递归导致栈溢出
}
```

### 2. 内存泄漏 (Memory Leak)

```cpp
void memoryLeak() {
    int* ptr = new int[1000];  // 分配堆内存
    // 忘记 delete[] ptr;      // 内存泄漏！
}
```

### 3. 悬空指针 (Dangling Pointer)

```cpp
void danglingPointer() {
    int* ptr = new int(42);
    delete ptr;           // 释放内存
    *ptr = 100;           // 错误！访问已释放的内存
}
```

### 4. 野指针 (Wild Pointer)

```cpp
void wildPointer() {
    int* ptr;             // 未初始化
    *ptr = 42;            // 错误！指向随机内存地址
}
```

## 最佳实践建议

### 栈的使用原则

```cpp
// 适合在栈上分配的情况：
void goodStackUsage() {
    int localVar;                    // 基本类型
    double coordinates[3];           // 小型数组
    std::string name;               // 标准库对象（内部使用堆）
    
    // 对象生命周期与函数一致
    MyClass obj;                    // 栈对象
}
```

### 堆的使用原则

```cpp
// 适合在堆上分配的情况：
void goodHeapUsage() {
    // 大型数据结构
    int* largeArray = new int[1000000];
    
    // 需要延长生命周期的对象
    MyClass* persistentObj = new MyClass();
    
    // 多态对象
    BaseClass* polyObj = new DerivedClass();
    
    // 记得释放！
    delete[] largeArray;
    delete persistentObj;
    delete polyObj;
}
```

### 现代C++的智能指针

```cpp
#include <memory>

void modernMemoryManagement() {
    // 使用智能指针自动管理堆内存
    std::unique_ptr<int> smartPtr = std::make_unique<int>(42);
    std::shared_ptr<MyClass> sharedObj = std::make_shared<MyClass>();
    
    // 无需手动delete，自动释放
}
```

## ==总结==

- **栈区**：自动管理，速度快，大小有限，适合局部变量和短期对象
- **堆区**：手动管理，速度慢，大小大，适合动态数据结构和长期对象
- **关键区别**：生命周期管理和性能特性
- **现代实践**：优先使用栈，必要时使用堆+智能指针

理解栈和堆的区别对于编写高效、安全的C++程序至关重要！

# 算法中的堆

## 1. 什么是堆？什么是最小堆/最大堆？

**堆**是一种特殊的二叉树（准确地说是“完全二叉树”），并且要满足**堆的性质**：

- **最小堆**：每个节点的值 **≤** 它的孩子节点的值。
  → 树根（堆顶）就是整棵树里最小的元素。
- **最大堆**：每个节点的值 **≥** 它的孩子节点的值。
  → 树根就是整棵树里最大的元素。

## 最小堆?

用优先队列实现最小堆： [容器.md](D:\Typora\typora_work\c++_md\3高级面向对象\10顺序容器\容器.md) 

比如 通过`[1,4,2,7,5,6]`或`[2,4,1,7,5,6]`构建的一个最小堆是这样：

```tex
        1
      /   \
     4     2
    / \   /
   7   5 6
```

**特点**：

- 树是一层一层填满的，最后一层可以不满，但必须从左到右连续填充（完全二叉树）。
- 任何一个父亲都比孩子小（或相等）。
- 堆顶是 `1`，即最小值。

**关键操作**：

- **插入元素**：先把它放到树的末尾，然后向上“冒泡”（和父节点比较，如果比父节点小就交换），直到满足堆的性质。时间复杂度 O(log n)。
- **删除堆顶**：把堆顶取出来（最小值），然后把最后一个元素搬到堆顶，再向下“下沉”（和较小的孩子交换），直到满足堆性质。时间复杂度 O(log n)。

在 C++ 里，`std::priority_queue` 默认是**最大堆**（堆顶是最大值），但我们通过指定比较器 `greater<int>` 就能把它变成**最小堆**：

```c++
priority_queue<int, vector<int>, greater<int>> minHeap;
```

这样 `minHeap.top()` 总是返回目前堆中最小的元素。
