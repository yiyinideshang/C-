# 1.1继承

## 🧠 核心思想：模拟 "是一个" (is-a) 的关系

- **现实世界类比：** 想象一下 "动物" 🐅 这个类别。狗、猫、鸟都是 "一种" 动物。它们共享动物的一些基本特征（比如会呼吸、会移动），但也有自己独特的特征（狗会吠叫、猫会喵喵叫、鸟会飞）。在这里：
  - **基类 (Base Class) / 父类 (Parent Class)：** `Animal` 类，定义了所有动物共有的属性和行为（如 `breath()`, `move()`）。
  - **派生类 (Derived Class) / 子类 (Child Class)：** `Dog`, `Cat`, `Bird` 类，它们 **继承** 了 `Animal` 的所有共性，然后添加或修改了特定于自己的属性和行为（如 `Dog` 添加了 `bark()`, `Bird` 添加了 `fly()`）。

## 🛠 在 C++ 中的目的与优势

1. **代码重用：** 避免重复编写公共代码。将通用的属性和方法放在基类中，派生类自动获得这些功能。
2. **建立层次结构：** 清晰地表示不同类型对象之间的关系（如 `Animal` -> `Mammal` -> `Dog`）。
3. **实现多态：** 这是继承最重要的目的之一（通常与虚函数配合）。它允许你使用基类的指针或引用来操作派生类的对象，并根据对象的实际类型调用正确的函数。这使得程序更灵活、更易扩展。

## 📝 C++ 继承的语法

cpp

```c++
class DerivedClass : access-specifier BaseClass {
    // DerivedClass 特有的成员 (数据成员和成员函数)
    // 它自动拥有 BaseClass 的所有可访问成员
};
```

- `DerivedClass`: 新创建的类，从现有类继承。
- `access-specifier`: 指定继承方式，控制从基类继承过来的成员在派生类中的 **最低访问权限**。主要有三种：
  - `public`: **最常用**。基类的 `public` 成员在派生类中保持 `public`，基类的 `protected` 成员在派生类中保持 `protected`。
  - `protected`: 基类的 `public` 和 `protected` 成员在派生类中都变成 `protected`。
  - `private`: 基类的 `public` 和 `protected` 成员在派生类中都变成 `private`。
  - 💡 **关键点：** 无论哪种继承方式，基类的 `private` 成员在派生类中都是 **不可直接访问** 的（但可以通过基类提供的 `public` 或 `protected` 成员函数间接访问）。
- `BaseClass`: 被继承的现有类。

### 示例 (public 继承)

```c++
#include 
using namespace std;

// 基类 (父类)
class Animal {
public:
    void eat() {
        cout << "I can eat!" << endl;
    }

    void sleep() {
        cout << "I can sleep!" << endl;
    }

protected:
    string name; // 派生类可以访问
private:
    int internalId; // 派生类不能直接访问
};

// 派生类 (子类) - public 继承
class Dog : public Animal {
public:
    void bark() {
        cout << "I can bark! Woof woof!" << endl;
        // 可以访问基类的 protected 成员
        name = "Buddy";
        cout << "My name is " << name << endl;
        // 不能直接访问基类的 private 成员
        // internalId = 123; // 错误！编译不通过
    }
};

int main() {
    Dog myDog;

    // 调用继承自 Animal 的方法 (public 继承，所以 eat/sleep 在 Dog 对象上仍是 public)
    myDog.eat();    // 输出: I can eat!
    myDog.sleep();  // 输出: I can sleep!

    // 调用 Dog 自己的方法
    myDog.bark();   // 输出: I can bark! Woof woof! \n My name is Buddy

    // Animal 的 private/protected 成员不能在 main 中直接访问
    // myDog.name = "Max"; // 错误！name 在 Dog 中是 protected (因为 public 继承自 Animal)
    // myDog.internalId = 1; // 错误！private 成员不可访问

    return 0;
}
```

## 🔑 关键概念与细节

### 派生类的三种继承方式

- `public`继承:**(保持不变)** **最常用**。基类的 `public` 成员在派生类中保持 `public`，基类的 `protected` 成员在派生类中保持 `protected`。
- `protected`继承: 基类的 `public` 和 `protected` 成员在派生类中都变成 `protected`。
- `private`继承: 基类的 `public` 和 `protected` 成员在派生类中都变成 `private`。
- 💡 **关键点：** 无论哪种继承方式，基类的 `private` 成员在派生类中都是 **不可直接访问** 的（但可以通过基类提供的 `public` 或 `protected` 成员函数间接访问）。

1. ### 成员访问权限 (重温):

   - **基类 `public` 成员：**
     - `public` 继承：在派生类中是 `public`。
     - `protected` 继承：在派生类中是 `protected`。
     - `private` 继承：在派生类中是 `private`。
   - **基类 `protected` 成员：**
     - `public` 继承：在派生类中是 `protected`。
     - `protected` 继承：在派生类中是 `protected`。
     - `private` 继承：在派生类中是 `private`。
   - **基类 `private` 成员：** 在派生类中 **永远不可直接访问**。派生类只能通过基类提供的 `public` 或 `protected` 成员函数来间接操作这些私有成员。

2. ### 构造函数与析构函数：

   - **构造函数：** 创建派生类对象时：

     1. 先调用 **基类** 的构造函数（初始化继承来的部分）。
     2. 然后调用 **派生类** 自己的构造函数（初始化新增的部分）。

     - 如果没有显式指定调用哪个基类构造函数，编译器会自动调用基类的**默认构造函数**。

     - 如果需要调用基类的带参数构造函数，必须在派生类构造函数的**成员初始化列表**中显式调用：

       cpp

       ```c++
       class Dog : public Animal {
       public:
           Dog(string dogName, int age) : Animal(dogName) { // 调用 Animal(string) 构造函数
               this->age = age;
           }
           // ... 其他成员 ...
       private:
           int age;
       };
       ```

   - **析构函数：** 销毁派生类对象时：

     1. 先调用 **派生类** 自己的析构函数。
     2. 然后自动调用 **基类** 的析构函数。

     - 顺序与构造相反。基类的析构函数通常应该是 `virtual` 的（尤其是在打算多态地删除对象时），但这属于多态的范畴。

3. ### 函数覆盖 (Overriding) 与隐藏 (Hiding):

   - 如果派生类定义了一个与基类中 **名称和参数列表完全相同** 的非静态成员函数：

     - 如果基类函数是 **虚函数 (`virtual`)**: 发生 **覆盖 (Overriding)**。这是实现多态的关键。
     - 如果基类函数 **不是虚函数**: 发生 **隐藏 (Hiding)**。基类的同名函数在派生类作用域中被隐藏。通过派生类对象调用该函数名时，只会调用派生类的版本（除非使用作用域解析运算符 `::`）。

   - 示例 (隐藏):

     cpp

     ```c++
     class Base {
     public:
         void show() { cout << "Base show" << endl; }
     };
     class Derived : public Base {
     public:
         void show() { cout << "Derived show" << endl; } // 隐藏了 Base::show()
     };
     int main() {
         Derived d;
         d.show(); // 输出 "Derived show"
         d.Base::show(); // 输出 "Base show" (使用作用域显式调用)
         return 0;
     }
     ```

4. ### 术语：

   - **基类 / 父类 / 超类：** 被继承的类 (`Animal`)。
   - **派生类 / 子类：** 继承而来的新类 (`Dog`)。
   - **单继承：** 一个派生类只从一个基类继承。上面例子都是单继承。
   - **多重继承：** 一个派生类从多个基类继承。语法为 `class D : public B1, public B2, ... { ... };`。功能强大但也更复杂（如菱形继承问题），需要谨慎使用。

### 基类构造先于派生类构造**；**派生类析构先于基类析构。

## 📌 总结

C++ 继承是一种强大的机制，允许你：

1. **重用** 基类的代码。
2. 在现有类的基础上 **扩展** 功能。
3. 建立反映现实世界关系的类 **层次结构**。
4. 为实现 **多态**（通过虚函数）奠定基础，这是编写灵活、可扩展代码的核心。

**核心要点记忆：**

- **目的:** 代码重用、层次建模、实现多态。
- **关系:** "是一个" (`is-a`)。
- **语法:** `class Derived : access Base { ... };`
- **访问控制:** `public`/`protected`/`private` 继承决定了基类成员在派生类中的可见性。基类 `private` 成员永远不可在派生类中直接访问。
- **构造/析构顺序:** **基类构造先于派生类构造**；**派生类析构先于基类析构**。
- **覆盖 vs 隐藏:** 虚函数导致覆盖（**多态**），非虚函数导致**隐藏**。


1. ### 基类的成员函数

   - 一种是基类希望派生类直接继承而不需要修改得到行为(例如所有人都要吃饭，睡觉)
     - 应该为普通的成员函数
   - 一种是基类希望派生类提供自己新的定义，以覆盖从基类继承过来的定义(例如，学生要学习，老师要上课)
     - 这种函数，应该定义为虚函数(virtual function)

   ```c++
   class Human
   {
   public:
       Human(const string& name, int age) :m_name(name), m_age(age), m_IDnum(1234){}
   	void eat(const string& food)4

       {

   ```

2. ### 基类成员的访问控制

`public` ：基类的公有成员在任何地方都可以直接访问,包括派生类

`private` ：基类的私有成员只有友元函数和本类成员函数可以访问,其他地方都不可以访问派 生类也不行 

`protected` ：如果有些成员不希望对外公开,当时又希望它的派生类能够直接访问,则可以使用 protected来修饰这些成员(友元,本类的成员函数,派生类的成员函数)

# 派生类


# 1.2继承方式

- 继承方式可以省略,==**class的默认的基础方式是private继承**==，`struct`的默认的继承方式是`public`继承，虽然`class`和`struct`都有默认的继承方式,但是为了程序的可读性应该显示的说明继承方式
- 在构造派生类之前，要先构造基类

## public：公有继承

- **基类的公有成员**，通过公有继承，称为派生类自己的公有成员。
- **基类的私有成员**，不会被子类直接继承(可以继承，但是不能使用)。这意味着子类不能直接访问或操作父类的私有成员。私有成员是父类内部实现的细节，对子类来说是隐藏的。

然而，尽管子类不能直接访问父类的私有成员，但这些私有成员在子类对象中仍然是存在的。这是因为子类对象在内存中包含了父类对象的部分，包括父类的私有成员。这些私有成员在父类的构造函数中被初始化，并在子类对象中占据了一定的内存空间。

- **基类的保护成员**，通过公有继承，成为派生类自己的保护成员。

```c++
#include<iostream>
using namespace std;
class Human
{
public:
    Human(const string& name, int age) :m_name(name), m_age(age), m_IDnum(1234){}

    {
    	cout << "我在吃" << food << endl;
    }
    void sleep(int time)
    {
    	cout << "我睡了" << time << "个小时" << endl;
    }
protected://保护型的成员可以在子类中被访问
    string m_name;
    int m_age;

//2但是可以提供保护的接口函数来间接访问
	int getIDnum()
    {
        return m_IDnum;
    }
private://1私有成员子类中无法访问
	int m_IDnum;//身份证号
};

//学生类(人类的一个子类)
class Student :public Human//显示指明子类的继承方式
{
public:
    //Human(...)保证在构造派生类之前，要先构造基类（在子类的初始化表中显示的调用基类的构造函数）
    Student(const string& name, int age, int no) :Human(name, age), m_no(no) {}
    void learn(const string& course) {
    	cout << "我在学" << course << endl;
    }
    void who(void) {
        cout << "我叫" << m_name << ",今年" << m_age <<
        "岁,学号是" << m_no << endl;
        cout << "身份证号" << getIDnum() << endl;
    }
private:
	int m_no;
};
int main()
{
    Student stu("蔡徐坤", 18, 001);
    stu.who();//子类自己的公有成员函数，在类外可以访问
    stu.eat("香翅捞饭");//公有继承，基类公有成员在子类中还是公有，因此在类外可以访问
    stu.sleep(8);
    stu.learn("C++");//子类自己的公有成员函数，在类外可以访问
    //star.getIDnum();//公有继承，基类保护成员在子类中还是保护，因此在类外不可访问，但是可以在类内访问，如在stu的who函数中可以打印出getIDnum()的返回值    
    return 0;
}
```

- 基类的保护成员,通过私有继承,成为了派生类自己的私有成员

- 基类的私有成员,通过保护继承,成为了派生类的一部分,但是派生类不可以直接访问它

## 注意事项

- 关于私有成员: 基类的private 成员在子类中任然存在,但是却无法直接访问,无论哪一种继承方式派生类都 不能直接使用基类的私有成员（要想访问基类的私有成员(假设为C)，需要在基类中的非私有成员函数(假设为A)【如public或protect】中调用该私有成员，并在子类中的非私有成员函数(假设为B)中调用基类的非私有成员函数A，才能在类外通过子类B函数访问基类的私有成员C) 即B通过A访问C。
- 派生类占用的空间的大小,等于基类占用的存储空间大小,加上派生类自己的成员大小             (派生类中拥有 一个基类子对象,考虑字节对齐)

```c++
#include <iostream>
using namespace std;
class A
{
void fun(){}//8+8+8
    int a;
    float b;
    char c;
    double d;
};
class B : public A//8+8
{
    char c;
    double d;
};
class C//空类大小为1
{
};
class D : public C
{
};
int main()
{
    cout << "sizeof(A) = " << sizeof(A) << endl;//24
    cout << "sizeof(B) = " << sizeof(B) << endl;//24+16=40
    cout << "sizeof(C) = " << sizeof(C) << endl;//1
    cout << "sizeof(D) = " << sizeof(D) << endl;//1
```

# 1.3公有继承的特性

##      1.子类继承基类成员

子类对象会继承基类属性的行为，通过子类对象可以访问基类中的成员，如同是基类对象在访问他们一样。

- 一个子类对象，从整体上分为两部分：
  - 从基类继承过来的成员(可以理解为一个整体，是一个基类子对象)
  - 子类自己的新增成员
- 在子类中，可以直接访问基类中的公有或保护成员，如同是子类自己的成员一样。
- 基类中的私有成员,子类也可以继承过来，但是会受到访问控制属性的限制，无法直接访问， 如果子类需要访问基类中的私有成员，可以通过基类提供的公有或保护接口函数来间接访问。
- 基类的构造函数和析构函数，子类是无法继承的，但是可以在子类的构造函数中使用**初始化表**来显示声明基类部分的初始化。(初始化表是在进入派生类构造函数之前执行的，需要在派生类构造之前，构造完成基类对象)

1. 分配内存
2. 创建对象
3. 执行构造函数(初始化成员)

##       2.向上造型

将子类类型的指针或引用转换成基类类型的指针或引用

- 由于在派生类中,含有基类的所有成员,所以,我们能够把公有继承的**子类对象当成基类对象来使用,** 具体表现在:
  - **基类的引用可以绑定到子类对象**
  - 基类的指针可以绑定到子类对象
  - 可以使用子类对象初始化基类对象
  - 可以使用子类对象给基类对象赋值

```c++
//father
//son
son d;
father &r_b = d;//基类的引用可以绑定到子类对象
father *p_r = &d;//基类的指针可以绑定到子类对象
father b(d);//可以使用子类对象初始化基类对象
father b1;//可以使用子类对象给基类对象赋值
b1 = d;
```

将子类对象当成基类对象，因为子类包含基类所有对象，还包含自身特有的对象

这种操作性缩小的类型转换,在编译器看来是安全的,可以直接隐式完成转换

- **当使用子类对象得到一个基类对象/引用/指针的时候，该基类对象/引用/指针是无法访问到子类的新增成员的，只能访问到子类从基类继承过来的成员。在编译器看来,基类对象/引用/指针的类型任然是基类!!!,【只是基类使用子类来绑定，本身依然是基类】**

子类指针指向基类申请的内存//error

基类指针指向子类申请的内存//ok

##      3.子类隐藏基类的成员

- 子类和基类中有同名的成员函数,因为作用域不同,**不会有重载关系**,而是一种隐藏关系,如果需要访问基类中隐藏的成员函数,可以通过在子类中加"基类类名::"显示指明 
- 如果隐藏的成员函数满足同名不同参重载条件,也可以通过using声明的方式,将基类的成员函数引入到子类的作用域,让它们形成重载关系,通过重载匹配来解决//不推荐

###              法1基类类名::显示指明

```c++
#include<iostream>
using namespace std;
class Base
{
public:
    void foo(void) //基类foo函数
    {
        cout << "Base::foo" << endl;
    }
};
class Derived :public Base
{
public:
    void foo(void) //子类foo函数
    {
        cout << "Derived::foo" << endl;
    }
};
int main() {
    Derived d;
    d.foo();//
    d.Base::foo();//通过"基类类名::"显示指明
    return 0;
}
```

###               法2子类中using 基类类名::;


## 2.子类的析构函数

- 子类对象的析构过程 
  - 执行子类析构函数代码 
  - 析构子类对象(按声明的逆序) 
  - 析构基类对象(按继承表的逆序) 
  - 释放内存

**问题**：为什么先析构子类对象然后析构基类对象？ 

- **资源释放的顺序：**子类可能依赖于基类提供的某些资源或状态。如果首先析构基类，那么这些资源或状 态可能在子类析构函数需要时已经不存在，从而导致未定义的行为或错误。因此，先析构子类可以确保 子类在析构时能够正确地使用基类提供的资源。 

- **依赖关系：**在面向对象的设计中，子类常常依赖于基类来提供某些功能或状态。这种依赖关系意味着子 类在使用完基类提供的功能后需要负责清理，然后基类再进行最后的清理工作。 

- **防止悬挂指针和引用：**如果基类在子类之前被析构，那么任何在子类中指向基类成员的指针或引用都可能变成悬挂的（即指向已经被释放的内存），这会导致未定义的行为。 

**子类指针指向基类申请的内存//error**

**基类指针指向子类申请的内存//ok**

**总结：**==子类的构造/析构函数都会调用基类的构造/析构函数，但是基类的构造/析构不会调用子类的构造/析构==

- 基类的析构函数不会自动调用子类的析构函数,如果对一个**指向子类对象的基类指针**使用delete操作符,**实际被执行的仅是基类的析构函数,子类的析构函数执行不到,有内存泄露的风险**

# 1.5子类的拷贝构造和拷贝赋值函数

在C++中子类不会子类（派生类）不会自动调用基类（父类）的拷贝构造函数或拷贝赋值运算符。

 这是因为拷贝构造和拷贝赋值操作是针对对象的整体而言的，而不是仅仅针对对象的某一部分（即基类 部分）。当创建一个新的子类对象作为现有子类对象的副本时，你需要显式地处理基类的拷贝。

 如果你不提供自定义的拷贝构造函数或拷贝赋值运算符在子类中，编译器会为你生成默认的版本。这些 默认的版本会执行成员到成员的拷贝，包括基类的部分。然而，如果基类有自定义的拷贝构造函数或拷 贝赋值运算符，并且你需要这些自定义行为在子类中发生，你就需要在子类中显式地调用它们。

# 1.6子类的移动构造和移动赋值函数

在C++中，子类（派生类）不会自动调用基类（父类）的移动构造函数或移动赋值运算符。与拷贝构造 函数和拷贝赋值运算符类似，这些操作也是针对对象的整体而言的。当你想通过移动一个现有对象来构 造或赋值另一个对象时，你需要在子类中显式地处理基类的移动。 

如果基类有自定义的移动构造函数或移动赋值运算符，并且你希望这些自定义行为在子类中发生，你需 要在子类的相应函数中显式地调用它们。以下是如何在子类的移动构造函数和移动赋值运算符中显式调 用基类的相应函数的示例：
