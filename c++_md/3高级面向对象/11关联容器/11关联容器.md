# 关联容器

关联容器是一种支持高效的关键字查找和访问的数据结构，用于存储和管理具有**键值对**的数据元素。

关联容器中的元素按照键值进行**排序**(默认是升序），这使得它们在数据检索时比序列式容器效率更高。

此外，关联容器中的**键值是唯一的**(不存在重复元素)，这保证了每个元素都能被唯一标识。

# 键(Key)

键是用于**唯一**标识关联容器中元素的一个值。

元素本身就是键，键与值相关联，用于查找和访问对应的值。

键的类型通常是可比较的，以便关联容器根据键 对元素进行排序和查找。

| 键（Key）  | 值（Value）         |                     |
| :--------- | :------------------ | ------------------- |
| **作用**   | 元素标识符          | 关联数据            |
| **可变性** | 常量（不可修改）    | 可修改              |
| **要求**   | 需支持排序/哈希     | 无特殊要求          |
| **示例**   | `map<K,V>` 中的 `K` | `map<K,V>` 中的 `V` |
|            | `set<T>` 中的 `T`   | -                   |

# 键值对(Key-Value Pair)

键值对是一个包含键和与键相关联的值的数据结构。

每个元素都是一个键值对，通过键，可以快速查找和访问与之关联的值。

关联容器通常使用平衡查找树（如红黑树、二叉树)或哈希表来实现高效的查找操作，能在对数时间或常数时间内完成查找。

# 优点:

**快速查找**：关联容器内部通常使用平衡树(如红黑树)来实现，这意味着它们可以在对数时间【O(log n)】内完成查找、插入和删除操作。这在处理大量数据时非常高效，尤其是当你需要频繁地根据键来查找值时。

**唯一性保证：**这在需要确保数据唯一性的场景中非常有用

**有序存储：**可以轻松遍历容器容器中的元素，按照键的顺序访问。

# map

在C++中，`std::map`是一个关联容器，它存储的元素都是键值对(key-value pairs)，并且根据键的值来自动排序。

头文件`#include<map>`

## 主要特点

- **键值唯一性**：`std::map` 中的每个元素都由一个**唯一的键(Key)**和一个**与之关联的值(value)**组成你。键在`std::map`中是唯一的，即不会有两个或更多的元素拥有相同的键。

如果尝试插入一个已经存在的键，

则新的值会覆盖旧的值(使用`operator[]`插入)

或者插入操作会失败(使用`insert`方法且键已经存在)

- **自动排序**：`std::map` 内部的元素默认按照键的升序排列。如果需要自定义排序规则，可以通过向`std::map` 传递一个比较函数或对象来实现。

- **高效查找**：由于`std::map` 的内部实现保证了元素的排序性，因此可以实现高效的查找操作。

- **动态大小:**`std::map` 是一个动态容器，可以在运行时根据需要增长或缩小。当容纳新元素时，如果容器的大小不足以容纳新元素，它会自动重新分配内存以容纳更多的元素。

  同样，当删除元素时，如果容器的大小超过了所需的容量，它可以会释放一些内存以节省空间。

- **提供迭代器：**`std::map` 提供了双向迭代器，使得可以遍历容器中的元素。迭代器允许按顺序访问容器中的元素，并且提供了对元素的读取和修改能力(通过迭代器访问的元素值可以被修改，但键是固定的)。

  **map不支持下标访问，但是它支持下标(运算符)，并不意味着是下标访问。**

  map[n]，n表示键；是指当前map中键(为n的元素)所对应的值

- **键值类型多样性**:`std::map` 的键和值可以是任何支持比较操作的类型。这意味着你可以使用自定义类型作为键，只需要为该类型定义比较操作符或提供比较函数对象即可。

### `std::pair`（类型 + 构造函数）

**键值对类型**

- **本质**：是一个模板类
- **用法**：需要显式指定两个元素的类型
- **特点**：
  - 构造时需明确声明类型
  - 支持直接初始化（推荐）或赋值初始化
  - C++17 起支持类模板参数推导（`CTAD`），可省略类型

```c++
//std::pair<T1,T2>是一个模版类，用于将两个可以不用类型的数据组合成一个单一对象。这种配对通常用于表示键值对(key-value pair)
std::pair<Key,T> myPair(Key,value);//接受两个参数，返回一个包含这两个参数的pair对象。如std::pair<int,string> myPair(1,"abc");

// 显式指定类型（传统方式）
std::pair<int, std::string> p1(42, "Hello");
// C++17 起支持类型推导
std::pair p2(3.14, "Pi"); // 自动推导为 pair<double, const char*>
```

### `std::make_pair`（函数模板）

- **本质**：是一个函数模板
- **用法**：自动推导 pair 的元素类型
- **特点**：
  - 无需显式指定类型
  - 常与 `auto` 配合使用
  - 对字符串字面值会推导为 `const char*`（而非 `std::string`）

```c++
std::make_pair()//接受两个参数，返回一个包含这两个参数得的pair对象。用来简化std::pair对象的创建过程，特别是不想显示指定std::pair的类型时，编译器会根据传递给std::make_pair的参数类型来推断std::pair的类型。
    
// 自动推导类型
auto p3 = std::make_pair(10, "ABC"); // pair<int, const char*>

// 需要 string 时需显式转换
auto p4 = std::make_pair(10, std::string("ABC")); // pair<int, string>
```

### 核心区别总结

| 特性               | `std::pair`                | `std::make_pair`           |
| :----------------- | :------------------------- | :------------------------- |
| **本质**           | 类模板                     | 函数模板                   |
| **类型指定**       | 必须显式声明（C++17 前）   | 自动推导                   |
| **字符串处理**     | 可直接声明为 `std::string` | 字面值推导为 `const char*` |
| **C++ 版本兼容**   | 所有版本                   | 所有版本                   |
| **C++17 类型推导** | 支持（可省略类型）         | 仍可用但必要性降低         |
| **典型使用场景**   | 类型明确的声明             | 模板代码 / `auto` 简化     |
| **构造效率**       | 可能更高效（避免临时对象） | 可能引入转换               |

#### 力扣第一题：

**两数之和**

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值** *`target`* 的那 **两个** 整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

你可以按任意顺序返回答案。

```c++
#include <vector>
#include <map>
using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        map<int,int> a;//建立hash表存放数组元素
        vector<int> b(2,-1);//存放结果
        for(int i=0;i<nums.size();i++)
        {
            if(a.count(target-nums[i]))//查找target-nums[i]是否在hash表中
            {
                b[0]=a[target-nums[i]];//找到则存放结果
                b[1]=i;
                break;
            }
            a[nums[i]]=i;
        }
        return b;
    }
};


std::map<int,int> a;
a[key] = value; 就是把 key-value 键值对存入 map。
在 twoSum 问题中，key 是数组元素值，value 是它的下标。
假设 nums = {2, 7, 11, 15}，
第一次循环 nums[0]=2, target - nums[0] = 9 - 2 = 7 不在哈希表中，将 a[2] = 0 存入哈希表
此时，哈希表状态为:{2:0}
第二次循环 nums[1]=7,  target - nums[1] = 9 - 7 = 2 在哈希表中，将 b[0] = a[2] = 0，b[1] = 1

在哈希表a中 
key 表示 数组元素的值
value 表示 该值在数组中的下标
a[2] == 0;
意思是：
    数字 2 在数组中的下标是 0。
    哈希表中key为2所对应的值为：0
```



```c++
#include<iostream>
#include<map>
using namespace std;
int main()
{
    std::map<int,string> myMap;

    std::pair<int,string> myPair1 = std::make_pair<int,string>(2,"def");

    auto it1 = myMap.find(7);//auto可以写为 std::map<int,string>::iterator

    {
        cout<<it1->first<<endl;

    }
    else
    {
        cout<<"没找到"<<endl;
    }
    cout<<"接下来是删除操作"<<endl;

    //键存在时返回 1（删除成功）
    //键不存在时返回 0（未删除）

    myMap.erase(6);
    // 按迭代器删除
    auto it2 = myMap.find(5);
    if (it2 != myMap.end()) 
    {
        myMap.erase(it2);
    }

    for (auto it = myMap.begin(); it != myMap.end(); ++it) 
    {
        cout << it->first << ": " << it->second << endl;
    }
    return 0;
}
```

# `multimap`

`std::multimap` 是 C++ 标准模板库（`STL`）中的一个关联容器，用于存储键值对（key-value pairs），**允许重复的键**，并按照键的顺序进行排序。

## 1. 基本特性

- **头文件**：`#include <map>`
- **命名空间**：`std`
- **底层实现**：通常基于红黑树（Red-Black Tree）
- **排序**：按键自动排序（默认升序）
- **键重复性**：允许重复键（与 `std::map` 的主要区别）

| 特性     | std::map                 | std::`multimap`     |
| :------- | :----------------------- | :------------------ |
| 键唯一性 | 键必须唯一               | 允许重复键          |
| 访问方式 | 支持 `operator[]`        | 不支持 `operator[]` |
| 插入结果 | 插入失败（如果键已存在） | 总是成功            |
| 使用场景 | 一对一映射               | 一对多映射          |

### 时间复杂度

- **查找**：O(log n) - 基于红黑树的查找
- **插入**：O(log n)
- **删除**：O(log n)
- **遍历**：O(n)

# set(集合)--元素有序唯一

`set` 是 C++ STL（标准模板库）中的关联容器，基于**红黑树**（一种自平衡二叉搜索树）实现。它存储**唯一元素**（无重复值），并自动按**升序**排序（可通过自定义比较器改变顺序）。它**只存储唯一的键**，没有与键相关联的值。(key 即value)

## 主要特点

- **唯一性**：元素值唯一（插入重复值会被忽略）
- **自动排序**：元素默认按 `<` 升序排列。如果需要降序排列或其他自定义排序方式，可以通过提供自定义的比较函数或对象来实现。
- **基于红黑树实现**：`set`内部使用红黑树数据结构来存储元素。红黑树是一种自平衡的二叉搜索树，它能在对数时间内完成插入、删除和查找操作。
- **快速查找**：`set`非常适合用于需要快速检查元素是否存在的场景。
- **不允许修改元素**值:一旦一个元素被插入到`set`中，不能直接修改该元素的值(因为这会破坏集合的唯一性和排序性质)。如果你需要修改一个元素的值，必须先删除旧元素，然后插入新元素

```c++
// 错误示例：
auto it = mySet.find(10);
*it = 100;  // 编译错误！元素是const

// 正确做法：
mySet.erase(10);
mySet.insert(100);
```

- **迭代器稳定性**
- 高效的内存使用

# map和set区别

## 元素类型

`set`值存储键，而`map`存储键值对

## 重复元素

`set`不允许有重复元素，每个元素都是唯一的

`map`的键是唯一的，不同的键可以有相同的值。

## 下标访问

`map`中使用[]可以访问键所对应的值,myMap[key]-》返回key对应值

`set`中不支持下标访问

## 用途

`set`通常用于快速查找唯一元素的场景，如检查某个值是否存在于集合中；

而`map`则用于存储键值对的数据结构

## 性能

`set`和`map`都是基于红黑树实现的，而

`map`存储的是键值对，在空间占用上会稍大一些

# unordered_set/unordered_map

### set/map

- **基于红黑树**（平衡二叉搜索树）
- 元素自动排序
- 需要定义比较函数（默认 `std::less`）

### unordered_set/unordered_map

- **基于哈希表**
- 元素无序存储
- 需要定义哈希函数（默认 `std::hash`）和相等比较函数

## 性能对比

| 操作 | set/map  | unordered_set/unordered_map |
| :--- | :------- | :-------------------------- |
| 插入 | O(log n) | 平均 O(1)，最坏 O(n)        |
| 查找 | O(log n) | 平均 O(1)，最坏 O(n)        |
| 删除 | O(log n) | 平均 O(1)，最坏 O(n)        |
| 遍历 | 有序遍历 | 无序遍历                    |

## 关键特性对比

| 特性         | set/map              | unordered_set/unordered_map |
| :----------- | :------------------- | :-------------------------- |
| 排序         | 自动排序             | 无序                        |
| 迭代器稳定性 | 稳定（除删除元素外） | 插入可能使所有迭代器失效    |
| 内存使用     | 相对较少             | 相对较多（哈希表负载因子）  |
| 自定义类型   | 只需 `<` 运算符      | 需要哈希函数和 `==` 运算符  |

**使用 set/map 的情况：**

- 需要元素有序
- 需要范围查询（如查找 10-20 之间的所有元素）
- 内存受限环境

**使用 unordered_set/unordered_map 的情况：**

- 主要进行单个元素的查找、插入、删除
- 不关心元素顺序
- **追求最佳平均性能**
