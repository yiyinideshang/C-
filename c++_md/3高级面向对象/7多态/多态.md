# 多态

# 1.1多态的定义

**多态(`Polymorphim`)**是面向对象编程中的一个核心概念，它描述的是**不同类型的对象在相同情况下(同一件事情)表现出不同的行为。**简单来说，多态意味着不同的对象对相同的消息或函数调用会作出不同的响应。

多态的实现主要基于**继承和方法的重写(override)**。

子类通过**继承**父类并使用或**重写**父类中的方法，可以表现出与父类不同的行为。

**当使用父类类型的引用或指针来调用一个被子类重写方法时，会根据实际对象的类型来执行相应的方法，从而实现多态。**

# 1.2多态的实现

多态主要是通过虚函数来实现的。

如果将**基类中**某个成员函数声明为**虚函数**，那么其**子类中**与该函数具有**相同原型（函数名称，参数列表和返回类型，常属性)**的成员函数也就是虚函数，并且**对基类中的版本形成覆盖**。

这时,通过**指向子类对象的基类指针**,或者通过**引用子类对象的基类引用**,去**调用函数**,实际被执行的将是**子类中的覆盖函数版本**,而不是在基类中的原始版本,这种语法现象被称为**多态**

# 1.2.1虚函数的定义

在**基类**中，虚函数是通过在函数**声明**前面加上`virtual`关键字来定义的。

- **注意**：**虚函数是在基类的函数声明前面加`virtual`关键字**，与子类是否加`virtual`关键字无关。子类对应的相同原型的函数加不加 virtual 关键字都无所谓。
- c++11也提供了一个保留字(**`override:`重写，写在子类里面的**),用于说明某一个函数是覆盖了基类的虚函数(重写了基类的虚函数)，可写可不写

==目的:==

  1. 在成员函数比较多的情况下,可以提示用户某一个函数是重写了基类的虚函数 
        - 提高代码的可读性 
 2. 编译器会强制检查这个函数是不是重写了基类的虚函数

       - 如果不是则报错(防止程序员粗心) 

       - override修饰的函数的函数原型（**函数名称，参数列表和返回类型**)必须和父类的虚函数相同!

```c++
#include<iostream>
// 假设的坐标点结构
struct Point
{
    int x;
    int y;
};

// 定义每个形状的最大顶点数
#define SIZE 10
class Shape
{
protected:
    Point arr[SIZE]; // 结构体数组来存放顶点
    int numArr; // 当前形状的顶点数
public:
    Shape() : numArr(0) {}
    // 添加顶点，注意这里需要确保不会超过数组的最大容量
    void addVertex(const Point& p)
    {
    if (numArr < SIZE)
        {
            arr[numArr++] = p;
        }
        else
        {
            std::cout << "Error: Too many vertices for this shape." <<
            std::endl;
        }
    }
    virtual void draw() const//const也要加上，否则不构成多态
    {
        std::cout << "draw--by Shape" << std::endl;
    }
};

//三角形子类
class Triangle : public Shape
{
public:
    Triangle()
    {
        // 三角形的三个顶点
        addVertex({ 0, 0 });
        addVertex({ 0, 5 });
        addVertex({ 5, 0 });
    }
    // 绘制三角形的方法
    void draw() const override
    {
        std::cout << "Drawing a triangle with vertices:" << std::endl;  
        for (int i = 0; i < numArr; ++i)
        {
            std::cout << "(" << arr[i].x << ", " << arr[i].y << ")" <<
            std::endl;
        }
    }
};

// 四边形子类
class Quadrilateral : public Shape
{
public:
    Quadrilateral()
    {
    // 四边形的四个顶点
        addVertex({ 0, 0 });
        addVertex({ 0, 5 });
        addVertex({ 5, 5 });
    addVertex({ 5, 0 });
    }
    // 绘制四边形的方法
    void draw() const /*override*/ //override可写可不写
    {
        std::cout << "Drawing a quadrilateral with vertices:" << std::endl;
        for (int i = 0; i < numArr; ++i)
        {
            std::cout << "(" << arr[i].x << ", " << arr[i].y << ")" <<
            std::endl;
        }
    }
};
int main()
{
    Shape shape;
    shape.draw();
    Triangle triangle;
    triangle.draw(); // 显式调用Triangle的draw方法
    Quadrilateral quadrilateral;
    quadrilateral.draw(); // 显式调用Quadrilateral的draw方法
    return 0;
}
```

## 成员函数的隐藏,重写,重载

- **重载**：是指同一可访问区内被声明的几个具有不同参数列（参数的类型，个数，顺序不同的同名函数，根据参数列表确定调用哪个函数。重载不关心函数返回类型。 
  - **相同作用域内，同名函数，不同参数列表。编译器根据实际传入的参数列表来确定调用哪个函数。**
- **隐藏**：是指子类的函数屏蔽了与其同名的基类函数，注意**只要同名函数，不管参数列表是否相同，基类函数都会被隐藏。** 
- **重写(覆盖)**：是指子类中存在重新定义的函数。**其函数名，参数列表，返回值类型，所有都必须同基类中被重写的函数一致。只有函数体不同**（花括号内），**子类调用时会调用子类的重写函数**，不会调用被重写函数。重写的**基类**中被重写的函数必须有`virtual`修饰。

## 虚函数可以设置默认参数(缺省值)吗？ 

虚函数也可以设置**默认参数**

 如果虚函数设置了默认参数,则基类和派生类中设置的默认值最好保持一致。如果不一致,则以基类中设置的默认值为准 。

当虚函数的声明和定义分开的时候,只需要在**声明**的地方加上virtual的说明即可

# 1.3多态的表现, this指针指向的是调用该函数的对象

- 需要使用一个**指向子类对象的基类指针**,或者通过**引用子类对象的基类引用**,去调用这个虚函数。 

- **实际被执行的将是子类中的覆盖版本,**而不是在基类中的原始版本,这种语法现象被称为**多态**

  - 调用虚函数的指针也可以是**this指针**,当通过一个**子类对象调用基类中的成员函数**时,该函数里面的 this指针就是一个**指向子类对象的基类指针,**再通过它去调用虚函数,实际上**调用的是子类的虚函数**，同样可以表现**多态**的语法特性

    ​    ==**this指针指向的是调用该函数的对象**==

    - **因为**成员函数func()：基类里面的函数

      所以，**this-》是一个基类指针**

    - **因为**该函数的对象 ：是一个子类对象来调用的

      所以，**this-》指向子类对象的基类指针**

```c++
#include<iostream>
using namespace std;
class Base{
public:
    virtual int cal(int x,int y)
    {
        return x + y;
    }
    void func()
    {
        //this是一个基类类型的指针，当子类类型对象来调时，此时this就是一个指向子类对象的基类指针(this 类型是 Base*，但指向 Derived 对象)，因此可以表现出多态(动态绑定)
        cout << this->cal(200,300) << endl;
        cout << cal(200,300) << endl;
    }
};

class Derived:public Base
{
public:
    int cal(int x,int y) override
    {
        return x * y;
    }
};
int main()
{
    Derived d;
    d.func();//当子类对象来调用基类函数

    Base &b = d;//绑定到子类对象的基类引用
    cout << b.cal(100,200) << endl;
    return 0;
}
//60000
//60000
//20000
//若 Base::cal 未被声明为 virtual，则 func() 中的调用会静态绑定到 //Base::cal，输出 500（200+300）。但此处因使用了虚函数，多态生效。
```

# 虚函数回避机制

在某些情况下,我们希望对虚函数的调用**不要进行动态绑定**,而是执行某一个特定的函数版本 此时使用**作用域运算符**就可以达到这个目的!

````c++
shapes[i]->Shape::draw();//显示调用Shape中的draw()函数,调用基类版本
shapes[i]->draw();//调用子类版本
````

# 动态类型转换

==**强制类型转换**==

静态类型转换 `static` 基本类型和指针类型

常类型转换 `const`	去除变量，指针，引用的常属性

重解释 `reinterpret_cast` 任意类型之间

==**动态类型转换**==

## 	语法:

```c++
目标类型变量 = dynamic_cast<目标类型>(源类型变量);
```

## 	主要使用场景

1. **向下转型（Downcasting）**

   - 将**基类指针/引用转换为子类指针/引用**
   - **典型场景**：当基类指针指向派生类对象时，访问派生类特有成员

   

   ```c++
   Shape* shape = new Triangle();//基类指针指向子类
   // 安全转换为Triangle类型
   if (Triangle* tri = dynamic_cast<Triangle*>(shape)) {
       tri->draw();  // 调用Triangle特有方法，前面已经写了虚函数
   }
   ```

2. **交叉转型（Cross casting）**

   - 在多重继承中，将指向一个基类的指针转换为另一个无关基类的指针

   

   ```c++
   class A { virtual ~A() {} };
   class B { virtual ~B() {} };
   class C : public A, public B {};
   
   A* a = new C();
   // 将A*转换为B*（通过共享的派生类C）
   if (B* b = dynamic_cast<B*>(a)) {
       b->someMethod();
   }
   ```

3. **类型安全检测**

   - 运行时验证对象的实际类型

   ```c++
   void processShape(Shape* s) {
       if (dynamic_cast<Triangle*>(s)) {//如果可以将基类指针s动态类型转换为子类指针
           std::cout << "Processing triangle\n";
       }
       else if (dynamic_cast<Quadrilateral*>(s)) {
           std::cout << "Processing quadrilateral\n";
       }
   }
   int main() {
       Triangle tri;                // 子类对象
       Quadrilateral quad;          // 子类对象
       Shape base;                  // 基类对象
   
       processShape(&tri);    // 输出: Processing triangle
       processShape(&quad);   // 输出: Processing quadrilateral
       processShape(&base);   // 无输出 (危险！)
       processShape(nullptr); // 无输出 (安全)
   }
   ```

   - 不同调用场景的结果

   | 传入指针 `s` 的实际指向 | 执行结果                        |
   | :---------------------- | :------------------------------ |
   | `Triangle` 对象         | 输出 "Processing triangle"      |
   | `Quadrilateral` 对象    | 输出 "Processing quadrilateral" |
   | **基类 `Shape` 对象**   | **无输出**（两个条件均不满足）  |
   | 其他派生类对象          | 无输出                          |
   | `nullptr`               | 无输出（安全）                  |

   - 多态

```c++
class Shape {
public:
    virtual void process() const { // 基类默认实现
        std::cout << "Processing generic shape" << std::endl;
    }
};

class Triangle : public Shape {
public:
    void process() const override {
        std::cout << "Processing triangle" << std::endl;
    }
};

// 统一调用接口
void processShape(Shape* s) {
    if (s) s->process(); // 自动调用实际类型的实现
}
```

## 	转换结果处理

| 转换目标类型 | 成功时返回   | 失败时返回           |
| :----------- | :----------- | :------------------- |
| **指针**     | 目标类型指针 | `nullptr`            |
| **引用**     | 目标类型引用 | 抛出 `std::bad_cast` |

​	**示例：**

```c++
// 指针转换（需检查nullptr）
Shape* s = new Quadrilateral();
if (Triangle* t = dynamic_cast<Triangle*>(s)) { // 转换失败
    t->draw(); // 不会执行
}

// 引用转换（需异常处理）
try {
    Shape& ref = *s;
    Triangle& tRef = dynamic_cast<Triangle&>(ref); // 抛出异常
} 
catch (const std::bad_cast& e) {
    std::cerr << "转换失败: " << e.what() << '\n';
}
```

# 指针数组与数组指针以及指针指向数组

| 指针指向数组 | 一个指针指向数组首地址     |
| :----------- | -------------------------- |
| **指针数组** | **一个数组存放的全是指针** |

一个指针指向整个数组

## 1.int *ptr = new int[10]（指针指向数组）

- 含义：一个通用指针指向数组的首元素
- 大小:sizeof(ptr) = 8（一个指针占8个字节)

```c++
int arr[5] = {1, 2, 3, 4, 5};
int* ptr = arr;  // 指向数组第一个元素
```

## 2. `int* arr1[10]`（指针数组）

- **含义**：声明一个**包含10个元素的数组**，每个元素是 `int*` 类型（指向整数的指针）。

- **内存布局**：连续存储10个指针，每个指针可独立指向整数或整数数组。

- **大小**：`sizeof(arr1) = 10 * sizeof(int*)`（例如80字节，指针占8字节）。

- **访问元素**：

  ```c++
  int a = 1, b = 2;
  int* arr1[2] = {&a, &b};  // 存储两个独立指针
  cout << *arr1[0];         // 输出: 1
  ```

## 3. `int(*arr2)[10]`（数组指针）

- **含义**：声明一个**指针**，该指针**指向**一个**包含10个整数的数组**。

- **内存布局**：`arr2` 本身是一个指针（8字节，若64位系统），指向一个大小为 `10 * sizeof(int)` 的连续内存块。

- **大小**：`sizeof(arr2) = sizeof(指针)`（例如8字节），与指向的数组大小无关。

- **访问元素**：

  ```c++
  int matrix[3][10];        // 二维数组（3行10列）
  int(*arr2)[10] = matrix;  // 指向第一行（10个元素的数组）
  arr2[1][2] = 99;          // 修改第1行第2列元素（等价于matrix[1][2]= 99）;
  ```

## 指针数组与数组指针 关键区别总结：

| **特性**        | `int* arr1[10]`（指针数组）                     | `int(*arr2)[10]`（数组指针）               |
| :-------------- | :---------------------------------------------- | :----------------------------------------- |
| **类型**        | 包含10个`int*`的数组(10个存放int类型指针的数组) | 指向`int[10]`数组的指针                    |
| **`sizeof` 值** | `10 * sizeof(int*)` (如80字节)                  | `sizeof(指针)` (如8字节,因为指针占8个字节) |
| **元素访问**    | `arr1[i]` 返回第`i`个指针                       | `(*arr2)[i]` 访问指向数组的第`i`个元素     |
| **赋值**        | `arr1[0] = new int;`                            | `arr2 = &existingArray;`                   |
| **常见用途**    | 存储多个独立指针（如字符串数组）                | 处理多维数组（如函数参数传递）             |

## 指针指向数组与数组指针 关键区别总结：

| **特性**         | 指针指向数组 (`int* ptr`) | 数组指针 (`int(*arrayPtr)[5]`)    |
| :--------------- | :------------------------ | :-------------------------------- |
| **声明方式**     | `int* ptr = arr;`         | `int (*arrayPtr)[5] = &arr;`      |
| **指向目标**     | 数组首元素                | 整个数组                          |
| **类型信息**     | 只有元素类型 (`int*`)     | 包含元素类型和数组长度 (`int[5]`) |
| **sizeof(指针)** | 指针大小 (通常8字节)      | 指针大小 (通常8字节)              |
| **兼容性**       | 可指向任意长度数组        | 只能指向特定长度的数组            |
| **访问元素**     | `ptr[i]` 或 `*(ptr + i)`  | `(*arrayPtr)[i]`                  |

**所有数组指针都是"指向数组的指针"，但并非所有指向数组的指针都是数组指针**

### 存布局对比：

假设 `int arr[5] = {1,2,3,4,5};` 地址从0x1000开始

```c++
普通指针 (int* ptr = arr)
┌───────┐     ┌───┬───┬───┬───┬───┐
│ 0x1000├────►│ 1 │ 2 │ 3 │ 4 │ 5 │
└───────┘     └───┴───┴───┴───┴───┘
ptr + 1 → 0x1004

数组指针 (int(*arrayPtr)[5] = &arr)
┌───────┐     ┌───────────────────┐
│ 0x1000├────►│ 整个int[5]数组    │
└───────┘     └───────────────────┘
arrayPtr + 1 → 0x1014 (0x1000 + 20)
```

# 1.4纯虚函数与抽象类

有时候在设计基类的时候，某些函数可能不知道如何去定义或者不应该去定义

如基类shape中，求面积函数

这种情况下，我们可以把这些不知道/不应该定义的函数定义为 **纯虚函数**

- #### 格式

```c++
virtual 返回值类型 函数名(参数列表) = 0;
```

纯虚函数不需要定义,只需要在函数声明时,在形参列表后面加上"=0"即可。 

"=0"不表示函数的值为0,仅仅是一种写法,用来告诉编译器,这个函数基类没有定义，需要派生类去实现它。

- #### ==如果一个类中含有**纯虚函数**,这种类叫做**抽象类(Abstract class)**。==

  - **抽象类不能用来实例化对象,但是可以创建基类引用绑定到派生类对象**

  -  如果一个类继承自一个抽象类,但是本**身依然没有实现那个纯虚函数**,则这个派生类依然是一个**抽象类**

```c++
#include<iostream>
using namespace std;
class Base //抽象类
{
public:
    void fun1()
    {
    	cout << "Base::fun1()" << endl;
    }
	virtual void fun2() = 0;//纯虚函数
};
class Derived :public Base
{
public:
    void fun2()
    {
    	cout << "Derived::fun2()" << endl;
    }
};
int main()
{
    //Base b1;//error 抽象类不能用来实例化对象
    Derived d;
    Base& b = d;//抽象类可以创建基类引用绑定到派生类对象
    b.fun1//Base::fun1()
    b.fun2();//Derived::fun2()
    return 0;	
}
```

- #### **==如果一个类中的成员函数都是纯虚函数,那么该类就是纯抽象类==**

# 1.5 虚函数实现原理（了解）虚函数表和虚指针

虚函数的实现原理主要依赖于C++中的 虚函数表(vtable)和虚指针（vptr）机制。这个机制允许在**运行时**确定应该调用哪个类的虚函数实现，从而实现动态多态性。

**虚函数表（vtable）**

每个包含虚函数的类（或者说，有虚函数表的类）都会有一个与之关联的虚函数表。

这个表是一个函数指针数组，其中每个指针都指向类中的一个虚函数的实现。虚函数表是在编译时创建的，并存储在程序 的只读数据段中。

```c++
int a = 1, b = 2;
int* arr1[2] = {&a, &b};  // 指针数组，存储两个独立指针,指针arr1[0],arr1[1]
```

**虚指针（vptr）**

每个包含虚函数的类的对象都会有一个指向其类的虚函数表的虚指针（vptr）。

这个指针在对象创建时 由编译器自动设置，并存储在对象的内存布局中。vptr通常作为对象的第一个成员变量存在（尽管具体 实现可能因编译器和平台而异）。

**动态绑定**

当通过基类的指针或引用调用虚函数时，编译器生成的代码不会直接调用函数，而是**首先通过vptr找到 虚函数表，然后在这个表中找到对应函数的地址，最后调用这个函数**(最终调用特定子类的函数)。

这个过程被称为动态绑定或晚期绑定，因为它是在运行时**根据对象的实际类型**来确定的。

**继承与重写**

当派生类重写基类的虚函数时，派生类的虚函数表会包含一个新的函数指针，指向派生类中的虚函数实现。

如果派生类没有重写某个虚函数，那么它的虚函数表中对应的位置将包含基类虚函数的地址。

# 1.6 虚析构,参考继承中子类的析构函数

- ==问题：构造函数可以是虚函数吗？== 

  不可以。

  - **最直接的原因**：虚函数要求该函数在子类和父类中 **函数名称，参数列表和返回类型**必须完全一致，但构造函数名称与该类名相同，不存在子类和父类类名相同的两个类，所以它不能是构造函数  
    - Base() {}   —》基类的构造函数
    - Derived() {} -》子类的构造函数
  - 需要的是一个子类对象的基类指针：执行构造函数时，子类对象不一定存在
  - **调用时机：**构造函数是在对象创建时自动调用的，而虚函数的机制依赖于对象的vptr（虚指针），这个 vptr是在构造函数执行过程中被初始化的。因此，在构造函数执行期间，vptr还没有被设置，所以无法 实现动态绑定。
  - **继承关系：**在对象创建时，首先调用的是基类的构造函数，然后是派生类的构造函数（如果有的话）。 如果构造函数是虚函数，那么在调用基类的构造函数时就需要确定实际调用的派生类构造函数，这在逻 辑上是不合理的。
  -  **设计原则**：构造函数的主要目的是初始化对象的状态，而不是实现对象的行为。虚函数主要用于实现对 象的行为多态性，因此将构造函数设计为虚函数并不符合面向对象的设计原则。

- ==问题：析构函数可以是虚函数吗?== 

  可以(析构函数在调用前,对象肯定存在了)。

#### 基类的析构函数不会自动调用子类的析构函数,如果对一个指向子类对象的基类指针使用delete操作符,实 际被执行的仅是基类的析构函数,子类的析构函数执行不到,有内存泄露的风险(参考继承中子类的析构函数)

```c++
#include<iostream>
using namespace std;
class Base
{
public:
    Base(void) : m_i(0)
    {
    	cout << "Base::Base(void)" << endl;
    }
    ~Base()
    {
    	cout << "Base::~Base()" << endl;
    }
	int m_i;
};
class Derived : public Base
{
public:
    Derived(void)
    {
    cout << "Derived::Derived(void)" << endl;
    // 动态分配资源
    m_dynamicArray = new int[10];
	}
	~Derived()
    {
        cout << "Derived::~Derived()" << endl;
        //释放动态分配的资源
        delete[] m_dynamicArray;
    }
    int* m_dynamicArray; // 动态分配的整数数组
    int m_i1;
};
int main()
{
    Base* pb = new Derived; //定义了指向子类对象的基类指针，分配Derived对象
    delete pb; // 通过基类指针释放对象，但由于Derived的析构函数没有释放资源，发生内存泄露
    return 0;
}

//结果
//Base::Base(void)
//Derived::Derived(void)
//Base::~Base()只执行了基类析构函数，而没有执行子类的析构函数，存在内存泄漏问题
```

#### 如何解决这个问题呢？ ---虚析构

可以**将基类的析构函数声明为虚函数,**那么子类的析构函数就也是一个虚函数,并且对基类的虚函数构成有效的覆盖,可以表现多态的语法特性

 这时**delete一个指向子类对象的基类指针**,**实际被调用的将是子类的析构函数**,

**子类的析构函数在执行结束以后，又会自动的调用基类的析构函数**,避免了内存泄漏。

````c++
virtual ~Base()
{
	cout << "Base::~Base()" << endl;
}
````

# 哪些可以声明为虚函数

### 可以被定义为虚函数的情况：

1. **普通成员函数**

   ```c++
   class Base {
   public:
       virtual void show() { // 虚成员函数
           cout << "Base show" << endl;
       }
   };
   ```

2. **析构函数**（强烈建议为多态基类声明虚析构函数）

   ```c++
   class Base {
   public:
       virtual ~Base() { // 虚析构函数
           cout << "Base destroyed" << endl;
       }
   };
   ```

1. **纯虚函数**（使类成为抽象基类）

   ```c++
   class AbstractBase {
   public:
       virtual void mustImplement() = 0; // 纯虚函数
   };
   ```

### 不能定义为虚函数的情况：

1. **构造函数**

   ```c++
   class Base {
   public:
       virtual Base() {} // ❌ 错误：构造函数不能是虚函数
   };
   ```

2. **静态成员函数**

   ```c++
   class Base {
   public:
       static virtual void func() {} // ❌ 错误：静态函数不能是虚函数
   };
   ```

3. **友元函数**（友元函数不是成员函数）

   ```c++
   class Base {
       friend virtual void helper(); // ❌ 错误：友元函数不能是虚函数
   };
   ```

4. **非成员函数**（全局函数）

   ```c++
   virtual void globalFunc() {} // ❌ 错误：非成员函数不能是虚函数
   ```

5. **内联函数**（技术上可声明，但虚性会覆盖内联性）

   ```c++
   class Base {
   public:
       virtual inline void func() {} // ⚠️ 虚性优先，实际不会内联
   };
   ```

6. **模板成员函数**

   ```c++
   class Base {
   public:
       template<typename T>
       virtual void templateFunc() {} // ❌ 错误：虚函数不能是模板
   };
   ```

### 总结表：

| 函数类型         | 能否为虚函数 | 说明                                              |
| :--------------- | :----------- | :------------------------------------------------ |
| **普通成员函数** | ✅ 是         | 多态的核心机制                                    |
| **析构函数**     | ✅ 是         | 基类必须声明为虚函数才能正确释放派生类资源        |
| **纯虚函数**     | ✅ 是         | 用于定义接口的抽象基类                            |
| **构造函数**     | ❌ 否         | 语言设计禁止（对象构造期间虚表未建立）            |
| **静态成员函数** | ❌ 否         | 与具体对象无关，无法实现多态                      |
| **友元函数**     | ❌ 否         | 不属于类的成员函数                                |
| **全局函数**     | ❌ 否         | 不属于任何类                                      |
| **模板成员函数** | ❌ 否         | 虚函数表需要固定大小，模板实例化会破坏此机制      |
| **内联函数**     | ⚠️ 语法允许   | 但虚函数调用会阻止内联展开（通过指针/引用调用时） |

以下关于C++语言中虚函数的描述正确的有（）[**多选**]

A	构造函数不可以是虚函数

B	析构函数不可以是纯虚函数

C	构造函数中不应该调用纯虚函数

D	`struct`中不可以定义虚函数

**A：构造函数不可以是虚函数**
✅ 正确。C++ 规定构造函数不能声明为 `virtual`，因为虚函数表指针（vptr）在构造过程中才初始化，此时无法实现多态。

**B：析构函数不可以是纯虚函数**
❌ 错误。析构函数可以声明为纯虚函数（如 `virtual ~Base() = 0;`），但必须提供定义（即使函数体为空）。纯虚析构函数使类成为抽象类，但派生类仍需调用基类析构函数。

**C：构造函数中不应该调用纯虚函数**
✅ 正确。在构造函数中调用纯虚函数可能导致未定义行为（如程序崩溃）。因为当基类构造函数执行时，派生类尚未构造完整，调用的纯虚函数可能没有派生类的实现。

**D：`struct` 中不可以定义虚函数**
❌ 错误。C++ 中 `struct` 与 `class` 的唯一区别是默认访问权限（`struct` 默认为 `public`，`class` 默认为 `private`），两者均支持虚函数、继承等面向对象特性。



关于虚函数，以下说法正确的是？

A	虚函数不能定义为private

B	虚函数不可以被子类覆盖

C	子类不能调用父类private的虚函数

D	虚函数的重载性和它声明的权限有关

- **A 错误**：虚函数可以定义为 private。C++ 允许将虚函数声明为 private，派生类可以覆盖它，但无法直接访问。
- **B 错误**：虚函数的主要目的就是允许派生类进行覆盖（重写），实现多态。
- **C 正确**：父类中声明为 private 的虚函数，子类不能直接调用，因为 private 成员在派生类中不可访问。但通过父类的公共接口间接调用或通过多态机制（基类指针/引用）调用虚函数时，实际调用的是派生类覆盖后的版本，这并不违反访问权限。
- **D 错误**：虚函数的重写（覆盖）能力与其声明的访问权限无关，private、protected 或 public 虚函数均可被派生类重写。

子类不能直接调用父类 private 虚函数，因为访问权限限制。但可以通过父类提供的非私有成员函数间接调用，或者通过基类指针/引用调用虚函数时，若子类覆盖了该函数，实际执行的是子类的版本，这属于**多态行为，而非直接调用父类的 private 函数。**
