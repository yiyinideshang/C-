# 1. 关于多态与虚析构函数

在 C++ 多态中，当你通过基类指针 `delete` 一个派生类对象时，如果基类的析构函数不是虚函数，就会发生你描述的现象：只调用了基类的析构函数，而派生类的析构函数没有被调用。这通常会导致派生类部分申请的资源（如堆内存、文件句柄等）无法正确释放，造成资源泄漏。

### 1. 内存分配与对象布局

先来看你提到的内存分配问题：
当使用 `new` 创建一个派生类对象时，例如：

```c++
class Base { ... };
class Derived : public Base { ... };

Base* p = new Derived();
```

- **内存分配**：`new Derived` 会在堆上分配一块连续的内存，其大小等于 `Derived` 类对象的总大小。这块内存包含两部分：
  - **基类子对象**（Base subobject）：存放从 `Base` 继承来的成员（包括虚函数表指针等）。
  - **派生类新增成员**：`Derived` 类自己定义的成员变量。
- **对象归属**：这块内存整体上属于一个完整的 `Derived` 对象。`p` 是一个 `Base*` 类型的指针，它指向这个 `Derived` 对象中的**基类子对象**的起始地址。在单继承且没有虚继承的情况下，基类子对象通常位于派生类对象的起始位置，因此 `p` 实际指向的内存地址与整个 `Derived` 对象的起始地址相同，但类型是 `Base*`，所以通过 `p` 只能访问到 `Base` 部分的成员（多态时通过虚函数表可以调用派生类重写的虚函数）。

### 2. 析构函数调用机制

当你执行 `delete p;` 时：

- 如果 `Base` 的析构函数**不是虚函数**，编译器会根据指针的**静态类型**（即 `Base*`）来决定调用哪个析构函数。它直接调用 `Base::~Base()`，然后释放 `p` 指向的内存块。
  然而，这块内存实际是 `Derived` 对象的完整内存，但 `Base` 的析构函数只负责清理 `Base` 部分的资源（如果有的话），对 `Derived` 部分新增的成员一无所知，因此派生类的析构函数不会被调用。如果派生类在构造函数中分配了额外资源（例如 `new` 了一些内存），这些资源将永远无法释放，导致内存泄漏。
- 如果 `Base` 的析构函数**是虚函数**，情况就不同了。`delete p` 会通过虚函数表动态绑定，实际上调用的是 `Derived` 的析构函数。`Derived` 的析构函数执行完自己的清理工作后，会自动调用 `Base` 的析构函数（就像派生类对象析构的正常顺序：先派生类析构，再基类析构）。这样所有资源都能正确释放。

### 3. 为什么会缺少派生类析构函数？

你的描述中，执行 `delete` 后看到了“基类的构造函数，子类的构造函数，基类的析构函数”，这其实是一个误解——构造函数是在对象创建时调用的，而析构函数是在销毁时调用的。你可能是在观察构造和析构的打印输出时，误以为构造函数在 `delete` 时又被调用了一次。实际上，`delete` 只会触发析构函数，不会再次触发构造函数。正确的输出顺序应该是：

- 创建对象：`Base 构造函数` → `Derived 构造函数`
- 删除对象（如果基类析构非虚）：`Base 析构函数`
- 删除对象（如果基类析构虚）：`Derived 析构函数` → `Base 析构函数`

因此，缺少的正是 `Derived` 的析构函数，这正是因为基类析构函数没有声明为 `virtual`。

### 4. 代码示例

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    Base() { cout << "Base constructor\n"; }
    ~Base() { cout << "Base destructor\n"; }  // 非虚，会导致问题
    // virtual ~Base() { cout << "Base destructor\n"; }  // 正确做法
};

class Derived : public Base {
public:
    Derived() { cout << "Derived constructor\n"; }
    ~Derived() { cout << "Derived destructor\n"; }
};

int main() {
    Base* p = new Derived();
    delete p;  // 输出：Base destructor（没有 Derived destructor）
    return 0;
}
```

如果取消注释虚析构函数，输出将变为：

```text
Base constructor
Derived constructor
Derived destructor
Base destructor
```

### 5. 总结

- **内存布局**：`new Derived` 分配的是整个 `Derived` 对象的内存，基类指针指向该对象中的基类部分，但整个内存块仍属于 `Derived` 对象。
- **析构多态**：为了让 `delete` 基类指针时能正确调用派生类的析构函数，必须将基类的析构函数声明为虚函数。这是实现多态清理的必备条件。
- **对象归属**：该对象在堆上，属于 `Derived` 类型，只是通过基类指针访问。只有通过虚析构函数才能让编译器在运行时知道要调用哪个析构函数，从而完整地销毁对象。

记住：**凡是设计为基类的类，都应该将析构函数声明为虚函数**，除非你明确禁止通过基类指针删除派生类对象。









# 2. 关于基类指针指向子类对象

那为什么要使用基类指针指向子类对象，直接使用子类指针不行吗

### 1. 统一接口，处理不同类型

通过基类指针，你可以编写一段代码，让它能够处理继承体系中的**任意派生类对象**，而无需关心对象的具体类型。例如：

```c#
class Animal {
public:
    virtual void speak() const = 0;
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void speak() const override { cout << "Woof!\n"; }
};

class Cat : public Animal {
public:
    void speak() const override { cout << "Meow!\n"; }
};

void makeSound(const Animal& animal) {  // 接受任何Animal派生类
    animal.speak();                     // 运行时多态调用
}

int main() {
    Dog d;
    Cat c;
    makeSound(d);  // Woof!
    makeSound(c);  // Meow!
}
```

如果不用基类指针，你需要为每个具体类型编写重载函数 `makeSound(const Dog&)` 和 `makeSound(const Cat&)`，不仅代码重复，而且每增加一个新动物类型，就要修改所有相关代码。

### 2. 容器中存储异质对象

在集合（如 `std::vector`）中存储不同类型的对象时，必须使用基类指针（或智能指针）。因为容器要求元素类型相同，而派生类对象可以隐式转换为基类指针，从而实现“装进同一容器”。

```c++
vector<unique_ptr<Animal>> zoo;
zoo.push_back(make_unique<Dog>());
zoo.push_back(make_unique<Cat>());

for (auto& animal : zoo)
    animal->speak();  // 各自输出正确叫声
```

若使用子类指针，则无法将 `Dog*` 和 `Cat*` 放入同一个 `vector`。

### 3. 依赖抽象，降低耦合

面向对象设计原则（如**依赖倒置原则**）提倡：高层模块不应依赖于低层模块，二者都应依赖于抽象。使用基类指针意味着代码只依赖于抽象基类，而不依赖于具体的派生类实现。这使得系统更容易扩展和维护——添加新派生类时，已有代码无需改动（开闭原则）。

例如，一个绘图程序可以定义基类 `Shape`，所有图形都派生自它，然后绘图函数只接收 `Shape*`。当新增 `Triangle` 类时，绘图函数无需修改，自动支持新图形。

### 4. 工厂模式与回调

许多设计模式（工厂模式、策略模式、观察者模式等）都需要返回或接收基类类型，以实现“面向接口编程”。例如，一个对象工厂根据输入返回不同派生类的实例，通常返回类型就是基类指针。

```c++
Animal* createAnimal(const string& type) {
    if (type == "dog") return new Dog();
    if (type == "cat") return new Cat();
    return nullptr;
}
```

### 5. 为什么不直接用子类指针？

直接使用子类指针**也可以**，但会失去上述所有好处：

- 代码将与具体类型绑定，导致难以扩展和复用。
- 无法编写处理所有派生类的通用代码。
- 增加新类型时，必须修改所有使用该具体类型的地方，容易引发错误和维护困难。

### 6. 与之前问题的关联

你之前提到基类析构函数非虚时，`delete` 基类指针会导致派生类析构不被调用。这正是**安全使用基类指针的前提**：必须将基类析构函数声明为虚函数。一旦满足这个条件，基类指针就能安全且优雅地管理派生类对象的生命周期，同时享受多态带来的灵活性。

### 总结

使用基类指针指向子类对象，本质上是在实践**面向接口编程**。它让代码更灵活、可扩展、易维护，是C++多态设计的精髓。而直接使用子类指针虽然在某些简单场景下可行，但会牺牲掉多态带来的架构优势。当你需要编写可适应变化的代码时，基类指针是更优的选择。

# 3. 什么是虚函数表

**虚函数表（vtable）** 是 C++ 编译器为实现**运行时多态**（动态绑定）而建立的一个数据结构。它本质上是一个**存储虚函数地址的数组**（或类似结构），每个包含虚函数的类（或从包含虚函数的基类派生的类）都有自己的虚函数表。

------

### 为什么需要虚函数表？

当通过基类指针或引用调用虚函数时，程序在**运行时**才能确定实际应该调用哪个版本的函数（基类版本还是派生类版本）。为了实现这种动态绑定，编译器需要一种机制来记录每个类的虚函数具体指向哪里，这就是虚函数表的作用。

------

### 虚函数表的工作原理

1. **编译阶段**：

   - 对于定义了虚函数的类，编译器会为其生成一个**虚函数表**（通常放在只读数据段，如 `.rodata`）。
   - 虚函数表是一个数组，其中按声明顺序（或某种编译器决定的顺序）存放着该类所有虚函数的**函数指针**。
   - 如果派生类**重写（override）**了某个虚函数，则派生类的虚函数表中对应位置会替换为派生类自己的函数地址；如果没有重写，则仍指向基类的函数地址。

2. **对象构造时**：

   - 每个对象内部会被编译器**隐式添加一个指针**，称为**虚指针（vptr）**，指向所属类的虚函数表。
   - 在对象构造过程中，vptr 会被正确初始化（先指向基类的虚表，再逐步更新为最终类的虚表），确保构造期间虚函数调用符合预期。
   - 通常 vptr 位于对象的起始位置（对于单继承），但具体布局由编译器决定。

3. **虚函数调用时**：

   - 通过对象访问虚函数时，编译器会生成类似这样的代码：

     ```c++
     (*ptr->vptr[index])(ptr);  // 通过vptr找到虚表，再通过索引调用函数
     ```
     
   - 其中 `index` 是该虚函数在虚表中的位置（编译时确定），这样就实现了动态绑定。

------

### 示例说明

假设有以下类定义：

```c++
class Base {
public:
    virtual void func1() { cout << "Base::func1\n"; }
    virtual void func2() { cout << "Base::func2\n"; }
};

class Derived : public Base {
public:
    void func1() override { cout << "Derived::func1\n"; }
    virtual void func3() { cout << "Derived::func3\n"; }
};
```

编译器会为 `Base` 和 `Derived` 分别生成虚函数表：

- **Base 的虚表**：

  ```tex
  [0] -> Base::func1
  [1] -> Base::func2
  ```
  
- **Derived 的虚表**：

  ```tex
  [0] -> Derived::func1   // 继承父类的funcl，并覆盖了 func1
  [1] -> Base::func2       // 继承父类的funcl，未覆盖，仍指向 Base 版本
  [2] -> Derived::func3    // 新增虚函数
  ```
  

对象布局示意图（假设 vptr 在对象起始处）：

```tex
Base 对象：
+--------+
| vptr   | ----> Base 虚表
| 其他成员 |
+--------+

Derived 对象：
+--------+
| vptr   | ----> Derived 虚表
| Base 部分成员 |
| Derived 新增成员 |
+--------+
```

当执行：

```cpp
Base* p = new Derived();
p->func1();  // 调用 Derived::func1
```

- 通过 `p` 找到对象的 vptr（此时指向 Derived 虚表）。
- 从 vptr 指向的虚表中取出第 0 项的函数指针。
- 调用该函数，即 `Derived::func1`。

------

### 多继承下的虚函数表

在多继承情况下，一个对象可能包含**多个 vptr**，每个指向对应基类的虚表。派生类会为每个基类生成相应的虚表，并根据需要调整函数地址（如 `thunk` 技术用于调整 this 指针）。

------

### 虚函数表的特点

- **每个类一个虚表**，所有对象共享（而非每个对象单独一份）。
- **对象只保存 vptr**，因此虚函数会增加对象的大小（通常是一个指针大小）。
- 虚表的内容在编译时确定，存储在只读数据段，运行时不可修改。
- 虚函数调用比普通函数调用多一次间接寻址，有轻微性能开销，但通常可接受。

------

### 总结

虚函数表是 C++ 实现动态多态的基石。它通过类和对象之间的间接层，使得程序能够在运行时根据对象的实际类型决定调用哪个函数，从而支持面向对象的多态特性。理解虚函数表有助于深入掌握 C++ 对象模型、性能分析以及调试相关问题（如通过内存查看虚表内容）。

# 4. 关于虚指针vptr

需要区分两个时间点：**对象构造过程中** 和 **对象构造完成后**。

在示例中：

```c++
Base* p = new Derived();
p->func1();
```

**在函数结束后**，`new Derived()` 已经执行完毕，对象**已经完全构造完成**。因此，该对象的虚指针（vptr）指向的是 **`Derived` 类的虚函数表**。调用 `p->func1()` 会通过 `Derived` 的虚表找到 `Derived::func1` 并执行。

**在构造期间**：

在对象构造过程中，vptr 会被正确初始化（先指向基类的虚表，再逐步更新为最终类的虚表

下面详细拆解这个过程：

------

### 构造过程中的 vptr 变化

当执行 `new Derived()` 时，实际步骤如下：

1. **分配内存**，然后调用 `Derived` 的构造函数。
2. **先调用基类 `Base` 的构造函数**：
   - 在进入 `Base` 构造函数体之前，编译器会先将对象的 vptr 设置为指向 `Base` 的虚表（因为此时对象被认为是 `Base` 类型的一部分）。
   - ==如果在 `Base` 构造函数内部调用了虚函数（比如 `func1`），那么通过 vptr 找到的是 `Base::func1`==，而不是 `Derived::func1`。这符合预期：基类构造时派生类部分还未初始化，调用派生类重写的函数可能访问未初始化的成员，因此标准规定此时应调用基类版本。
3. **基类构造完成后，开始构造派生类部分**：
   - ==在进入 `Derived` 构造函数体之前，编译器会将 vptr 更新为指向 `Derived` 的虚表。==
   - 之后，如果在 `Derived` 构造函数中调用虚函数，就会通过新的 vptr 调用派生类重写的版本（如果有），或者基类版本。
4. **整个构造过程结束**，对象完全建成，vptr 最终指向 `Derived` 的虚表。

------

通过示例看观看vptr的变化（但注意无法直接访问 vptr，只能通过函数调用观察）：

```c++
#include <iostream>
using namespace std;

class Base {
public:
    Base() { func1(); }  // 构造中调用虚函数
    virtual void func1() { cout << "Base::func1\n"; }
};

class Derived : public Base {
public:
    Derived() { func1(); }  // 构造中调用虚函数
    virtual void func1() override { cout << "Derived::func1\n"; }
};

int main() {
    Derived d;  // 输出：Base::func1   Derived::func1
    // 构造完成后
    d.func1();  // 输出：Derived::func1
    return 0;
}
```

输出为：

```text
Base::func1      // Base构造时，vptr指向Base虚表，调用Base::func1
Derived::func1   // Derived构造时，vptr已更新，调用Derived::func1
Derived::func1   // 构造完成后，再次调用，仍是Derived::func1
```

这清晰展示了 vptr 在构造过程中先指向基类虚表，后指向派生类虚表，最终稳定在派生类虚表。
