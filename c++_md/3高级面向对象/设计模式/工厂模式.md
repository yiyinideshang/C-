- **具体的产品类 == 产品类子类**
- **具体的工厂类 == 工厂类子类**
- 产品类 只有一个
- 工厂类 只有一个

# 简单工厂模式

![简单工厂1](D:\Typora\typora_work\c++_md\3高级面向对象\设计模式\简单工厂1.png)

- 工厂类`SmileFactory`有且只有一个，在这个工厂类里，有且只有一个工厂函数(`createSmaile`)，通过这个唯一的公函数，就能够生产出不同的对象，
- 这些不同的对象是需要一个共同的父类，产品类(`AbstractSmile`)，在这个父类中提供一些接口，基于这个父类派生出交几个子类(`SheepSmile`、`LionSmile`、`BatSmile`)，每个子类中重写父类的接口
- 这样就可以在工厂类中去创建这些产品类的子类对象
- 给工厂类的工厂函数提供一个参数，给到不同的枚举值，在工厂函数内部进行判断，就知道要生产哪一个产品类的子类对象

1.关于虚析构函数、2.基类指针指向子类对象、3.什么是虚函数表、4.关于虚指针见： [`一些deepseek设计模式.md`](一些deepseek设计模式.md) 

关于枚举，见： [`第4章复合类型.md`](D:\Typora\typora_work\C++ Primer Plus\第4章复合类型.md) 

## 示例

```c++
#include <iostream>
using namespace std;
//产品类的父类，恶魔果实
class AbstractSmile
{
public:
	virtual void transform()=0;//形态变化
	virtual void ability()=0;//能力变化
	virtual ~AbstractSmile() {}//虚析构函数，将析构函数设置为虚函数，有效解决多态的内存泄漏问题，
	//当new创建一个基类指针指向子类对象时，如果delete该对象后，程序依次执行：基类的构造函数，子类的构造函数，基类的析构函数。
	//会缺少子类的析构函数，而发生内存泄漏问题。
	// 父类构造-》子类构造
	//子类析构-》父类析构
};
class SheepSmile :public AbstractSmile
{
	void transform() override
	{
		std::cout << "山羊人形态" << std::endl;
	}
 	void ability() override
	{
		std::cout << "手臂变为绵羊角" << std::endl;
	}
};
class LionSmile :public AbstractSmile
{
	void transform() override
	{
		std::cout << "狮子人形态" << std::endl;
	}
	void ability() override
	{
		std::cout << "可以喷火" << std::endl;
	}
};
class BatSmile :public AbstractSmile
{
	void transform() override
	{
		std::cout << " 蝙蝠人形态" << std::endl;
	}
	void ability() override
	{
		std::cout << "使用万剑归宗" << std::endl;
	}
};
//定义工厂类， 在简单工厂模式下，有且只有一个
enum class Type:char{Sheep,Lion,Bat};//强类型枚举
class SmileFactory
{
public:
	AbstractSmile* createSmile(Type type)
	{
		AbstractSmile* ptr = nullptr;
		switch (type)
		{
		case Type::Sheep:
			ptr = new SheepSmile;
			break;
		case Type::Lion:
			ptr = new LionSmile;
			break;
		case Type::Bat:
			ptr = new BatSmile;
			break;
		}
		return ptr;
	}
};
int main()
{
	//创建工厂类对象
	SmileFactory* factory = new SmileFactory;
	//调用工厂类的创造函数，生产出产品类的子类对象obj
	AbstractSmile* obj = factory->createSmile(Type::Lion);
	obj->transform();
	obj->ability();

	delete obj;//释放产品类的子类对象
	delete factory;//释放工厂类
	return 0;
}
```

## 缺点

- 当种类增加时，不仅要增加新的产品类的子类（支持开放原则，添加新的子类），还需要在工厂类中添加这些子类的判断以及枚举的个数（违背封闭原则，修改了现有的类）
- 这样就违背了 开放封闭原则，已经开发好的类我们就不再对他进行修改了。

# 工厂模式 Factory Method Pattern

- 还是只有一个工厂类，但是将它管理不同的工厂类子类。

- 将工厂类的子类类与产品类的子类一一对应，一个工厂类只负责当前实际产品的生产，削弱了具体的工厂类的功能，将工厂类进行 解耦合。

![工厂模式2](D:\Typora\typora_work\c++_md\3高级面向对象\设计模式\工厂模式2.png)

## 优点

- 解决了简单工厂模式的缺点：
- 对于新添加的产品类的子类，直接添加新类；对应的 添加新的工厂类的子类，直接添加新类。
- 想要多加多少种对象都无所谓，对于已经编辑好的代码(已有的类)不需要做任何修改，而是只要添加新的代码(新的类)
- 使用工厂模式，完全遵守设计模式三原则。

## 类型分析

- **抽象产品**：`AbstractSmile`
- **具体产品**：`SheepSmile`、`LionSmile`、`BatSmile`
- **抽象工厂**：`AbstractFactory`（定义了 `createSmile()` 工厂方法）
- **具体工厂**：`SheepFactory`、`LionFactory`、`BatFactory`（分别实现 `createSmile()` 返回对应的具体产品对象）
