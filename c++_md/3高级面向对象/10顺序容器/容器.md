# 三种容器适配器

C++ 标准库中的三种容器适配器分别位于两个头文件：

- **`<queue>`** 提供 `std::queue` 和 `std::priority_queue` 先进先出 (FIFO)
- **`<stack>`** 提供 `std::stack`    后进先出（LIFO）

## 1. 什么是容器适配器？

**容器适配器** 不是一个独立的全功能容器，而是对现有容器（如 `deque`、`vector`、`list`）的 **接口进行封装和限制**，从而提供一种 **特定的数据结构行为**（如栈、队列、优先队列）。

简单说：

- **容器**：提供丰富的操作（插入、删除、随机访问、迭代器等）。
- **适配器**：只暴露符合某种数据结构规则的一小组操作，隐藏底层容器的其他功能。

## 2. 类比理解

- **底层容器** = 一辆多功能汽车（能前进、后退、转弯、加速、刹车、开天窗……）。
- **容器适配器** = 把这辆车改造成 **专用车辆**：
  - 改装成 **救护车**：只允许使用“鸣笛、闪灯、紧急行驶”这几个功能，其余禁用。
  - 改装成 **冰淇淋车**：只允许使用“播放音乐、弹出冰淇淋”功能。

## 3. C++ 标准库中的三个容器适配器

| 适配器                | 底层默认容器 | 提供的受限接口                 | 实现的数据结构          |
| :-------------------- | :----------- | :----------------------------- | :---------------------- |
| `std::stack`          | `deque`      | `push`, `pop`, `top`           | 栈（后进先出）          |
| `std::queue`          | `deque`      | `push`, `pop`, `front`, `back` | 队列（先进先出）        |
| `std::priority_queue` | `vector`     | `push`, `pop`, `top`           | 优先队列（最大/最小堆） |

## 4. 为什么叫“适配器”？

因为它是 **设计模式中的适配器模式** 的一种应用：

> 将一个类的接口转换成客户希望的另一个接口。

`deque` 的接口很宽（`push_front`, `push_back`, `pop_front`, `pop_back`, `insert`, `[]` 等），适配器 `queue` 把它“适配”成只保留 `push_back` 和 `pop_front` 的 FIFO 接口。

## 5. 关键好处

- **安全性**：防止用户不小心违反数据结构规则（例如从栈底删除元素）。
- **语义清晰**：代码写 `stack<int>` 比 `deque<int>` 更能表达“这是一个栈”。
- **更换底层容器**：只需改模板参数，例如 `stack<int, vector<int>>`，不影响使用代码。

## 总结

**容器适配器** = **限制操作 + 明确语义** 的包装器。它们本身不管理内存，而是把实际存储交给底层容器，自己只提供符合特定数据结构的成员函数。

# std::queue -队列（FIFO）

queue是一个容器适配器（默认基于`deque`），但它不提供迭代器。`queue`的设计是为了提供FIFO（先进先出）接口，只允许访问前端和尾端。它没有提供begin()和end()成员函数来返回迭代器。因此，不能直接使用迭代器遍历queue。

# std::priority_queue - 优先队列

## 关于priority_queue 的头文件

`std::priority_queue` 的底层默认容器确实是 `std::vector`，但它的头文件依然是 `<queue>`，而不是 `<vector>` 或单独的 `<priority_queue>`。原因如下：

```c++
#include <queue>   // 提供 std::queue 和 std::priority_queue
```

> ## 1. 头文件的划分依据是“抽象概念”，不是“底层实现”
>
> - **`<queue>`** 头文件包含了 **队列式** 容器适配器：`std::queue`（FIFO）和 `std::priority_queue`（按优先级出队）。
> - 尽管 `priority_queue` 底层用了 `std::vector`，但它的 **对外行为** 是“每次取出优先级最高的元素”，这仍然属于“队列”家族的变种（只是出队顺序不再是插入顺序）。
> - 标准委员会认为这两个适配器概念相近，所以把它们放在同一个头文件里。
>
> ## 2. 名字里带 “queue” 是分组的关键
>
> `priority_queue` 的名字已经明确表明它是一种队列（带有优先级的队列），放在 `<queue>` 里顺理成章。如果另起一个 `<pqueue>` 或塞进 `<vector>`，会破坏命名的直观性。
>
> ### 3. 头文件不负责提供底层容器的实现
>
> - 即使 `priority_queue` 需要 `std::vector` 作为默认底层容器，**`<queue>` 内部会间接包含 `<vector>`**（或者包含必要的声明）。用户只需要包含 `<queue>`，无需手动包含 `<vector>`。
> - 你甚至可以显式指定其他底层容器，比如 `std::priority_queue<int, std::deque<int>>`，这并不改变需要包含 `<queue>` 的事实。
>
> ## 4. 对比其他适配器
>
> - `std::stack` 默认底层也是 `std::deque`，但它被单独放在 `<stack>` 里，因为 `stack` 的概念是 LIFO，与队列不同，所以独立成头文件。
> - `std::queue` 和 `std::priority_queue` 因为都属于“队列”这一大类，就共用 `<queue>`。
>
> ## 总结
>
> **头文件是根据适配器呈现的“抽象数据结构类型”来组织的**，而不是根据它默认使用了哪个底层容器。`priority_queue` 虽然内心依赖 `vector`，但它的“户口”落在队列家族，所以住在 `<queue>` 里。

## 关于优先队列与堆

**优先队列** 是一种抽象数据类型，它至少支持两个操作：

- 插入一个元素（带优先级）
- 取出（并删除）优先级最高的元素

那么怎么高效实现它？最常用的办法就是**二叉堆（binary heap）**，因为：

- 插入和删除最大/最小值都是 **O(log n)**，并且可以就地存储在一段连续数组里，不用指针，非常快。

**`std::priority_queue` 的标准明确规定：它的底层实现必须使用堆结构。**
实际上，它内部使用一个 `std::vector`（或你指定的容器）存储元素，并利用 `<algorithm>` 里的 `push_heap`、`pop_heap` 等来维护堆的性质。

举例：

- 当你调用 `minHeap.push(x)` 时，`priority_queue` 会把元素塞进底层容器的末尾，然后调用 `push_heap` 向上调整。
- 当你调用 `minHeap.pop()` 时，它会调用 `pop_heap`，把堆顶元素交换到容器末尾，然后再做向下调整。

所以它**行为上是优先队列，物理实现上是堆**

## 类模板声明

```c++
template <
    class T,
    class Container = std::vector<T>,
    class Compare = std::less<typename Container::value_type>
> class priority_queue;
```

- `T`：存储元素的类型。
- `Container`：底层容器，必须支持随机访问迭代器以及 `front()`, `push_back()`, `pop_back()`。默认 `std::vector<T>`（另一个常用选项是 `std::deque<T>`）。
- `Compare`：比较器类型，用于确定优先级顺序。**默认 `std::less<T>`**，即**大顶堆**（最大元素在堆顶）。如果要用小顶堆，传入 **`std::greater<T>`**。

## 关于最大堆和最小堆

`priority_queue<int>` 默认是最大堆，而加上 `greater<int>` 才变成最小堆。

> 因为 `priority_queue` 的默认比较器是 `std::less`，它认为“更大的元素有更高的优先级”。
> 堆算法在比较时，用这个比较器来维护堆序，结果就是堆顶永远是优先级最高的元素（最大值）。
> 若要反过来，就传入 `std::greater`，让“更小的元素优先级更高”，堆顶就变成最小值了。

### 构造函数

### 容量

```c++
bool empty() const;   // 判断是否为空
size_t size() const;  // 返回元素个数
```

### 元素访问

```c++
const T& top() const; // 返回堆顶元素（优先级最高）。不可修改。
```

### 修改器

```c++
void push(const T& value);      // 插入元素的左值版本
void push(T&& value);           // 插入元素的右值版本

template <class... Args>
void emplace(Args&&... args);   // 在堆中原地构造元素，避免拷贝/移动

void pop();                     // 移除堆顶元素（不返回）。调用前必须非空。

void swap(priority_queue& other) noexcept(/* ... */); // 交换两个优先队列的内容
```

### 示例:指定最小堆

```c++
#include <queue>
#include <vector>

// 原型中的模板参数：
std::priority_queue<int, std::vector<int>, std::greater<int>> minHeap;
//                     T     Container            Compare
```

这里 `std::greater<int>` 是比较器类型，它会让较小的元素具有更高优先级，从而实现最小堆。

# std::stack -栈（LIFO）

`std::stack` 是 C++ 标准库中的一个**容器适配器**（Container Adapter），它包装了底层的序列容器（默认是 `std::deque`），只对外暴露有限的接口，强制遵循**后进先出（LIFO, Last-In-First-Out）**的规则。

## 核心特性

| 操作      | 含义                     | 时间复杂度 |
| :-------- | :----------------------- | :--------- |
| `push(x)` | 将元素 `x` 压入栈顶      | O(1)       |
| `pop()`   | 移除栈顶元素（无返回值） | O(1)       |
| `top()`   | 返回栈顶元素的引用       | O(1)       |
| `empty()` | 判断栈是否为空           | O(1)       |
| `size()`  | 返回元素个数             | O(1)       |

注意：`pop()` 返回 `void`，必须先用 `top()` 取值再 `pop()`。

# std::forward_list(单向链表)

`std::forward_list` 是 C++ 标准库里的**单向链表**容器（C++11 引入），定义在头文件 `<forward_list>` 中。

- 它是一串节点的集合，每个节点包含**数据** + **一个指向下一个节点的指针**。
- 只能**从头到尾**遍历，不能反向走，也不能随机跳转。
- 像一列只有“下一节”钩子的火车，你只能顺着找到下一节，找不到上一节。

## 与`std::list`区别

| 特性     | `std::list`                              | `std::forward_list`                                          |
| :------- | :--------------------------------------- | :----------------------------------------------------------- |
| 结构     | **双向链表**（每个节点有前驱和后继指针） | **单向链表**（只有后继指针）                                 |
| 遍历     | 可向前、向后                             | 只能向前                                                     |
| 内存开销 | 每个节点多存一个指针                     | 更省内存                                                     |
| `size()` | 有，O(1) 或 O(n) 取决于实现              | **没有** `size()`（为了省开销）                              |
| 插入删除 | 可在任意位置高效插入/删除                | 只能在给定位置**之后**高效插入/删除                          |
| 特有操作 | `push_back` / `pop_back`                 | **没有**`push_back`，只有 `push_front`；但有 `before_begin()` 等 |

因为单向链表的特性，`std::forward_list` 的设计非常“极简”，目的就是**在只需要单向遍历时，节省内存和运行时开销**。
