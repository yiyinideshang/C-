# 1.容器

# 1.1容器的定义

在C++中，容器的概念指的是一种对象类型，它可以持有其他对象或指向其他对象的指针。这种对象类型在数据存储上提供了一种有效的方式来管理一组元素。容器在C++中通常是**模版类**的形式。

一般来说，容器内的元素都是相同类型的。即如果该容器内存放的是int类型的数据，那么其它所有的数据都是int类型的。如果你想存储多种类型的数据，建议使用结构体。

## 容器和数组的联系与区别

- 联系：数组在广义上可以被视为一种容器，因为它用于存储一组相同类型的元素。然而，在C++标准库的语境中，当我们提到”容器“，通常不包括数组。

- 区别：

  - 创建大小调整：
    
    - **数组**：在创建数组时，必须指定其大小，且一旦创建，数组的大小就是固定的，不能动态改变。
    
    - **容器**：容器的创建不需要预先制定大小，且其大小可以动态改变，根据需要添加或删除元素
    
  - 存储方式：
  
    - **数组**：数组在内存空间上是连续存储的，这意味着数组元素在内存内中的位置是连续的，可以通过下标直接访问。
  
    - **容器**：不同的容器不同的存储方式，例如，`std::vector`和 `std::deque`是连续存储的，而`std::list` 则是链式存储的
  
  - 访问效率
  
    - **数组：**通过**数组下标**可以直接访问对应位置的元素，因此访问效率非常高。
  
    - **容器**：**连续存储的容器**（如 `std::vector` 和 `std::deque` ）也支持通过**下标**访问元素，但**链式存储的容器**（如 `std::list` ）则不支持，需要遍历链表来查找元素。
  
  - 元素操作：
  
    - **数组：**数组的元素操作通常包括赋值、读取等，但由于其连续，在数组中间位置**插入或者删除元素**比较麻烦，需要移动其他元素。
  
    - **容器：**容器提供了更为丰富的元素操作。例如， `std::list`支持在容器中间位置插入或删除元素，而无需移动其他元素。

## 为什么要学习和使用容器

其实从上述问题中我们就可以看到了。

### 	**动态内存管理：**

容器类负责动态分配和释放内存，简化了内存管理的复杂性。使用容器时，我们无需担心数组越界、内存泄漏等问题，因为容器类内部已经实现了这些内存管理的细节。

### 	自动扩展和收缩：

一些容器类（如 `std::vector` ）能够自动扩展和收缩，以适应存储元素数量的变化。这意味着我们可以将元素添加到容器中，而无需预先分配固定大小的内存空间。

### 	**代码复用和可维护性：**

使用容器类可以提高代码的复用性和可维护性。由于容器类提供了通用的数据结构和操作接口，我们可以将更多的精力放在实现业务逻辑上，而不是在数据结构和内存管理上。此外，使用容器类还可以减少代码中的重复部分，提高代码的可读性和可维护性。

# 1.2容器的分类

基于容器内部数据的组织方式、访问方式以及操作特性，容器大致可分为两大类：**顺序（序列）容器**和 **关联容器**。

## 1.2.1顺序容器

顺序容器是将单一类型的元素聚集起来成为容器，并根据元素的插入位置来存储和访问这些元素。顺序容器的元素排列**次序**与元素值无关，而是由**元素添加到容器里的次序**决定。

顺序容器常用的方法主要包括以下方面：

1. **构造函数**：用于创建容器对象，可以指定初始大小、元素值等。
2. **赋值操作**：可以使用赋值运算符（ = ）将一个容器的内容赋值给另一个容器。
3. **元素访问：**通过下标运算符（ `[]` ）或迭代器（ `iterator` ）来访问容器中的元素。对于**支持随机访问**(容器内连续)的容器（如 `vector` 和 `array` ），可以直接使用下标访问；对于只支持顺序访问的容器（如 `list` ），则需要使用**迭代器**进行遍历。
4. **容器大小**：可以使用 size() 成员函数来获取容器中元素的数量。
5. **添加元素**：对于支持在**尾部**添加元素的容器（如 `vector` 和 `deque` ），可以使用 `push_back()` 方法；对于支持在**头部**添加元素的容器（如 `list` 和 `deque` ），可以使用 `push_front()` 方法。中间添加`insert`函数。
6. **删除元素**：可以使用 `erase()` 成员函数来删除容器中的指定元素或元素范围。此外，对于支持在**尾部**删除元素的容器，还可以使用 `pop_back()` 方法；对于支持在**头部**删除元素的容器，可以使用 `pop_front()` 方法。 
   - `erase` **返回一个指向被删除元素之后位置的迭代器**（若删除的是最后一个元素，则返回 `end()`）。
7. **修改元素**：直接通过**下标**或**迭代器**访问并修改容器中的元素值。 
8. **关系运算符**：如 `==` 、 `!=` 、 `<` 、 `<=` 、 `>` 和 `>=` ，用于比较两个容器是否相等或判断一个容器是否小 于、大于另一个容器。 
9. **获取迭代器**：使用 `begin()` 和 `end()` 成员函数来获取指向容器**第一个元素**和**最后一个元素之后位置**的迭代器，用于遍历容器中的元素。

- **迭代器：**容器（集合）应该提供一种方法。顺序的访问一个集合对象中的各个元素，而又不暴露该 对象的内部表示

# `std::getline`

在C++中，`std::getline`函数用于从输入流中读取一行文本。它有两个常见的版本：

1. 在`<string>`头文件中定义的用于`std::string`的全局函数`getline`。
2. 在`<istream>`中定义的用于字符数组的成员函数`getline`。

- ## 函数原型

````c++
std::istream& getline(std::istream& is, std::string& str, char delim = '\n');
````

**第一个参数：`std::istream& is`**

- **类型**：输入流引用
- **作用**：指定从哪个输入流读取数据

**常见值**：

```c++
std::cin                     // 标准输入（键盘）
std::ifstream file("data.txt") // 文件流
std::stringstream ss         // 字符串流
```

**第二个参数：`std::string& str`**

- **类型**：字符串引用
- **作用**：存储读取到的内容
- **特点**：
  - 会**清除**str中原有的内容
  - 自动管理内存，无需预先分配大小
  - 读取的内容**不包含**分隔符

**第三个参数（可选）：`char delim`**

- **默认值**：`'\n'`（换行符）
- **作用**：指定读取的终止分隔符
- **注意**：分隔符会被读取但**不会**存入str

- # 与`std::cin`的区别

```c++
#include <iostream>
#include <string>

int main() {
    std::string part1, part2, full;
    
    std::cout << "输入两个单词（空格分隔）: ";
    std::cin >> part1 >> part2;  // 读取两个以空格分隔的单词
    
    std::cout << "part1: " << part1 << std::endl;
    std::cout << "part2: " << part2 << std::endl;
    
    std::cin.ignore();  // 清除缓冲区中的换行符
    
    std::cout << "输入一整行（可包含空格）: ";
    std::getline(std::cin, full);  // 读取整行，包括空格
    
    std::cout << "完整行: " << full << std::endl;
    
    return 0;
}
```

# 1.3 array(固定数组)

在C++标准模板库（`STL`）中， `array` 是一个顺序容器，它封装了**固定大小的数组**，并提供了与自定义数组类似的接口，但增加了类型安全和一些额外的功能。 `array` 容器允许程序员以更安全、更便捷的方式处理固定大小的数组。头文件： `#include<array>`

### `array` 的主要特点和常用方法

`array` 的主要特点：

**固定大小：**与自定义数组一样， array 在创建时指定大小，之后其大小不能再改变。

**随机访问**： array 支持随机访问其元素，可以通过下标运算符 [] 直接访问任意位置的元素。

**类型安全**：使用 array 时，编译器会检查类型，确保只有正确类型的元素被添加到容器中。 

**空间连续**：使用一组连续的内存空间来存储具有相同类型的数据。

`std::array`不支持添加或删除元素。

常用方法：	

- ​	**构造函数和赋值**

```c++

std::array<T, 5> arr2 = {1, 2, 3, 4, 5}; // 列表初始化
std::array<T, 5> arr3(arr2); // 拷贝构造函数
std::array<T, 5> arr4 = std::move(arr3); // 移动构造函数
std::array<T, 5> arr5 = {std::begin(arr2), std::end(arr2)}; // 从迭代器范围初始化
arr1 = arr2; // 赋值操作
```

- ​	**容量和大小**

- ​	**访问元素**

- **不失效性：**`std::array`的大小是固定的，因此在修改数组内容时(例如赋值操作)，迭代器不会失效。

- **随机访问迭代器**： `std::array` 的迭代器是随机访问迭代器，这意味着你可以使用迭代器进行算术运算（如 ++it , --it , it + n , it - n , it[n] 等）。

# 1.4vector(动态数组)

在C++中， `vector` （向量）是一个顺序容器，它封装了**动态大小数组**的功能，并提供了许多有用的成员函数和方法来管理这些元素。 `vector` 在内存中是**连续存储**的，这意味着它的元素在内存中占用一段**连续的空间**。头文件： `#include<vector>`

### `vector` 的主要特点和常用方法：                                          版本

### 迭代器失效

**迭代器失效**：虽然 `std::vector` 的迭代器在大多数操作下是有效的，但在某些情况下，迭代器可能会失效。特别是当 `std::vector` 进行容量调整（如 push_back 导致重新分配内存） 时，所有指向该 vector 的迭代器、引用和指针都可能失效。这是因为重新分配内存可能导致元素被移动到新的内存位置。

1. **插入元素 (`push_back`, `insert`, `emplace_back` 等)**
   - **当插入导致 vector 扩容时**：
     `vector` 需要分配新的更大的内存空间，将原有元素复制/移动到新空间，然后释放旧内存。
     **结果**：所有迭代器（包括指针和引用）**全部失效**。
   
   - **当插入未导致扩容时**：
     仅**插入位置和插入位置之后**的迭代器失效（因为元素向后移动）。
   
2. **删除元素 (`erase`, `pop_back`, `clear`)**

   - 删除操作会使**被删除元素及其之后的所有元素**的迭代器失效（元素向前移动）。

   - 删除位置之前的迭代器**仍然有效**。

3. **内存重分配操作 (`reserve`, `resize`, `shrink_to_fit`)**
   - 任何导致 vector 容量（`capacity()`）变化的操作（如 `reserve(大于当前容量)`, `shrink_to_fit`）会触发内存重分配。
     **结果**：所有迭代器失效。

### 底层原理

- **在尾部插入元素（底层原理）**

  如果当前容量（ `capacity` ）足够，则直接在尾部添加新元素。 如果当前容量不足，则分配一个新的、更大的内存块，将原有元素复制到新块中，然后在新块的尾部添加新元素，并释放旧块。

- **在指定位置插入元素**(**底层原理**)

  如果当前容量足够，则将指定位置及之后的元素向后移动一个位置，以腾出空间，然后再制定位置插入新元素。

  如果当前位容量不足，则同样需要进行内存重新分配和元素复制。

- **删除尾部元素(底层原理)**

  ​	直接移除尾部的元素，不需要移动其他元素。

- **删除指定位置的元素（底层原理）**

  将指定位置之后的元素向前移动一个位置，以覆盖被删除的元素。

- **更改大小(底层原理)**

如果新的大小 小于 当前大小，则删除尾部多余的元素。

如果新的大小 大于 当前大小，则在尾部添加默认构造的元素或给定值的元素。如果当前容量不足，则需要进行内存重新分配和可能的元素复制。

# 1.5 `deque`(双端队列)

- **全称：** **Double-Ended Queue (双端队列)**。
- **核心特性：** 允许在队列的**头部（front）**和**尾部（back）**进行**高效**的元素**插入（push）**和**删除（pop）**操作。
- **类比：** 想象一个两端都可以打开和关闭的管道。
- **定位：** 它是 C++ 标准模板库 (STL) 提供的顺序容器之一，位于 `<deque>` 头文件中。

`std::deque`（双端队列）是C++标准库中的一个容器，它允许在序列的两端（即头部和尾部）进行元素的快速插入和删除操作。

`std::deque`通常使用**多个固定大小的内存块**来存储元素，这些块通过**指针或迭代器**链接在一起，从而实现了高效的头部和尾部操作。 头文件：`#include<deque>`

### `std::deque` 的主要特点和常用方法

`std::deque` 的主要特点：

**快速的头部和尾部操作**：这是因为 std::deque 的内部实现允许它在不移动其他元素的情况下，在序列的两端添加或删除元素。

 **中间操作的效率**：虽然 std::deque 在中间位置插入或删除元素的操作不如在头部或尾部高效，但它的性能通常优于 std::vector 。这是因为 std::deque 不需要像 std::vector 那样重新分配整个内存块 并移动所有元素。 

**内存使用**： std::deque 的内存使用可能不如 std::vector 紧凑，因为它使用多个块来存储元素，并且 这些块之间需要额外的空间来存储指针或迭代器。然而，这种内存使用方式使得 std::deque 在头部和尾部操作时更加高效。 

**随机访问**：与 std::vector 一样， std::deque 也支持随机访问迭代器，这使得可以快速地访问序列中 的任意元素。

### 底层原理

- **分段存储**： std::deque 内部包含多个固定大小的块（或称为“节点”），每个块通常包含一定数量 的元素和一个指向下一个块的指针。块的大小通常是预先设定的，并且对于给定的 std::deque 实 例是固定的。 
- **头部和尾部指针**： std::deque 维护了两个迭代器，一个指向序列的开始（头部），另一个指向序 列的结束（尾部）。这两个迭代器实际上是指向各自块的开始和结束位置的迭代器。
- 插入和删除操作：
  - **在头部插入或删除**：当在头部插入或删除元素时， std::deque 会检查头部块是否有足 够的空间。如果有，则直接在头部块进行操作；如果没有，则可能需要分配一个新的块 并将其添加到头部，或者如果头部有多个块且第一个块为空，则可能会释放它。
  - **在尾部插入或删除**：与头部操作类似，但在尾部进行。 std::deque 会检查尾部块是否 有足够的空间，并根据需要分配或释放块。
  - **在中间插入**： 
    - 定位插入点：首先，通过迭代器或索引找到要插入元素的具体位置。
    -  检查空间：检查包含插入点的块是否有足够的空间来容纳新元素。如果有足够的空 间，直接在块内插入元素，并可能需要移动该位置之后的所有元素以腾出空间。
    - 分配新块：如果目标块没有足够的空间， std::deque 会分配一个新的块来存储新 元素。新块可能插入到现有块的前面或后面，取决于插入点的位置。 
    - 移动元素：为了使新元素处于正确的位置，可能需要将插入点之后的所有元素向后 移动一个或多个块。这可能涉及复制或移动元素到新的位置。
    - 更新迭代器：最后，更新任何指向已移动元素的迭代器，以确保它们仍然有效。
  - **在中间删除：**
    - 定位删除点：通过迭代器找到要删除元素的位置。
    -  删除元素：从包含删除点的块中移除元素。如果删除后块变为空，可能需要将其从 std::deque 中移除。 
    - 合并块：如果删除操作导致相邻的块都变得非常空（例如，只包含少量元素）， std::deque 可能会尝试合并这些块以优化内存使用。然而，由于块的大小通常是 固定的，直接合并可能并不总是可行的。 
    - 更新迭代器：更新任何指向已删除元素或其后元素的迭代器。
- **内存分配**：由于 std::deque 是由多个块组成的，因此它的内存分配策略通常涉及动态内存分配。 当需要更多空间时，会分配新的块；当空间不再需要时，会释放块。

## queue -

queue是一个容器适配器（默认基于`deque`），但它不提供迭代器。`queue`的设计是为了提供FIFO（先进先出）接口，只允许访问前端和尾端。它没有提供begin()和end()成员函数来返回迭代器。因此，不能直接使用迭代器遍历queue。

# std::stack

`std::stack` 是 C++ 标准库中的一个**容器适配器**（Container Adapter），它包装了底层的序列容器（默认是 `std::deque`），只对外暴露有限的接口，强制遵循**后进先出（LIFO, Last-In-First-Out）**的规则。

# 1.6 list(双向链表)

`std::list` 是 C++ 标准模板库（`STL`）中的一个容器，它表示一个**双向链表**。 与 `std::vector` 和 `std::deque` 不同，`std::list`中的元素不是存储在连续的内存空间中，而是通过指针或迭代器链接在一起。这种结构使得 `std::list` 在某些操作上具有不同的性能特点。 头文件：`#include<list>`

### **底层原理** 

`std::list` 的底层实现通常包括一个节点（`node`）结构，每个节点包含**两个指针**（或迭代器）：一个 指向下一个节点(**后继指针**)，另一个指向前一个节点(**前驱指针**)。此外，**每个节点还包含一个数据元素**。这使得 `std::list` 可以在任何位置进行插入和删除操作，因为只需要更新相邻节点的指针即可。

### `std::list`的主要特点和常用方法

**双向迭代**： std::list 支持双向迭代，意味着你可以向前或向后遍历链表。 

**插入和删除**：在链表的**任何位置**插入或删除元素通常只需要更新相邻节点的指针。 

**非连续内存**： std::list 的元素不是存储在连续的内存中，这避免了在插入或删除元素时可能需要的大量内存移动。 

**空间开销**：由于每个元素都需要额外的空间来存储指针，因此 std::list 在空间使用上可能不如 std::vector 或 std::deque 高效，特别是当存储小对象时。 

**迭代器稳定性**：与 std::vector 不同， std::list 的插入和删除操作不会使指向序列中其他元素的迭代器或引用失效，除非它们指向被删除的元素本身。

- - **双向迭代器**：

    `std::list` 的迭代器是双向迭代器，这意味着你可以使用 ++it 和 --it 来在链表中前进或后退。但是，它们**不支持随机访问**，如 it + n 或 it[n] 这样的操作。

  - **迭代器稳定性**：

    与 `std::vector` 不同， `std::list` 在修改容器（如插入或删除元素）时不会使除了被删除元素本身的迭代器以外的迭代器失效。这是因为 std::list 是通过链接节点来管理其元素的，插入和删除操作只影响被操作节点及其相邻节点的链接，而不会影响其他节点的内存位置或链接关系。

因此，在 `std::list` 中，你可以安全地在迭代器指向的元素之前或之后插入或删除元素，而不会影响其 他迭代器的有效性。但是，如果你删除了迭代器当前指向的元素，那么该迭代器将变为无效。

```c++
#include <iostream>
#include <list>
int main()
{
    // 创建一个空的 int 类型列表
    std::list<int> myList;
    // 在列表末尾插入元素
    myList.push_back(10);
    myList.push_back(20);
    myList.push_back(30);
    // 在列表开头插入元素
    myList.push_front(5);

    // 输出列表元素
    std::cout << "List elements: ";
    for (const auto& elem : myList)
    {
        std::cout << elem << " ";//5 10 20 30
    }
    std::cout << std::endl;

    // 在指定位置插入元素
    auto it = myList.begin();
    myList.insert(it, 15);

    // 输出修改后的列表元素
    std::cout << "List after insertion: ";
    for (const auto& elem : myList)
    {
        std::cout << elem << " ";//15 5 10 20 30
    }
    std::cout << std::endl;

    // 移除列表末尾的元素
    if (!myList.empty())
    {
        myList.pop_back();//15 5 10 20 
    }
    // 移除列表开头的元素
    if (!myList.empty())
    {
        myList.pop_front();//5 10 20
    }
    // 移除所有值为 10 的元素
    myList.remove(10);
    
    // 输出移除元素后的列表
    std::cout << "List after removal: ";
    for (const auto& elem : myList)
    {
        std::cout << elem << " ";// 5 20
    }
    std::cout << std::endl;

    // 获取列表大小
    std::cout << "Size of the list: " << myList.size() << std::endl;//2
    // 判断列表是否为空
    if (myList.empty())
    {
        std::cout << "The list is empty." << std::endl;
    }
    else
    {
        std::cout << "The list is not empty." << std::endl;
    }

    // 反转列表
    myList.reverse();
    std::cout << "Reversed list: ";
    for (const auto& elem : myList)
    {
        std::cout << elem << " ";//20 5
    }
    std::cout << std::endl;

    // 排序列表（默认升序）
    myList.sort();
    std::cout << "Sorted list: ";
    for (const auto& elem : myList)
    {
        std::cout << elem << " ";//5 20
    }
    std::cout << std::endl;
    return 0;
}
```

- 插入操作(底层原理)

  - **分配新节点**：首先，为新元素分配内存空间，并创建一个新节点。这个新节点将包含要插入的 元素以及两个指针，一个指向下一个节点，另一个指向前一个节点。 

  - **更新指针**：接下来，根据插入的位置更新节点的指针。

    如果是在链表头部插入，新节点的下一个指针将指向当前的第一个节点，而当前第一个节点的前一个指 针将指向新节点。同时，更新链表的头指针，使其指向新节点。

    如果是在链表尾部插入，新节点的前一个指针将指向当前的最后一个节点，而当前最后一个节点的下一 个指针将指向新节点。同时，更新链表的尾指针，使其指向新节点。

    如果是在链表中间插入，需要找到插入位置的前一个节点和后一个节点。然后，更新这些节点的指针， 使新节点正确地插入到链表中。新节点的前一个指针将指向插入位置的前一个节点，后一个指针将指向 插入位置的后一个节点。同时，更新前一个节点和后一个节点的指针，以包含新节点。

  - **维护链表完整性**：确保链表的头尾指针以及其他节点的指针都正确指向了相应的节点，以保持 链表的完整性。

- 删除操作(底层原理)

  - **找到要删除的节点**：首先，遍历链表找到要删除的节点。这通常通过从头节点开始，并沿着下 一个指针遍历链表直到找到目标节点。 
  - **更新指针**：一旦找到要删除的节点，就更新其前一个节点和后一个节点的指针，以跳过该节 点。具体来说，前一个节点的下一个指针将指向要删除节点的后一个节点，而后一个节点的前 一个指针将指向要删除节点的前一个节点。 
  - **释放内存**：删除节点后，释放该节点所占用的内存空间。 
  - **维护链表完整性**：确保链表的头尾指针以及其他节点的指针都正确地指向了删除节点前后的节 点，以保持链表的完整性。

# 1.3容器使用时机

### 1. **`std::array`（固定数组）**

- **特点**：编译时固定大小、栈上分配、连续内存。

- **使用时机**：

  - 需**固定大小**且**尺寸在编译时已知**（如矩阵、固定配置参数）。
  - 需**栈上分配**避免堆开销（小型数据）。
  - 需兼容C风格数组但要求安全性（自带边界检查）。

- **示例**：

  ```c++
  std::array<int, 3> points = {1, 2, 3}; // 固定3个点
  ```

### 2. **`std::vector`（动态数组）**

- **特点**：动态扩容、连续内存、随机访问高效（O(1)），尾部操作高效（O(1)摊销），中间/头部插入删除慢（O(n)）。

- **使用时机**：

  - **元素数量未知或需动态扩容**（如读取文件数据）。
  - 需**高频随机访问**（如通过索引访问）。
  - 主要操作在尾部（`push_back`/`pop_back`）。

- **示例**：

  ```c++
  std::vector<int> logs;
  logs.push_back(100); // 动态添加日志
  ```

### 3. **`std::deque`（双端队列）**

- **特点**：分块连续内存、头尾插入/删除高效（O(1)），支持随机访问（略慢于vector）。

- **使用时机**：

  - 需**高频在头尾插入/删除**（如任务队列、滑动窗口）。
  - 需随机访问且可接受略低于vector的性能。
  - 避免vector扩容时的复制开销（扩容时部分复制）。

- **示例**：

  ```c++
  std::deque<int> tasks;
  tasks.push_front(urgent_task); // 头部插入紧急任务
  ```

### 4. **`std::list`（双向链表）**

- **特点**：非连续内存、任意位置插入/删除高效（O(1)），无随机访问（需遍历，O(n)）。

- **使用时机**：

  - 需**高频在任意位置插入/删除**（如实时更新有序列表）。
  - 需高效合并/拆分链表（`splice()`）。
  - 避免迭代器失效问题（插入删除不使其他迭代器失效）。

- **示例**：

  ```c++
  std::list<int> sorted_list;
  sorted_list.insert(std::find(sorted_list.begin(), sorted_list.end(), 5), 6); // 在5后插入6
  ```

------

### **决策流程图**

1. **是否需要固定大小？**
   - **是** → `array`
   - **否** → 进入下一步
2. **是否需要高频随机访问？**
   - **是** → 选择 `vector`或 `deque`：
     - 主要操作在**尾部**？ → `vector`(相对于普通数组来说，进行尾部的插入和删除操作)
     - 需高效**头尾**操作？ → `deque`(相对于vector多了头部插入删除，访问元素快）
   - **否** → 进入下一步
3. **是否需高频在任意位置插入/删除？**
   - **是** → `list`(插入删除效率高，访问元素慢)
   - **否** → 默认选 `vector`（综合性能最优）

|   容器   | 随机访问 | 尾部操作 | 头部操作 | 中间插入 | 内存连续性 | 迭代器失效风险 |
| :------: | :------: | :------: | :------: | :------: | :--------: | :------------: |
| `array`  |  ✅ O(1)  |    ❌     |    ❌     |    ❌     |   ✅ 连续   |       低       |
| `vector` |  ✅ O(1)  | ✅ O(1)*  |  ❌ O(n)  |  ❌ O(n)  |   ✅ 连续   |  高（扩容时）  |
| `deque`  |  ✅ O(1)  |  ✅ O(1)  |  ✅ O(1)  |  ❌ O(n)  | ❌ 分块连续 |  中（修改时）  |
|  `list`  |  ❌ O(n)  |  ✅ O(1)  |  ✅ O(1)  |  ✅ O(1)  |  ❌ 非连续  |       低       |

```c++
        std::string bigStr = "999999999999999";
```

## 字符串反转

### 1. `std::reverse()` 就地反转


# `lower_bound`/`upper_bound`函数

==1==

https://zhuanlan.zhihu.com/p/20828283597

在 **C++ 标准模板库**（`STL`）中，`std::lower_bound` 和 `std::upper_bound` 是两个强大的**二分查找函数**，适用于 **有序范围**（如 `std::vector`、`std::set` 或 `std::map`）。这两个函数可以帮助我们快速找到元素的位置，支持高效的插入、统计和查找操作。

### `std::lower_bound`

- **作用**: 返回第一个 **大于等于** (`>=`) 指定值的元素的迭代器。
- **如果值存在**: 返回该值的第一个位置。
- **如果值不存在**: 返回比目标值 **大的第一个元素** 位置。
- **如果所有元素都小于目标值**: 返回 `end()` 迭代器。(**未找到**)
- **反向查找小于目标值的元素**: `std::lower_bound` 返回的迭代器减一，即 `std::lower_bound(vec.begin(), vec.end(), target) - 1`。

### `std::upper_bound`

- **作用**: 返回第一个 **大于** (`>`) 指定值的元素的迭代器。
- **如果值存在**: 跳过所有相同值，返回比目标值 **大的第一个元素** 位置。
- **如果值不存在**: 返回比目标值 **大的第一个元素** 位置。
- **如果所有元素都小于等于目标值**: 返回 `end()` 迭代器。(**未找到**)
- **反向查找小于等于目标值的元素**: `std::upper_bound` 返回的迭代器减一，即 `std::upper_bound(vec.begin(), vec.end(), target) - 1`。

这三个是 `std::vector` 里最常用的添加元素方法，核心区别在于 **“往哪加”** 和 **“怎么构造”**。

# `push_back`, `insert`, `emplace_back` 

### 1. 功能定位对比

| 方法           | 添加位置                       | 核心作用                                       |
| -------------- | ------------------------------ | ---------------------------------------------- |
| `push_back`    | **末尾**                       | 将现有对象拷贝/移动到容器尾部                  |
| `insert`       | **任意指定位置**（通过迭代器） | 在某个位置插入现有对象的拷贝/移动              |
| `emplace_back` | **末尾**                       | 在容器尾部**直接构造**一个新对象，无需临时对象 |

### 2. 参数与构造方式的区别（重点）

这是它们性能差异的根本原因。

#### `push_back(const T& value)` / `push_back(T&& value)`
需要先存在一个完整的对象（哪怕是临时的），然后将其**拷贝**或**移动**到 vector 内部。

```cpp
vector<string> v;
string s = "hello";

v.push_back(s);          // 拷贝 s 进 vector（s 仍存在）
v.push_back("world");    // 先构造临时 string("world")，再移动进 vector（C++11起）
v.push_back(string("!"));// 同上，构造临时对象
```

#### `emplace_back(Args&&... args)`
**不需要现成的对象**。你直接把**构造函数的参数**传给它，它会在 vector 内部预留的内存上直接调用构造函数“搭”出一个对象。省去了临时对象的创建和拷贝/移动开销。

```cpp
vector<string> v;
v.emplace_back("hello");    // 直接在 vector 尾部用 const char* 构造 string
v.emplace_back(5, 'A');     // 直接在尾部构造 "AAAAA"
```

#### `insert(iterator pos, const T& value)` 等重载
类似于 `push_back`，但插入位置任意。同样需要传入一个已构造好的对象进行拷贝或移动。

```cpp
v.insert(v.begin(), "first");   // 在头部插入，需移动后续所有元素
v.insert(v.end(), 3, "x");      // 在尾部插入 3 个 "x"
```

### 3. 性能与使用场景建议

| 场景                 | 推荐方法           | 原因                                                         |
| -------------------- | ------------------ | ------------------------------------------------------------ |
| 简单添加一个已有对象 | `push_back`        | 意图明确，可读性好                                           |
| 添加临时对象/字面量  | **`emplace_back`** | 减少一次不必要的临时对象构造，对 `string`、`pair`、自定义类效果明显 |
| 在非末尾位置插入     | `insert`           | 唯一的选择（虽然时间复杂度 O(n)）                            |
| 构造参数多、复杂     | `emplace_back`     | 避免写冗长的 `push_back(MyClass(a,b,c))`                     |

### 4. 直观的性能对比示例

假设有一个较重的类：
```cpp
class Widget {
public:
    Widget(int a, double b, const string& c) { /* 开销大 */ }
};
```

**使用 `push_back`**：
```cpp
vector<Widget> v;
v.push_back(Widget(1, 2.0, "hello"));
// 过程：构造临时 Widget -> 在 vector 内存中移动/拷贝构造新 Widget -> 析构临时对象
```

**使用 `emplace_back`**：
```cpp
v.emplace_back(1, 2.0, "hello");
// 过程：直接在 vector 内存中调用 Widget(1, 2.0, "hello") 构造一次
```

对于 `std::string` 或者包含 `vector` 的复合类型，这个差异在大量添加时非常可观。

### 5. 特别提醒

- `emplace_back` **不一定总是更快**：如果你已经有现成的对象，且该对象**移动成本极低**（如 `int`），`push_back(move(obj))` 和 `emplace_back(obj)` 差别微乎其微。但对于构造型参数，`emplace_back` 稳赢。
- `emplace_back` 返回引用（C++17起返回构造元素的引用），而 `push_back` 返回 `void`。
- 插入位置限制：`push_back` 和 `emplace_back` 只能加在末尾，若要在中间插入只能用 `insert` 或 `emplace`（注意是 `emplace`，不是 `emplace_back`）。

# emplace系列

C++11 引入的 `emplace` 系列操作，核心思想是**原地构造**（emplacement）：直接在容器内部为元素分配内存，然后在该内存上用传入的参数调用构造函数生成对象。这避免了传统 `push_back`、`insert` 等操作需要先构造一个临时对象，再拷贝或移动到容器中的过程，从而提升了性能，也使得容器能够容纳一些“不可拷贝/移动”的类型。

下面我们分别讲解 `emplace_back`、`emplace_front` 和 `emplace`，并梳理它们的适用容器和常见陷阱。

---

## 1. emplace_back —— 在尾部原地构造元素

**适用容器**：`std::vector`、`std::deque`、`std::list` 等顺序容器（只要支持 `push_back` 的，一般都支持 `emplace_back`）。  
**函数签名（vector为例）**：

```cpp
template< class... Args >
reference emplace_back( Args&&... args );   // C++17 起返回被构造元素的引用
// 在 C++11/14 中返回 void
```

### 与 push_back 的对比

假设我们有一个 `std::vector<std::pair<int, std::string>>`：

```cpp
std::vector<std::pair<int, std::string>> vec;

// push_back 需要先构造临时对象
vec.push_back(std::make_pair(42, "hello"));
// 或者通过移动
vec.push_back({42, "hello"});  // 仍会先构造临时对象再移动

// emplace_back 直接传递构造函数参数，原地构造
vec.emplace_back(42, "hello");  // 直接用 42 和 "hello" 构造 pair
```

`emplace_back` 接收的是**任意数量和类型的参数**，并将它们完美转发给元素类型的构造函数。这样既省去了临时对象的构造与析构，也绕过了拷贝/移动操作（对于不可拷贝的对象，这是唯一出路）。

> **性能提示**：如果对象已经构造好（例如一个已存在的变量），使用 `push_back(move(obj))` 通常和 `emplace_back` 效率一致；只在“需要从零构造对象”时，`emplace_back` 的优势才最大。

---

## 2. emplace_front —— 在头部原地构造元素

**适用容器**：`std::deque`、`std::list`、`std::forward_list` 等支持头插的容器（`std::vector` 没有 `push_front`，自然也没有 `emplace_front`）。  
**函数签名（deque为例）**：

```cpp
template< class... Args >
reference emplace_front( Args&&... args );   // C++17 起返回引用，之前为 void
```

行为与 `emplace_back` 完全对称，只是把元素构造在容器的头部。

```cpp
std::deque<std::string> dq;
dq.emplace_front("first");
dq.emplace_back("last");
dq.emplace_front(5, 'a');  // 构造 "aaaaa"
```

---

## 3. emplace —— 在指定位置或关联容器中原地构造

`emplace` 的行为因容器类型而异，我们分开讨论：

### 3.1 顺序容器中的 emplace

对于 `std::vector`、`std::deque`、`std::list` 等顺序容器，`emplace` 需要在**某个迭代器位置之前**插入并构造元素，相当于更高效的 `insert`。

**签名**：

```cpp
template< class... Args >
iterator emplace( const_iterator pos, Args&&... args );
```

返回指向新插入元素的迭代器。

```cpp
std::vector<std::string> sv = {"A", "B", "D"};
// 在 "B" 之前插入 "C"
sv.emplace(sv.begin() + 2, "C");  // sv: A, B, C, D

// 与 insert 的对比
sv.insert(sv.begin(), std::string("Z"));   // 先构造临时 string
sv.emplace(sv.begin(), "Z");               // 直接构造，省去临时对象
```

### 3.2 关联容器（map / set 等）中的 emplace

对 `std::map`、`std::set` 以及它们的 unordered/multi 版本，`emplace` **没有位置参数**，因为它会根据键值自动决定元素位置。它相当于更高效的 `insert`。

**签名（以 map 为例）**：

```cpp
template< class... Args >
std::pair<iterator, bool> emplace( Args&&... args );
```

返回值中，`bool` 表示是否插入成功（键是否已存在），`iterator` 指向已存在或新插入的元素。

```cpp
std::map<int, std::string> m;
m.insert(std::make_pair(1, "one"));      // 有临时 pair
m.emplace(2, "two");                     // 原地构造 pair<int,string>(2,"two")

// 对于仅移动类型，必须用 emplace
std::map<int, std::unique_ptr<int>> ptrMap;
ptrMap.emplace(1, std::make_unique<int>(10));  // 移动构造 unique_ptr
// ptrMap.insert(...) 会很麻烦，因为 key-value pair 需要移动
```

**关联容器没有 `emplace_back` / `emplace_front`**，因为它们不维护线性顺序。

---

## 4. 原地构造的深层优势

### 4.1 避免“不可拷贝/移动”的限制

经典例子：将 `std::mutex` 或 `std::atomic` 放入容器（虽然实际中往往不用容器装互斥量，但能说明问题）。

```cpp
struct NoCopyMove {
    NoCopyMove(int) {}
    NoCopyMove(const NoCopyMove&) = delete;
    NoCopyMove(NoCopyMove&&) = delete;
};

std::vector<NoCopyMove> vec;
// vec.push_back(NoCopyMove(42));  // 编译错误：无法拷贝/移动
vec.emplace_back(42);              // 正确，直接构造
```

### 4.2 完美转发与类型推导

`emplace` 系列通过可变参数模板和完美转发，将参数原封不动地传递给构造函数，自动调用最匹配的重载。这可能会触发**隐式转换**或**显式构造函数**，有时会带来意外（例如 `emplace_back(nullptr)` 对一个 `std::string` 会构造出空字符串？实际会调用 `string(const char*)` 接受空指针，导致未定义行为或抛出异常？标准是：`std::string s(nullptr)` 是未定义行为，所以需要留意）。

---

## 5. 注意事项与常见陷阱

### 5.1 花括号初始化列表

不能直接给 `emplace_back` 传一个花括号初始列表，因为它无法推导模板参数 `Args`。

```cpp
struct Point { int x; int y; };
std::vector<Point> points;
// points.emplace_back({1,2});      // 编译错误：无法推导 braced-init-list
points.emplace_back(1, 2);          // 正确，两个 int 参数
points.push_back({1, 2});           // push_back 可以，因为 {} 是 Point 的初始化列表
```

C++20 起允许聚合类型通过 `emplace_back` 使用 `()` 初始化（需要合适构造函数，或者借助 C++20 的聚合括号初始化），但最佳实践仍是明确传参。

### 5.2 异常安全

`std::vector::emplace_back` 提供**强异常保证**：如果构造元素时抛出异常，容器状态不会改变（就像什么都没发生）。但如果是在扩容时（分配了新内存，且旧内存上的元素需要移动/拷贝），某些容器可能只能做到**基本保证**（比如 `std::deque` 在某些操作下）。不过标准库实现通常尽力优化。

### 5.3 性能并非总是更好

若你已经有一个现成的对象，且它支持移动，那么 `push_back(obj)` 或 `push_back(std::move(obj))` 与 `emplace_back(std::move(obj))` 的效率完全相同。不必为了“先进”而刻意改写所有 `push_back` 为 `emplace_back`，应衡量其实际收益。

### 5.4 容器的适用性汇总

| 函数           | vector | deque | list | forward_list   | set/map | unordered_set/map |
| -------------- | ------ | ----- | ---- | -------------- | ------- | ----------------- |
| emplace_back   | ✔      | ✔     | ✔    | ✘              | ✘       | ✘                 |
| emplace_front  | ✘      | ✔     | ✔    | ✔              | ✘       | ✘                 |
| emplace(pos,…) | ✔      | ✔     | ✔    | (insert_after) | ✘       | ✘                 |
| emplace(args…) | ✘      | ✘     | ✘    | ✘              | ✔       | ✔                 |

`std::stack` / `std::queue` 这些容器适配器也提供了 `emplace`，但它们实际上是调用的底层容器（默认 deque）的 `emplace_back`，因此如果底层容器支持，适配器就能用。

---

## 6. 总结

- **emplace_back / emplace_front**：在尾部或头部直接使用构造函数参数生成元素，避免临时对象。
- **emplace**：顺序容器中在指定位置前构造元素；关联容器中按键值自动构造并插入。
- **核心优势**：提升性能、允许不可移动/拷贝类型的存储。
- **使用原则**：当你需要“从零构造元素插入容器”时优先使用 `emplace` 系列；如果元素已存在，直接使用移动版 `push_back` / `insert` 即可。
