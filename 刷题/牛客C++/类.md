# 初始化表和构造函数体内赋值

有哪几种情况只能用`intialization list` 而不能用`assignment`?[**多选**]

A	当类中含有const成员变量

B	基类无默认构造函数时，有参的构造函数都需要初始化。

C	当类中含有reference成员变量

D	当类中含有static成员变量

- **A，正确：当类中含有 const 成员变量**
  const 成员变量必须在声明时初始化，且不能修改。因此，必须在初始化列表中初始化，不能在构造函数体内赋值。
- **B，正确：基类无默认构造函数时，有参的构造函数都需要初始化**
  当基类没有默认构造函数（即无参构造函数）时，派生类必须在初始化列表中显式调用基类的有参构造函数，否则编译器会尝试调用基类默认构造函数而导致错误。因此，这种情况必须使用初始化列表。
- **C，正确：当类中含有 reference 成员变量**
  引用必须在创建时初始化，且不能重新绑定。因此，必须在初始化列表中初始化，不能在构造函数体内赋值。
- **D，错误：当类中含有 static 成员变量**
  static 成员变量属于类，而非对象，必须在类外单独定义和初始化。不能在构造函数初始化列表中初始化，也不应在构造函数体内赋值（因为它是所有对象共享的，初始化应在类外进行）。因此，D 不正确。

# 析构函数私有化：

在C++中，为了让某个类只能通过new来创建（即如果直接创建对象，编译器将报错），应该（）

A	将构造函数设为私有

B	将析构函数设为私有

C	将构造函数和析构函数均设为私有

D	没有办法能做到

正确答案：**B. 将析构函数设为私有**

## 原理分析

### 为什么选择析构函数私有化？

```cpp
class OnlyOnHeap {
private:
    ~OnlyOnHeap() {}  // 私有析构函数
public:
    OnlyOnHeap() {}   // 公有构造函数
    
    void destroy() {
        delete this;  // 提供销毁方法
    }
};
```

### 工作机制

1. **栈对象创建失败原因**：
   - 栈对象在离开作用域时，编译器会自动调用析构函数
   - 析构函数私有 → 编译器无法调用 → 编译错误
   - 因此 `OnlyOnHeap obj;` 会导致编译错误

2. **堆对象创建成功原因**：
   - `new` 操作符只需调用构造函数（公有）
   - 对象生命周期结束时，需要显式调用 `delete`
   - `delete` 会调用析构函数（私有）→ 编译错误
   - 需要提供公有方法（如 `destroy()`）来释放对象

### 其他选项分析

**A. 将构造函数设为私有**

```cpp
class A {
private:
    A() {}  // 私有构造函数
};
```

- 问题：`new A()` 也会失败，因为 `new` 也需要调用构造函数
- 只能通过静态工厂方法创建，但这不是题目要求的"只能通过new创建"

**C. 将构造函数和析构函数均设为私有**

- 完全无法创建对象（既不能栈上也不能堆上）

**D. 没有办法能做到**

- 错误，可以通过析构函数私有化实现

## 完整实现示例

```cpp
class OnlyOnHeap {
public:
    // 公有构造函数，允许new
    OnlyOnHeap() { std::cout << "构造" << std::endl; }
    
    // 公有销毁方法
    void destroy() {
        delete this;
    }
    
    // 其他成员函数
    void doSomething() {
        std::cout << "做点事" << std::endl;
    }
    
private:
    // 私有析构函数，禁止栈对象
    ~OnlyOnHeap() { std::cout << "析构" << std::endl; }
};

int main() {
    // OnlyOnHeap obj1;      // 错误：析构函数不可访问
    // OnlyOnHeap* p = new OnlyOnHeap();  // 正确
    // delete p;            // 错误：析构函数私有
    // p->destroy();        // 正确：通过公有方法销毁
    
    OnlyOnHeap* p = new OnlyOnHeap();
    p->doSomething();
    p->destroy();  // 必须通过此方法销毁
    
    return 0;
}
```

## 使用场景

这种技术常用于：

1. **控制对象生命周期**：确保对象在特定时间点被销毁
2. **单例模式**：确保只有一个实例
3. **内存池管理**：统一管理对象分配和释放
4. **COM对象**：使用引用计数控制生命周期

## 注意事项

1. **必须提供销毁方法**：否则堆对象无法释放，导致内存泄漏

2. **继承问题**：派生类需要访问基类析构函数

   - 可以将析构函数设为 `protected` 而非 `private`

3. **智能指针不适用**：`std::shared_ptr` 需要调用析构函数

4. **更好的替代方案**（C++11以后）：

   ```cpp
   class OnlyOnHeap {
   public:
       static std::unique_ptr<OnlyOnHeap> create() {
           return std::unique_ptr<OnlyOnHeap>(new OnlyOnHeap());
       }
   private:
       OnlyOnHeap() {}
       ~OnlyOnHeap() {}
   };
   ```

**总结**：将析构函数设为私有是阻止栈对象创建、强制使用堆分配的经典方法。

# `delete`描述符

下面关于delete描述错误的是（）

A	它必须用于`new`返回的指针

B	使用它删除对象时要调用析构函数

C	对一个指针可以使用多次该运算符

D	指针名前只有一对方括号符号，不管所删除数组的维数

- **A 正确**：`delete` 必须用于释放由 `new` 动态分配的内存（包括空指针，此时操作无害）。对非 `new` 返回的指针使用 `delete` 会导致未定义行为。
- **B 正确**：使用 `delete` 删除对象时，会先调用该对象的析构函数，再释放内存。
- **C 错误**：对同一指针多次使用 `delete` 会导致未定义行为（如重复释放内存），这是绝对不允许的。
- **D 正确**：删除动态分配的数组时，无论数组维数如何，只需在指针前使用一对方括号（即 `delete[]`）。但需注意，对于逐层独立分配的多维数组，应逐层释放，不可直接使用 `delete[]`。



如果有一个类是 myClass , 关于下面代码正确描述的是:

```c++
myClass::~myClass(){
    delete this;
    this = NULL;
}
```

A	正确，我们避免了内存泄漏

B	它会导致栈溢出

C	**无法编译通过**

D	这是不正确的，它没有释放任何成员变量。

- `this = NULL`	在 C++ 中，`this` 指针是一个右值（prvalue），不允许被赋值。语句 `this = NULL;` 试图修改 `this` 的值，违反了语言规则，导致编译错误。
- 即使忽略赋值问题，在析构函数中调用 `delete this` 也是极其危险的行为：如果对象是通过 `new` 分配的，且正在执行析构函数（例如因 `delete` 触发），那么 `delete this` 会导致析构函数的无限递归，最终引发栈溢出（选项 B 描述的情况）。但在此之前，代码已因编译错误而无法运行。
- 选项 A 和 D 的表述不准确：该代码不仅不能避免内存泄漏，还会导致严重错误；同时，释放成员变量应在析构函数中完成，但此处未展示任何成员变量，因此该批评并非代码的主要问题。
- 综上，代码因 `this = NULL;` 无法通过编译，故正确描述是 **C**。
- 在C++中，析构函数的主要职责是释放对象所持有的资源（如动态分配的内存、文件句柄、网络连接等）。对于类的成员变量，通常不需要（也不应该）在析构函数中调用`delete this`，因为析构函数本身就是在对象销毁时自动调用的。

正确的析构函数写法应该是：

- 如果类中有动态分配的成员（原始指针），则在析构函数中使用`delete data`或`delete[] buffer`释放它们。
- 如果使用智能指针（如`std::unique_ptr`、`std::shared_ptr`）管理资源，则通常不需要在析构函数中显式释放，因为智能指针会在析构时自动释放所管理的资源。
- 对于其他资源（如文件流、锁等），确保在析构函数中关闭或释放。

# 使用构造函数的坑：

下面是非默认构造函数:

```c++
Stock first("Concrete Conglomerate"); // calls constructor
Stock second();                       // declares a function
Stock third;                          // calls default constructor
```

- `Stock first("Concrete Conglomerate");` 这调用了非默认构造函数，即接受参数的构造函数

- `Stock second();`  这个声明指出：`second() `是一个返回`Stock`对象的函数

  **要想使用隐式的默认构造函数，不要带圆括号！**

  ```c++
  Stock second() !=	Stock second
  Stock second() != 	Stock second = Stock() 
  ```



下列代码编译时会产生错误的是（）

````c++
#include <iostream>
using namespace std;
struct Foo {
    Foo() {}
    Foo(int) {}
    void fun() {}
};
 
int main(void) {
    Foo a(10);//语句1
    a.fun();//语句2
    Foo b();//语句3 b是一个函数名
    b.fun();//语句4 不存在b对象，不能通过b调用函数fun
    return 0;
}
````

语句4会发生错误：

语句3没有声明一个b的`Foo`类型，而是声明了一个无参数的返回类型为`Foo`的函数`b`。如果要声明一个`Foo`，并调用默认构造函数，那么应该是这样的：`Foo b；`

```c++
Foo b() != Foo b;
Foo b() != Foo b = Foo();
```

# `this`指针

关于 C++ 中的 this 指针，下面说法正确的是（）[**多选**]

A	每个非静态成员函数都隐含一个 this 指针

B	this 指针在成员函数中始终指向当前作用对象

C	在非静态成员函数中直接访问成员 `m`，相当于 `this->m`

D	非静态成员函数中访问成员，必须使用 `this`

**A. 每个非静态成员函数都隐含一个 this 指针**
✅ 正确。C++ 标准规定，每个非静态成员函数都有一个隐式的 `this` 指针参数，指向调用该函数的对象。静态成员函数没有 `this` 指针。

**B. this 指针在成员函数中始终指向当前作用对象**
✅ 正确。`this` 指针始终指向调用该成员函数的对象实例，在成员函数执行期间保持不变。

**C. 在非静态成员函数中直接访问成员 m，相当于 this->m**
✅ 正确。编译器会自动将成员访问转换为通过 `this` 指针的访问。例如，`m = 10;` 等价于 `this->m = 10;`。

**D. 非静态成员函数中访问成员，必须使用 this**
❌ 错误。在非静态成员函数中，可以直接使用成员名称访问成员（如 `m = 10;`），不需要显式使用 `this`。编译器会隐式添加 `this->`。只有在需要明确指明当前对象或避免命名冲突时才需显式使用 `this`。

# 常成员

下列关于常成员的叙述中，正确的是
A	常成员函数只能由常对象调用
B	常成员函数不能更新对象的状态
C	常数据成员可以被类对象共享
D	常数据成员可以在构造函数体中初始化

- A 错误：常成员函数既可以被常对象调用，也可以被非常对象调用。但常对象只能调用常成员函数。
- B **正确**：常成员函数承诺不修改对象的状态（除非成员变量被声明为 `mutable`），即不能修改类的非 `mutable` 成员变量。
- C 错误：常数据成员是每个对象各自的常量，并不共享。共享的应是 `static` 成员。
- D 错误：==**常数据成员必须在构造函数的初始化列表中初始化，不能在构造函数体内赋值。**==

# 保护成员

- **保护成员（protected）**：派生类的成员函数可以直接访问基类的保护成员。

# 私有成员

- **私有成员（private）**：派生类的成员函数不能直接访问基类的私有成员，只能通过基类提供的公有或保护成员函数间接访问。

# `volatile` -禁止变量访问优化

`volatile` 是C/C++中的一个关键字，它告诉编译器该变量可能会**意外地改变**，因此编译器不应对该变量的访问进行优化。

## 核心含义

**`volatile` 的意思是：**

> "这个变量的值可能会在任何时候被程序之外的因素改变，不要做任何优化假设"

## 主要作用

### 1. **防止编译器优化**

```c
int flag = 0;

while (flag == 0) {
    // 等待
}
```

- **无 `volatile`**：编译器可能会优化为 `if (flag == 0) while(1) {}`，因为它认为循环中 `flag` 不会改变
- **有 `volatile`**：`volatile int flag = 0;` 强制每次循环都从内存读取 `flag` 的最新值

### 2. **适用于特定场景**

#### 场景1：**硬件寄存器访问**

```c
// 读取硬件状态寄存器
volatile uint32_t* status_reg = (uint32_t*)0x40021000;
while ((*status_reg & 0x01) == 0) {
    // 等待硬件就绪
}
```

#### 场景2：**中断服务程序中的共享变量**

```c
volatile int interrupt_occurred = 0;

// 主程序
while (!interrupt_occurred) {
    // 正常工作
}

// 中断处理函数（硬件触发）
void interrupt_handler() {
    interrupt_occurred = 1;  // 主程序需要立即看到这个变化
}
```

#### 场景3：**多线程共享变量**（但注意：volatile ≠ 线程安全）

```c
volatile bool data_ready = false;

// 线程1：生产者
void producer() {
    prepare_data();
    data_ready = true;  // 告诉消费者数据准备好了
}

// 线程2：消费者
void consumer() {
    while (!data_ready) {
        // 等待
    }
    consume_data();
}
```

## 与 `const` 的结合

| 组合             | 含义             | 使用场景             |
| ---------------- | ---------------- | -------------------- |
| `volatile`       | 变量可能意外改变 | 硬件寄存器、中断变量 |
| `const volatile` | 只读但可能改变   | 只读硬件寄存器       |
| `const`          | 程序不能修改     | 常量                 |

```c
// 示例：只读的状态寄存器（硬件会改变它，但程序不能写）
const volatile uint32_t* status_reg = (uint32_t*)0x40021000;
uint32_t status = *status_reg;  // 可以读取
// *status_reg = 1;  // 错误：const 禁止写入
```

## 示例对比

### 没有 `volatile`（可能出错）：

```c
int data_ready = 0;

void wait_for_data() {
    while (!data_ready) {
        // 编译器可能优化为：if (!data_ready) while(1) {}
    }
}

// 中断处理（异步发生）
void interrupt() {
    data_ready = 1;
}
```

### 使用 `volatile`（正确）：

```c
volatile int data_ready = 0;

void wait_for_data() {
    while (!data_ready) {
        // 每次都会从内存读取 data_ready
    }
}

void interrupt() {
    data_ready = 1;  // 立即生效
}
```

## 重要注意事项

### 1. **`volatile` ≠ 原子性**

```c
volatile int counter = 0;

// ❌ 这不是原子操作！
counter++;  // 在多线程中仍可能出问题

// 实际上相当于：
// 1. 读取 counter 到寄存器
// 2. 寄存器加1
// 3. 写回 counter
```

### 2. **`volatile` ≠ 内存屏障**

- `volatile` 不保证执行顺序
- 需要内存屏障时应用 `std::atomic` 或特定屏障指令

### 3. **不要滥用 `volatile`**

```c
// ❌ 不需要的情况
for (volatile int i = 0; i < 1000; i++) {
    // 循环变量i不需要volatile
}

// ✅ 需要的情况
volatile bool* hardware_flag = (bool*)0x1234;
```

## 现代C++中的替代方案

对于多线程编程，优先使用：

```cpp
#include <atomic>

std::atomic<bool> data_ready{false};  // 线程安全，包含内存屏障

// 生产者
data_ready.store(true, std::memory_order_release);

// 消费者
while (!data_ready.load(std::memory_order_acquire)) {
    // 等待
}
```

## 总结

| 特性         | 说明                                                |
| ------------ | --------------------------------------------------- |
| **目的**     | 防止编译器优化，确保每次访问都从内存读取            |
| **适用场景** | 硬件寄存器、中断变量、信号处理、多线程（有限使用）  |
| **不保证**   | 原子性、内存顺序、线程安全                          |
| **现代替代** | 多线程中用 `std::atomic`，硬件访问中仍需 `volatile` |

**核心原则**：只有当变量可能被**程序外部因素**（硬件、中断、其他线程等）改变时，才使用 `volatile`。

# `explicit` -禁止隐式类型转换

在 C++ 中，**`explicit` 是一个关键字**，用于修饰类的**单参数构造函数**（或可通过默认参数变成单参数的构造函数），以防止编译器进行隐式类型转换。

## 主要作用

**禁止隐式类型转换**，要求必须显式调用构造函数。

## 示例说明

### 1. 没有 `explicit` 的情况（允许隐式转换）

```cpp
class MyClass {
public:
    MyClass(int x) : value(x) {}  // 单参数构造函数
    int getValue() const { return value; }
private:
    int value;
};

void printValue(const MyClass& obj) {
    std::cout << obj.getValue() << std::endl;
}

int main() {
    MyClass obj1(10);     // 正常构造
    MyClass obj2 = 20;    // 隐式转换：int → MyClass
    printValue(30);       // 隐式转换：30 → MyClass(30)
    return 0;
}
```

**输出**：`30`

这里 `printValue(30)` 能编译通过，因为编译器会自动调用 `MyClass(30)` 进行隐式转换。

### 2. 使用 `explicit` 的情况（禁止隐式转换）

```cpp
class MyClass {
public:
    explicit MyClass(int x) : value(x) {}  // explicit 构造函数
    int getValue() const { return value; }
private:
    int value;
};

void printValue(const MyClass& obj) {
    std::cout << obj.getValue() << std::endl;
}

int main() {
    MyClass obj1(10);     // 正常构造 ✓
    // MyClass obj2 = 20; // 错误：不允许隐式转换 ✗
    // printValue(30);    // 错误：不允许隐式转换 ✗
    
    printValue(MyClass(40));  // 正确：显式转换 ✓
    printValue(static_cast<MyClass>(50));  // 正确：显式转换 ✓
    return 0;
}
```

## 使用场景

1. **避免意外的类型转换**

   ```cpp
   class String {
   public:
       explicit String(int size);  // 明确表示：创建指定长度的字符串
   };
   
   String s1(10);     // 创建10个字符的字符串
   // String s2 = 10; // 错误！避免误解：10是什么？长度还是内容？
   ```

2. **智能指针设计**

   ```cpp
   template<typename T>
   class SmartPtr {
   public:
       explicit SmartPtr(T* ptr);  // 避免意外转换
   };
   
   SmartPtr<int> p(new int(5));
   // SmartPtr<int> q = new int(10);  // 错误！避免内存泄漏风险
   ```

3. **容器类**

   ```cpp
   class Vector {
   public:
       explicit Vector(int size);  // 明确是大小，不是元素值
   };
   
   Vector v1(5);     // 创建5个元素的向量
   // Vector v2 = 5; // 错误！避免歧义
   ```

## C++11 扩展

从 C++11 开始，`explicit` 还可用于**转换运算符**：

```cpp
class SmartBool {
public:
    explicit operator bool() const {  // 显式转换为bool
        return state;
    }
private:
    bool state;
};

SmartBool sb;
// if (sb) ...        // C++11 起允许（上下文转换）
// bool b = sb;       // 错误：需要显式转换
bool b = static_cast<bool>(sb);  // 正确
```

## 最佳实践

1. **默认使用 `explicit`** 修饰单参数构造函数，除非有充分的理由需要隐式转换
2. **转换构造函数**（如 `std::string(const char*)`）通常不使用 `explicit`
3. **复制构造函数**不应使用 `explicit`（会破坏拷贝初始化）

## 总结

`explicit` 关键字：

- 提高代码安全性，防止意外类型转换
- 增强代码可读性，明确转换意图
- 是现代 C++ 中的重要安全特性

## 什么是 is-a 关系

**is-a 关系** 是面向对象编程中的一个核心概念，指一个类（派生类）是另一个类（基类）的特殊类型，即"派生类是一种基类"的关系。

## 核心特征：

- **公有继承的语义**：通过公有继承实现

- **可替换性**：派生类对象可以替代基类对象使用（Liskov替换原则）

- **类型兼容**：派生类对象可以赋值给基类指针/引用

| 关系类型                       | 描述      | 示例               | 实现方式           |
| :----------------------------- | :-------- | :----------------- | :----------------- |
| **is-a**                       | 继承关系  | 汽车是一种交通工具 | 公有继承           |
| **has-a**                      | 组合/聚合 | 汽车有发动机       | 成员对象           |
| **uses-a**                     | 依赖关系  | 司机使用汽车       | 参数传递、局部变量 |
| **is-implemented-in-terms-of** | 实现关系  | 栈用向量实现       | 私有继承/组合      |

## is-a关系的条件：

1. **完全继承接口**：派生类必须支持基类的所有操作
2. **不违反基类契约**：派生类不能弱化基类的前置条件或强化后置条件
3. **语义一致性**：派生类必须满足基类的所有语义约束

## 注意事项：

- **公有继承才表示is-a关系**：私有/保护继承表示其他关系
- **不是所有"现实中的is-a"都应建模为继承**：要考虑软件设计的实际需求
- **小心"正方形-长方形"问题**：数学上的is-a关系在编程中可能违反Liskov替换原则

### 反例（违反is-a关系）：

```c++
// 错误示例：企鹅是一种鸟，但不会飞
class Bird {
public:
    virtual void fly() { cout << "Flying" << endl; }
};

class Penguin : public Bird {  // 逻辑错误
public:
    void fly() override {
        throw "Penguins can't fly!";  // 违反基类契约
    }
};
```

正确的设计应该将不会飞的特性分离：

```c++
class Bird {
    // 通用鸟类特性
};

class FlyingBird : public Bird {
    virtual void fly() { /* ... */ }
};

class Penguin : public Bird {  // 不继承FlyingBird
    // 不会飞
};
```

## 子类访问权限

在派生类的函数中，能够直接访问**全部基类**的公有成员和保护成员。这句话是否正确？

不完全正确。

说明：

- 在C++中，派生类的成员函数可以直接访问其**直接基类**的所有公有成员和保护成员，无论继承方式如何。继承方式（公有、保护或私有）影响的是这些成员在派生类中对外部的可见性，但不影响派生类内部成员函数对它们的直接访问。
- 但对于**间接基类**（即基类的基类）如A->B->C，访问能力取决于继承链中的继承方式。如果继承链中存在**私有继承**，则间接基类的公有成员和保护成员在派生类中可能无法直接访问（因为它们可能在中间派生类中变为私有成员，而私有成员不能被后续派生类访问）**只有私有继承会切断访问链。**

```c++
class A {
public:
    int public_a;
protected:
    int protected_a;
};

class B : protected A {
    // 在B内部：A::public_a 和 A::protected_a 都变成了 protected 成员
public:
    void testB() {
        public_a = 1;      // 正确，B可直接访问（现在是protected）
        protected_a = 2;   // 正确，B可直接访问
    }
};

class C : public B { // 或 `class C : protected B`
    // 从B继承来的成员（其中包括从A“传承”下来的protected成员）
public:
    void testC() {
        public_a = 3;      // **正确！** C可以访问间接基类A的public_a（因为它作为B的protected成员被继承下来）
        protected_a = 4;   // **正确！** 同上
    }
};
```

+-----------------+

+-----------------+

# 编译时多态和运行时多态

1. 编译时多态（Compile-time Polymorphism）：
   - 也称为静态多态，是通过**模板**和**函数重载**实现的。
   - 在编译时，编译器根据函数调用的参数类型或模板参数来确定具体调用哪个函数。
   - 例如，函数重载和运算符重载，以及模板特化。
2. **运行时多态**（Runtime Polymorphism）：
   - 也称为动态多态，是通过**虚函数**和**继承**实现的。
   - **在运行时，根据对象的实际类型来调用相应的函数。**
   - 通常通过基类的指针或引用来调用虚函数，具体调用哪个派生类的函数取决于指针或引用所指向的实际对象类型。

- ## 对比总结

| 特性         | 编译时多态           | 运行时多态            |
| :----------- | :------------------- | :-------------------- |
| **确定时机** | 编译期间             | 运行期间              |
| **实现机制** | 函数重载、模板       | 虚函数、继承          |
| **性能**     | 更高（无运行时开销） | 稍低（虚表查找）      |
| **灵活性**   | 较低                 | 较高                  |
| **绑定方式** | 早期绑定             | 晚期绑定              |
| **关键字**   | 无特殊关键字         | `virtual`, `override` |

## 虚函数实例

```c++
#include "stdio.h"
class Base
{
public:
    Base()
    {
        Init();
    }
    virtual void Init()
    {
        printf("Base Init\n");
    }
    void func()
    {
        printf("Base func\n");
    }
};
class Derived: public Base
{
public:
    virtual void Init()
    {
        printf("Derived Init\n");
    }
    void func()
    {
        printf("Derived func\n");
    }
};
 
int main()
{
    Derived d; // 创建Derived对象
    ((Base *)&d)->func(); // 非虚函数调用
    ((Base *)&d)->Init(); // 虚函数调用
    return 0;
}

Base Init 
Base func
Derived Init
```

### **分析**：

```c++
Derived d;  // 创建Derived对象
```

构造顺序：

1. 调用基类 `Base` 的构造函数
2. `Base` 构造函数中调用 `Init()`
3. 此时虚函数表指针指向 `Base` 的虚表
4. **输出：`"Base Init"`**
5. 完成 `Derived` 部分的构造

```c++
((Base *)&d)->func();
```

 **将派生类对象 `d` 强制转换为基类指针，然后调用非虚函数 `func()`**。

- `&d`：获取 `Derived` 类型对象 `d` 的地址（`Derived*` 类型）
- `(Base*)&d`：将 `Derived*` 强制转换为 `Base*`（C风格强制转换）
- `->func()`：通过基类指针调用成员函数

由于`func()` 是**非虚函数**，使用的是**静态绑定**(编译时确定)，指针的类型是`Base*`，所以调用 `Base::func(),` **输出：`"Base func"`**.

```c++
((Base *)&d)->Init();  // 虚函数调用
```

- `Init()` 是**虚函数**（声明为 `virtual`）
- 通过基类指针调用虚函数时，发生**动态绑定**
- 根据对象的**实际类型**（`Derived`）调用相应的函数
- **输出：`"Derived Init"`**

定义一个函数为虚函数，不代表函数是不被实现的函数

定义它为虚函数是为了允许使用基类的指针来调用子类的这个函数

## 虚函数与纯虚函数

定义一个函数为纯虚函数，才代表函数没有被实现

定义它为纯虚函数是为了实现一个接口，起到规范的作用，规范继承这个类的程序员必须实现这个函数。

```c++
class A
{
public:
    virtual void foo()
    {
        cout<<"A::foo() is called"<<endl;
    }
};
class B:public A
{
public:
    void foo()
    {
        cout<<"B::foo() is called"<<endl;
    }
};
int main(void)
{
    A *a = new B();
    a->foo();   // 在这里，a虽然是指向A的指针，但是被调用的函数(foo)却是B的!
    return 0;
}
```

这是一个虚函数的典型应用，虚函数，它虚就虚在所谓“推迟联编”或者“动态联编”上，一个类函数的调用并不是在编译时刻被确定的，而是在运行时被确定的。由于编写代码 时候并不能确定被调用的是基类的函数还是哪个派生类得到函数，所以被写成“虚函数”。

## 纯虚函数

纯虚函数实在基类中声明的虚函数，它在基类中没有定义，但要求任何派生类都要定义自己的实现方法。在基类中实现纯虚函数的方法是在函数原型后加 `=0`

```c++
virtual void funtion1()==0;
```

**引入原因**

1、为了方便使用多态特性，我们常常需要在基类中定义虚拟函数。

2、在很多情况下，基类本身生成对象是不合情理的。例如，动物作为一个基类可以派生出老虎、孔雀等子类，但动物本身生成对象明显不合常理。

为了解决上述问题，引入了纯虚函数的概念，将函数定义为纯虚函数（方法：**virtual ReturnType Function()= 0;**），则编译器要求在派生类中必须予以重写以实现多态性。同时含有纯虚拟函数的类称为抽象类，它不能生成对象。这样就很好地解决了上述两个问题。

**声明了纯虚函数的类是一个抽象类。所以，用户不能创建类的实例，只能创建它的派生类的实例。**

**纯虚函数最显著的特征是**：它们必须在继承类中重新声明函数（不要后面的＝0，否则该派生类也不能实例化），而且它们在抽象类中往往没有定义。

定义纯虚函数的目的在于，使派生类仅仅只是继承函数的接口。

纯虚函数的意义，让所有的类对象（主要是派生类对象）都可以执行纯虚函数的动作，但类无法为纯虚函数提供一个合理的默认实现。所以类纯虚函数的声明就是在告诉子类的设计者，"你必须提供一个纯虚函数的实现，但我不知道你会怎样实现它"。

## 抽象类

如果一个类中有纯虚函数，那么这个类就是抽象类

抽象类是一种特殊的类，它是为了抽象和设计的目的为建立的，它处于继承层次结构的较上层。

**（1）抽象类的定义：** 称带有纯虚函数的类为抽象类。

**（2）抽象类的作用：** 抽象类的主要作用是将有关的操作作为结果接口组织在一个继承层次结构中，由它来为派生类提供一个公共的根，派生类将具体实现在其基类中作为接口的操作。所以派生类实际上刻画了一组子类的操作接口的通用语义，这些语义也传给子类，子类可以具体实现这些语义，也可以再将这些语义传给自己的子类。

**（3）使用抽象类时注意：**

- 抽象类只能作为基类来使用，其纯虚函数的实现由派生类给出。如果派生类中没有重新定义纯虚函数，而只是继承基类的纯虚函数，则这个派生类仍然还是一个抽象类。如果派生类中给出了基类纯虚函数的实现，则该派生类就不再是抽象类了，它是一个可以建立对象的具体的类。
- 抽象类是不能定义对象的。

## 总结：

- 1、纯虚函数声明如下： **virtual void funtion1()=0;** 纯虚函数一定没有定义，纯虚函数用来规范派生类的行为，即接口。包含纯虚函数的类是抽象类，抽象类不能定义实例，但可以声明指向实现该抽象类的具体类的指针或引用。

- 2、虚函数声明如下：**virtual ReturnType FunctionName(Parameter)** 虚函数必须实现，如果不实现，编译器将报错，错误提示为：虚函数可以在基类中声明，在派生类中实现

  ```c++
  error LNK****: unresolved external symbol "public: virtual void __thiscall ClassName::virtualFunctionName(void)"
  ```

- 3、对于虚函数来说，父类和子类都有各自的版本。由多态方式调用的时候动态绑定。

- 4、实现了纯虚函数的子类，该纯虚函数在子类中就变成了虚函数，子类的子类即孙子类可以覆盖该虚函数，由多态方式调用的时候动态绑定。

- 5、虚函数是C++中用于实现多态(polymorphism)的机制。核心理念就是通过基类访问派生类定义的函数。

- 6、在有动态分配堆上内存的时候，析构函数必须是虚函数，但没有必要是纯虚的。

- 7、友元不是成员函数，只有成员函数才可以是虚拟的，因此友元不能是虚拟函数。但可以通过让友元函数调用虚拟成员函数来解决友元的虚拟问题。

- 8、析构函数应当是虚函数，将调用相应对象类型的析构函数，因此，如果指针指向的是子类对象，将调用子类的析构函数，然后自动调用基类的析构函数。

有纯虚函数的类是抽象类，不能生成对象，只能派生。他派生的类的纯虚函数没有被改写，那么，它的派生类还是个抽象类。

定义纯虚函数就是为了让基类不可实例化化，因为实例化这样的抽象数据结构本身并没有意义，或者给出实现也没有意义。

实际上我个人认为纯虚函数的引入，是出于两个目的：

- 1、为了安全，因为避免任何需要明确但是因为不小心而导致的未知的结果，提醒子类去做应做的实现。
- 2、为了效率，不是程序执行的效率，而是为了编码的效率。

# 空指针问题

```c++
#include <iostream>
using namespace std;
 
class A {
public:
    void FunctionA() {cout << "FunctionA" << endl;}
    virtual void FunctionB() {cout << "FunctionB" << endl;}
    static void FunctionC() {cout << "FunctionC" << endl;}
};
 
class B : public A {
public:
    void FunctionB() {cout << "FunctionB" << endl;}
    int FunctionD() {cout << "FunctionD" << endl;}
};
 
int main() {
    B *b = nullptr;
    b->FunctionA();
    b->FunctionB();
    b->FunctionC();
    b->FunctionD();
    return 0;
}
```

以上程序中，下列哪个函数调用会有问题（）

在给定的程序中，`b` 是一个空指针（`nullptr``），通过该指针调用成员函数会导致未定义行为。具体分析如下：

- `FunctionA()`：非虚成员函数，不访问成员变量，可能不会立即崩溃，但属于未定义行为。
- `FunctionB()`：虚函数，调用时需要访问对象的虚表指针，而 `b` 为空，几乎必然导致程序崩溃。
- `FunctionC()`：静态成员函数，不依赖对象实例，调用安全。
- `FunctionD()`：非虚成员函数，类似 `FunctionA()`，属于未定义行为。

因此，最可能立即导致问题的是 `FunctionB()` 的调用。

答案：`FunctionB()`

# 禁止类的拷贝操作

**Boost Noncopyable**

在C++中，拷贝操作是非常常见的，但有时我们希望禁止类的拷贝操作，以避免潜在的问题。`Boost`库提供了一个简单的解决方案，即使用`boost::noncopyable`类。

```c++
#include <boost/core/noncopyable.hpp>
class MyClass : private boost::noncopyable {
public:
   MyClass() {}
   ~MyClass() {}
};
```

在这个示例中，`MyClass`继承了`boost::noncopyable`，因此不能被拷贝或赋值。

为什么使用Boost Noncopyable

在某些情况下，我们希望类的实例不能被拷贝。例如，当类管理动态内存或其他资源时，拷贝操作可能导致资源泄漏或双重释放。通过禁止拷贝操作，我们可以避免这些问题。

实现不可拷贝类的其他方法

除了使用Boost库，我们还可以通过以下方法实现不可拷贝类：

- **将拷贝构造函数和拷贝赋值操作符声明为私有**：

```c++
class MyClass {
private:
    MyClass(const MyClass&);
    MyClass& operator=(const MyClass&);
};
```

- **在C++11及以上版本中使用`delete`关键字**：

  ```c++
  class MyClass {
  public:
      MyClass(const MyClass&) = delete;
      MyClass& operator=(const MyClass&) = delete;
  };
  ```

这些方法都可以有效地禁止类的拷贝操作。

结论

使用`boost::noncopyable`类可以方便地禁止类的拷贝操作，避免潜在的资源管理问题。对于需要禁止拷贝的类，这是一个简单而有效的解决方案。



# 覆盖和重写有什么区别

在C++中，“覆盖”（override）是面向对象编程中的一个标准术语，而“重写”（overwrite）通常不是标准术语，容易与“重载”（overload）或“隐藏”（hide）混淆。下面分别说明它们的区别。

---

### 1. 覆盖（Override）

**定义**：派生类重新定义基类的**虚函数**，从而在通过基类指针或引用调用时，实现动态多态。

**特点**：
- 基类函数必须声明为 `virtual`。
- 派生类函数与基类函数具有相同的**函数签名**（返回类型、函数名、参数列表）。
- 使用 `override` 关键字（C++11起）可以显式标注，让编译器检查是否正确覆盖。
- 运行时根据对象的实际类型决定调用哪个版本。

**示例**（你的代码中就是覆盖）：

```cpp
class Animal {
public:
    virtual void speak() const { ... }  // 虚函数
};

class Dog : public Animal {
public:
    void speak() const override { ... } // 覆盖
};
```

---

### 2. 重写（Overwrite）的常见误解

“重写”一词在中文技术社区中有时被用作“覆盖”的同义词，但更严格地说，C++中并没有“重写”这个标准术语。如果遇到“重写”，通常可能指以下两种情况：

#### (1) 重载（Overload）
**定义**：在同一作用域内（如同一个类中），函数名相同但参数列表不同（参数个数、类型或顺序）。重载与继承无关。

```cpp
class Dog {
public:
    void speak();          // 无参
    void speak(int times); // 重载，参数不同
};
```

#### (2) 隐藏（Hide）
**定义**：派生类定义了与基类**同名**的函数，但该函数在基类中**不是虚函数**，**或者虽然是虚函数但参数列表不同**。此时基类的同名函数在派生类作用域中被隐藏，无法通过派生类对象直接调用（除非使用作用域运算符 `::`）。

```cpp
class Animal {
public:
    void info() { ... }        // 非虚函数
    virtual void move() { ... }
};

class Dog : public Animal {
public:
    void info() { ... }        // 隐藏基类的 info
    void move(int speed) { ... } // 隐藏基类的 move,构成（即使基类是虚函数，但参数不同，也属于隐藏）
};
```

---

### 总结

| 术语                 | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| **覆盖（Override）** | 派生类重新定义基类的虚函数，函数签名相同，实现多态。         |
| **重载（Overload）** | 同一作用域内函数名相同，参数列表不同。                       |
| **隐藏（Hide）**     | 派生类定义了与基类同名的函数（无论是否为虚函数，只要签名不同或基类非虚），导致基类函数在派生类作用域中不可见。 |

如果你看到“重写”一词，需要根据上下文判断作者是想表达“覆盖”还是“隐藏”。在你的代码中，`Dog` 和 `Cat` 对 `speak()` 和 `info()` 的实现都属于**覆盖**（因为基类函数是 `virtual`，且签名一致）。
