## cat

功能：用来**串接文件或显示文件的内容**，也可以从**标准输入设备读取数据**并将结果重定向到一个新的文件中,达到建立新文件的目的。

| 选项          | 作用                                              |
| ------------- | ------------------------------------------------- |
| -n或-number   | 由1开始对所有输出的行数编号                       |
| -b            | 和-n相似,只不过对于空白行不编号                   |
| -s            | 当遇到由连续两行以上的空白行,就替换为一行的空白行 |
| -E--show-ends | 在每行结束处显示 $                                |

**输出重定向**：

````bash
cat a1.txt a2.txt>a3.txt#cat a1.txt a2.txt->a3.txt
cat a1.txt a2.txt>>a3.txt#cat a1.txt a2.txt->>a3.txt
````

- `>`：表示输出重定向，将a1和a2的内容输出到a3，如果a3.txt的不存在则创建一个新的a3.txt，如果存在则覆盖。
- `>>`：表示追加重定向：将a1和a2的内容输出到a3的尾部，如果a3.txt的不存在则创建一个新的a3.txt。

## rm

Linux rm（英文全拼：remove）命令用于删除一个文件或者目录。

- **语法**

```bash
rm [options] name...
```

**参数**：

- **-i 删除前逐一询问确认。**
- -f 即使原档案属性设为唯读，亦直接删除，无需逐一确认。
- **-r 将目录及以下之档案亦逐一删除。**

### 示例

删除文件可以直接使用rm命令，若删除目录则必须配合选项"-r"，例如：

```bash
# rm  test.txt 
rm：是否删除 一般文件 "test.txt"? y  
# rm  homework  
rm: 无法删除目录"homework": 是一个目录  
# rm  -r  homework  
rm：是否删除 目录 "homework"? y 
```

删除当前目录下的所有文件及目录，命令行为：

```bash
rm  -r  * 
```

文件一旦通过rm命令删除，则无法恢复，所以必须格外小心地使用该命令。

## `ls`

- 功能描述：列出目录的内容，是list的缩写
- 语法：`ls [选项][文件或目录]`

| 参数                        | 说明                                                         |
| --------------------------- | ------------------------------------------------------------ |
| `-a` 或 `--all`             | 显示所有文件（包括以 `.` 开头的隐藏文件）。                  |
| `-A` 或 `--almost-all`      | 显示除 `.` 和 `..` 外的所有文件（包括隐藏文件）。            |
| `-l`                        | 以长格式（详细信息）列出文件（权限、所有者、大小、修改时间等）。 |
| `-h` 或 `--human-readable`  | 与 `-l` 一起使用时，以人类可读的格式显示文件大小（如 KB、MB）。 |
| `-t`                        | 按修改时间排序（最新优先）。                                 |
| `-r` 或 `--reverse`         | 反向排序（配合 `-t`、`-S` 等使用）。                         |
| `-S`                        | 按文件大小排序（大文件优先）。                               |
| `-R` 或 `--recursive`       | 递归列出子目录内容。                                         |
| `-F` 或 `--classify`        | 在文件名后附加标识符（如 `/` 表示目录，`*` 表示可执行文件）。 |
| `--color`                   | 彩色输出（通常默认启用，`--color=auto`）。                   |
| `-i` 或 `--inode`           | 显示文件的 inode 编号。(**显示索引节点**)                    |
| `-n` 或 `--numeric-uid-gid` | 以数字形式显示 UID 和 GID（替代用户名和组名）。              |
| `-d` 或 `--directory`       | 仅显示目录本身，而非其内容（常用于配合 `-l`）。              |
| `-1`                        | 每行只显示一个文件（默认在终端宽度不足时自动启用）。         |
| `-m`                        | 以逗号分隔的列表形式显示文件。                               |
| `-Q` 或 `--quote-name`      | 用引号括住文件名（适用于含空格的文件名）。                   |
| `--group-directories-first` | 先显示目录，后显示文件。                                     |
| `--time-style=<格式>`       | 自定义时间显示格式（如 `+%Y-%m-%d`）。                       |

### ls -l

在使用 **ls -l** 命令时，第一列的字符表示文件或目录的类型和权限。其中第一个字符表示文件类型，例如：

- \- 表示普通文件
- d 表示目录
- l 表示符号链接
- c 表示字符设备文件
- b 表示块设备文件
- s 表示套接字文件
- p 表示管道文件

在使用 **ls -l** 命令时，第一列的其余 9 个字符表示文件或目录的访问权限，分别对应三个字符一组的 **rwx** 权限。例如：

- r 表示读取权限
- w 表示写入权限
- x 表示执行权限
- \- 表示没有对应权限

前三个字符表示所有者的权限，中间三个字符表示所属组的权限，后三个字符表示其他用户的权限。例如：

```bash
-rw-r--r-- 1 user group 4096 Feb 21 12:00 file.txt
```

表示文件名为file.txt的文件，**所有者**具有读写权限，**所属组**和**其他用户**只有读取权限。

查找最近修改的文件：

```bash
ls -lt | head -5
```

显示最近修改的 5 个文件。

统计文件数量：

```bash
ls | wc -l
```

统计当前目录下的文件数量(不包括隐藏文件)。

**linux文件的三种时间属性分别为：**

- **atime**，为access time（访问时间）的缩写，显示的是文件中的数据最后被访问的时间，读一次这个文件的内容，这个时间就会更新，比如被系统的进程直接使用或者通过一些命令和脚本间接使用。（执行一些可执行文件、脚本）或对这个文件运用 more、cat等命令。ls、stat命令都不会修改文件的访问时间

- **mtime**，为modify time（修改时间）的缩写，显示的是文件的内容被改变时的最后时间，比如用vi编辑时就会改变（也就是Block的内容），ls -l列出的时间就是这个时间。

- **ctime**，为change time（状态改动时间）的缩写，显示的是文件的权限，拥有者，所属的组，链接数发生改变时的时间。当然当内容改变时，也会改变。（也就是Inode内容发生改变和Block内容发生改变时），通过chmod、chown命令修改一次文件属性，这个时间就会更新。

## `pwd`

`print working directory`：用于显示**当前工作目录的绝对路径**。(完整路径)

- 在 Bash 中，`pwd` 通常是一个**内置命令**（shell builtin），同时系统中也有一个独立的可执行文件（如 `/bin/pwd`）。
- 可以通过 `type pwd` 查看：

```bash
type pwd
#pwd 是 shell 内建
```

**参数说明:**

| 选项        | 说明                                                   |
| :---------- | :----------------------------------------------------- |
| `-L`        | 显示**逻辑路径**（**默认行为**），**保留符号链接名称** |
| `-P`        | 显示**物理路径**，解析（展开）符号链接                 |
| `--help`    | 显示帮助信息                                           |
| `--version` | 显示版本信息                                           |

- 这里的解析符号链接指的是：**是否把路径中的符号链接（软链接）替换成它指向的真实路径**。

### pwd 命令的工作原理

`pwd` 命令通过以下方式确定当前工作目录：

1. 检查环境变量 `PWD` 的值（当使用 `-L` 选项时）
   - **逻辑路径**（`-L`）是 shell 维持的当前工作目录变量，反映了你是“怎么走进来”的。
2. 或者通过遍历父目录来物理确定路径（当使用 `-P` 选项时）
   - **物理路径**（`-P`）是通过系统调用获取的真实文件系统路径，去掉了所有符号链接的中间层。

多数情况下，`-L` 更符合你的直观感受（当进的是链接目录，自然希望显示链接名）。`-P` 则用于需要确切知道文件实际存放位置的场景，比如权限检查、挂载点判断等。

### 使用 -P 选项

```bash
$ ln -s /var/www/html myweb
$ cd myweb
$ pwd
/home/username/myweb    # 逻辑路径
$ pwd -P
/var/www/html          # 物理路径
```

## cd

`cd`（英文全拼：change directory）命令用于改变当前工作目录的命令，切换到指定的路径。

若目录名称省略(直接使用`cd`)，则进入使用者的 `home` 目录。

另外

- **~ 也表示为 home 目录** ， 
- **.** **表示目前所在的目录**，
- **..** **表示目前目录位置的上一层目录**。

```bash
cd [dirName]
```

- `dirName`：要切换的目标目录，可以是相对路径或绝对路径。

### 示例

切换到 /usr/bin/ 目录:

```bash
cd /usr/bin
#cd bin #当当前在usr目录下时,直接使用相对路径也可进入该目录下的bin目录
```

```bash
cd ..        #回到上一级目录
cd ../../    #切换到上上级目录
```

**切换到用户主目录（home）：**使用 **~** 表示当前用户的主目录，可以使用 cd 命令直接切换到主目录。

```bash
cd ~
# cd
```

**切换到上次访问的目录：**使用 **cd -** 可以切换到上次访问的目录。

```bash
cd -
```

**切换到环境变量指定的目录：**可以使用环境变量来指定目标目录，并使用 **cd** 命令切换到该目录。

```bash
cd $VAR_NAME
```

## `mkdir`

Linux mkdir（英文全拼：make directory）命令用于创建目录。

要在某个目录下创建文件或子目录，你需要对该目录拥有 **写 (`w`) 权限**。无论你是否在这个目录里，只要**没有写权限就无法创建**（可以**借助超级用户权限**，此时可以在命令前加上`sudo`，临时提权来完成操作。）；反之，有了写权限就能创建。

- **语法**

```bash
mkdir [-p/-m/-v] dirName
```

**参数说明**：

| 选项 | 作用                                               |
| ---- | -------------------------------------------------- |
| -p   | 依次创建目录，需要时创建目录的上级目录             |
| -m   | 设置权限模式，在创建目录时按模式指定设置目录权限。 |
| -v   | 每次创建新目录时，都显示执行过程信息。             |

- -p 确保目录名称存在，不存在的就建一个。
- -m 选项用来设置目录的权限。对目录的 **读**、**写**、**执行**权限分别为 **4、2 、1**，它们的和表示**目录所有者** 或 **所属组**中其他人对目录的权限 或 系统中**其他人**   对该目录的权限。
- -m的格式为`mkdir -m [参数] [目录名]`，这里的参数信息见后文

- 常见的参数组合有：

| 参数 | 含义                                           |
| ---- | ---------------------------------------------- |
| 600  | 只有所有者有读写权限                           |
| 700  | 只有所有者有读写以及执行的权限                 |
| 644  | 所有者有读写权限，组用户和其他用户只有读的权限 |
| 666  | 每个人都有可读可写权限                         |
| 777  | 每个人都有读和写以及执行的权限                 |

### 示例

```bash
mkdir runoob #在当前工作目录下，建立一个名为 runoob 的子目录
mkdir -p runoob2/test #在工作目录下的 runoob2 目录中，建立一个名为 test 的子目录。
#若 runoob2 目录原本不存在，则建立一个。（注：本例若不加 -p 参数，且原本 runoob2 目录不存在，则产生错误。）
mkdir -m 777 test4 #在当前工作目录下,创建test4目录，每个人都有读、写和执行的权限。	
```

## chgrp

Linux chgrp（英文全拼：**change group**）命令用于变更文件或目录的**所属群组**。

`change group` ，改变文件或目录的**所属组**，要被改写的组名必须在`/etc/group`文件内**存在**才可以，默认情况下只有root权限才能执行。

与 **`chown`** 命令不同，`chgrp` 允许普通用户改变文件所属的组，只要该用户是该组的一员。

```bash
chgrp [-选项][所属群组][文件或目录...][--help][--version]
```

前面是所属组（目标），后面是该文件或目录（源）

### 参数

chgrp 命令的参数可以分为以下几类：操作标志、输出控制、递归处理和参考文件。

## chown

Linux chown（英文全拼：**change owner**）命令用于设置文件所有者和文件关联组的命令。

利用 chown 将**指定文件的所有者改为指定的用户或组，还可以修改文件所属组群**。用户可以是用户名或者用户 ID，组可以是组名或者组 ID，文件是以空格分开的要改变权限的文件列表，支持通配符。

chown 需要超级用户 **root** 的权限才能执行此命令，非超级用户如需要设置关联组可能需要使用 `chgrp` 命令。

**使用权限** : root

`chown [选项][用户[:群组]][文件或目录]`

| -c 或 --changes                                | 效果类似 "-v" 参数，但仅回报更改的部分。适合需要确认具体修改了哪些文件时使用。 |

| -R 或 --recursive                              | 递归处理，将指定目录下的所有文件及子目录一并处理。批量修改目录内所有文件时使用。 |
| -v 或 --verbose                                | 显示指令执行过程。用于调试或确认每个文件的修改状态。         |
| --reference=<参考文件或目录(目的文件)>  原文件 | 把指定文件或目录的所属群组全部设成和参考文件或目录**相同的所属群组**。用于批量复制权限场景。 |

```bash

```

### 注意事项

| 操作                           | 普通用户（文件所有者）         | root   |
| :----------------------------- | :----------------------------- | :----- |
| 只改所属组（改为自己所在的组） | ✅ `chgrp` / `chown :组` 均允许 | ✅ 允许 |
| 只改所属组（改为非所在组）     | ❌ 禁止                         | ✅ 允许 |

# 5.3.2输入重定向


# 5.3.3输出重定向

输出重定向，将从标准输出或标准错误输出 重新定向到 指定的文件

## 5.4 管道

管道（Pipeline）：一个由标准输入输出链接起来的进程集合，是一个连接两个进程的连接器管道的命令操作符是：“|”，它将操作符左侧命令的输出信息（stdout）作为操作符右侧命令的输入信息（stdin）。

管道类似于输入输出重定向，但是管道触发的是两个子进程，而重定向执行的是一个进程。

**管道使用时需要注意以下几点**：

1. 管道是单向的，一端只能输入，另一端只能用于输出，遵循“先进先出”原则。
2. 管道命令只处理前一个命令的正确输出，如果输出的是错误信息，则不处理。
3. 管道分为普管道操作符右侧命令通管道和命名管道两种。这里所讲的管道是 **普通管道**。

```bash
#例1：查找文件内容并显示、统计

$cat  a1.txt|grep “a”|wc –l  #查找文件a1.txt中包含a的字符串并统计行数，随后显示统计结果
```

可以看出系统将前一个命令的输出也就是a1.txt的内容输入到后一个命令，作为grep的输入，最终的查询结果会显示在屏幕上。

# 5.5.1 什么是链接

链接是一种在共享文件和访问它的用户的若干目录项之间建立联系的方法。

例如：当我们需要在不同的目录，用到相同的文件时，我们不需要在每一个需要的目录下都放一个必须相同的文件，我们只要在某个固定的目录，放上该文件，然后在其它的目录下链接（link）它就可以，不必重复的占用磁盘空间。	

# 5.5.2 索引节点

索引节点（inode）。在Linux系统中，内核为每一个新创建的文件分配一个inode（索引结点），每个文件都有一个唯一的inode号，我们可以将inode简单理解成一个指针，它永远指向本文件的具体存储位置。文件属性保存在索引结点里，在访问文件时，索引结点被复制到内存里，从而实现文件的快速访问。系统是通过索引节点（而不是文件名）来定位每一个文件。

**软链接**可以理解为Windows中的快捷方式，**硬链接**可以理解为在源文件基础上复制的新文件。

## 软连接(符号链接)

- 文件A和文件B inode 节点虽然不一样，但是文件A的内容就是文件B的路径 

- 读取文件A的时候，系统会自动将访问者导向文件B 

- 因此，无论打开文件A还是打开文件B，最终读取到的内容都是文件B的内容 

- 这种时候/情况，文件A称为文件B的 软链接 ( `soft Link `) 

- 意味着文件A指向了文件B，删除文件A是不会对文件B有影响的，但是**如果删除文件B就会对文件A 产生影响**，文件A无法打开	

  - 语法： 

  - `ln -s 源文件 软连接文件名字`

    ln -s B A(给B创建一个快捷方式A)

## 硬链接Hard Link

- 一般情况下，文件名和 inode 节点是一一对应的关系，也就是每一个 inode 节点对应一个文件名 

- 但是 linux 系统允许多个文件名指向同一个 inode 节点，意味着可以用不同的文件名访问相同的 内容

- 对于这个文件内容的进行修改，会影响其他文件名访问那个文件内容，但是**删除一个文件名，不影响其他文件名的使用的**。这个链接称为 硬链接 （`hard link`）

- 语法：

  - `ln 源文件 硬连接文件名`

    ln B A

  - 为源文件创建一个硬链接

==注意：==

- **硬链接完全支持跨目录创建文件链接，限制只有两个核心：**
- **① 必须在同一文件系统；**
- **② 只能用于普通文件，不能用于目录。**

## **软链接 使用相对路径的错误做法**：

> ```bash
> zhanghaoboo@zhanghaoboo-virtual-machine:~$ pwd
> /home/zhanghaoboo
> 
> zhanghaoboo@zhanghaoboo-virtual-machine:~$ ln -s file.txt link_dir/mylink
> ```
>
> - **原因**
>
> `ln -s`会把字符串 `file.txt` 存进 `/home/user/link_dir/mylink` 这个链接里。
>
> 之后，当你访问 `/home/user/link_dir/mylink` 时，系统看到链接内容为 `file.txt`，这是相对路径，于是它从**链接所在的目录** `/home/user/link_dir/` 开始找，最终尝试去找
> `/home/user/link_dir/file.txt` —— 这个文件根本不存在，链接**失效**。
>
> **`ln -s 源 链接` 中的“源”如果是相对路径，是以“链接文件所在的目录的起点”为基准的，和你在哪个目录下执行命令无关。**
>
> > `ln`站在的是链接文件所在的目录,而不是源文件所在目录,链接后通过这个链接文件找源文件时,是从自己这个链接文件的目录下开始,找源文件
> >
> > - 如果是在当前工作目录下有`file.txt`,源文件路径直接写相对路径`file.txt`,而在另一个目录下进行链接,如在`link_dir/mylink`中存放链接文件,则下次打开`link_dir/mylink`文件时,找它指向的源文件时只会是:`link_dir/mylink/file.txt`,会导致链接失效
> >
> > - 如果是在当前工作目录下有`file.txt`,源文件路径写相对路径`../file.txt`时,在`link_dir/mylink`中存放链接文件,则下次打开`link_dir/mylink`文件时,找它指向的源文件位置信息为:`/home/user/file.txt`
> >
> > 链接文件的起始目录`link_dir` 再解析`..`,回到`/home/user/`,再查找`/home/user/file.txt`

**硬链接不用关心路径问题**：

- **符号链接**：建的时候写什么路径，它就存什么；访问时从这个路径字符串去跳转。
  → 有基于链接位置的相对路径坑。
- **硬链接**：建的时候用路径**仅为了找到 inode**，建成后链接只记 inode 号，和路径彻底脱钩。
  → **完全没有相对路径解析的坑**，你只需要保证执行 `ln` 命令时，系统能通过你给的路径找到源文件即可。
