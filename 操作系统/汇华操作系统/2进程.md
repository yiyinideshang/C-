# 进程与程序的区别

- 程序是静态的概念（是指令的有序集合 ，“程序文件”），进程是一个动态概念（动态产生，动态消 亡）
- 进程是一个程序的一次执行活动，一个程序可以对应多个进程。(**进制是程序的执行过程**)
- 进程是一个独立的活动单位，进程是竞争系统资源的基本单位。（**进程是资源分配(和调度)的基本单位**）

# 进程的定义：

程序在计算机中的一次执行过程，是资源分配和调度的基本单位

**进程 = 程序块 + 数据块 + PCB + 堆栈**

# 处理机调度的三个层次

- 高级调度(长程调度/**作业**调度)
  -  外存-》内存
  - 主要用于多道批处理系统中
- 低级调度(短程调度/**进程**调度) 
  - 内存-》CPU
  - 调用频率最高
  - 应用在于多道批处理、分时和实时OS
- 中级调度(中程调度/**内存**调度)
  - 把那些暂时不能运行的进程调到外存等待
  - 把那些已经具备运行条件的就绪进程重新调入内存，并修改它们的状态为就绪态
  - 目的：提供高内存利用率和系统吞吐量

## 相关时间

调度相关计算：调度开销、**平均周转时间、带权周转时间、响应比**

==周转时间：==

- 是指从作业被提交给系统开始，到作业完成为止这段时间间隔(作业周转时间)

==等待时间==

- 周转时间 - 运行时间

平均周转时间

- 每个周转时间的和 / 个数

带权周转时间

- 周转时间/运行时间

响应时间

- 从到达到首次运行的时间

==响应比==

- 响应比=周转时间/运行时间=(等待时间+运行时间)/运行时间 = 1 + 等待时间/运行时间==

## 先来先服务`FCFS`

画**甘特图**(`Gantt chart`)

- **优点：**
  - 算法简单
- **缺点**：
  - 效率低
  - 对长作业有利，对短作业不利
  - 有利于CPU繁忙型作业，不利于I/O繁忙型作业
    - 来一个执行一个，CPU可以不闲下来
    - 某个作业来了之后就进行I/0操作，CPU就闲下来了

## 短作业优先`SJF`或`SPF`

既可以用于作业，也可用于进程

对于进程，分抢占式和抢占式(也称为**最短剩余时间优先调度**)

- **优点**：
  - ==平均等待时间和平均周转时间最优算法==
- **缺点**：
  - 只能估算进程的运行时间（估值不准确），所以通常用于作业调度
  - 对长作业不利
  - 人-机无法实现交互
  - 完全未考虑作业的紧迫程度

## 优先级调度`PR`

每个进程都有一个优先数

既可用于作业调度，也可用于进程调度。

- **优点**
  - 实现简单，考虑了进程的紧迫程度
  - 灵活，可模拟其它算法
- 缺点：
  - 饥饿 ——低优先级的进程可能永远得不到运行
- 解决方法
  - 老化 —— 视进程等待时间的延长提高其优先数

## 高响应比优先调度算法`HRRN`

（PR的特例`HRRN`）

既考虑作业的等待时间，又考虑作业的运行时间

==响应比=周转时间/运行时间=(等待时间+运行时间)/运行时间 = 1 + 等待时间/运行时间==

属于动态优先级算法： 响应比越大，优先级越高  

**特点：**

- 如等待时间相同，运行时间越短，优先级越高，类似于`SJF`
- 如运行时间相同，取决于等待时间，类似于`FCFS`
- 可随其等待时间的增加而提高，进程都可得到服务，不会产生饥饿

**缺点**：

- 每次调度之前，都需要计算响应比，增加系统开销

## 时间片轮转`RR`

**特点：**

- 专为分时系统设计

- 抢占式调度算法

优点：

- 有利于人机交互

时间片太大 ，相当于先来先服务

时间片太小 ， 导致切换频繁

## 多级反馈队列调度算法

![多级反馈队列](D:\Typora\typora_work\操作系统\汇华操作系统\多级反馈队列.png)

- **特点**：

  - 将不同类型或性质的进程分配在不同的就绪队列

  - 不同的就绪队列采用不同的调度算法

  - 就绪队列之间设置不同的优先级

- **优点**：

  - 是目前公认较好的调度算法

- **调度过程**：
  - 设置多级就绪队列，各级队列优先级从高到低，时间片从小到大
    - 新进程到达时先进入第1级队列，按`FCFS`原则，排队等待被分配时间片。若用完时间片进程还未结束，则进程进入下一级队列队尾。
    - 如果此时已经在最下一级队列，则重新放入最下级队列的队尾
    - 只有第K级队列为空时，才会为第k+1级队头的进程分配时间片

# 死锁：

## 必要条件

- 互斥
  - 在一段时间内，某资源只能被一个进程占用

- 请求与保持
  - 进程已经占用了至少一个资源，但又提出了新的资源请求，而被该请求的资源已经被其他进程占有，此时请求进程被阻塞，同时其对自己占有的资源保持不放

- 不可剥夺(不可抢占)
  - 进程已获得的资源在未使用完之前不能被抢占，只能在进程使用完时由其自己释放。

- 循环等待


## 死锁处理

### 	预防死锁（破坏必要条件）

- 一次性请求所有运行所需的资源-----**破坏请求与保持条件**
- 资源编号有序请求、资源预分配、. 资源的有序分配策略-------**破坏循环等待条件**

### 	检测死锁（资源有向图）

- **如果图没有环，那么不会产生死锁**
- **如果图有环，不一定会产生死锁**
  - ○圆圈表示进程结点

  - 方块表示资源结点

  - 方块->圆圈 表示分配边

  - 圆圈->方块 表示请求边
- **死锁定理：**
  - 证明**S状态为死锁状态的充分必要条件：当且仅当S状态的资源分配图是不可完全简化的**

### 	避免死锁

- 银行家算法

### 解除死锁

- 撤销、终止进程
- 资源抢占（**从死锁进程中强制剥夺资源**--资源剥夺法）
- 死锁进程退回到上一个检查点
- 重启系统

## 死锁避免

系统有同类资源m个，供n个进程共享，若每个进程对资源的最大需求量为k，试问:当m,n,k的值分别为下列情况时，是否会发生死锁?

必须保证至少有一个进程能得到所需的全部资源并执行完毕

如

| 序号 | m    | n    | k    | 是否会死锁  |
| ---- | ---- | ---- | ---- | ----------- |
| 1    | 6    | 3    | 3    | 是 6< 3*2+1 |
| 2    | 3    | 3    | 2    | 是 3<3*1+1  |
| 3    | 9    | 3    | 3    | 否 9>3*2+1  |

==**当m>= n(k-1)+1 时，一定不会发生死锁**==

==**死锁避免实现的依据是防止系统进入不安全状态**==

系统安全一定无死锁的状态

系统不安全不一定是死锁导致的

死锁一定导致系统不安全

# 进程同步与互斥：

## 进程间的制约关系

## 临界资源（独占资源）

- 系统中某些资源**一次只允许一个进程使用**，称这样的资源为临界资源或**互斥资源**或**共享变量**
  - 举例：
  - 1、打印机、磁带机、扫描仪等物理设备
  - 2、消息队列、变量、数据、文件等软件资
- 临界区互斥机制遵循准则：空闲让进、忙则等待、有限等待、让权等待
- 同步机制：信号量（P/V 操作）、`Peterson` 方法、`TestAndSet` 指令等（信号量可实现让权等待）
- 经典问题：生产者 - 消费者问题
