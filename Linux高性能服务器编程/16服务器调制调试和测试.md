**`ulimit`** 命令是 `Linux` 系统中用于控制 `shell` 程序资源的内建指令。它允许用户设置和查看进程资源限制，如文件大小、CPU 时间、进程数量等。这些限制有助于管理系统资源的使用，防止过度使用导致的性能问题或系统崩溃。

```bash
ulimit [选项] [限制值]    
```

# grep命令

```bash
grep [选项] 模式 [文件...]

```

- **模式**：要搜索的字符串或正则表达式。
- **文件**：要搜索的目标文件。如果省略文件，则从标准输入读取（例如通过管道传递的数据）。

## 常用选项

| 选项         | 作用                                                         |
| :----------- | :----------------------------------------------------------- |
| `-i`         | 忽略大小写                                                   |
| `-v`         | 反向匹配，输出不包含模式的行                                 |
| `-n`         | 显示匹配行的行号                                             |
| `-c`         | 只输出匹配的行数，不显示具体内容                             |
| `-l`         | 只显示包含匹配内容的文件名，不显示具体行                     |
| `-L`         | 只显示不包含匹配内容的文件名                                 |
| `-r` 或 `-R` | 递归搜索子目录中的文件                                       |
| `-w`         | 匹配整个单词（单词由字母、数字、下划线组成，两侧为非单词字符） |
| `-x`         | 匹配整行（行内容必须完全等于模式）                           |
| `-e`         | 指定多个模式，例如 `grep -e "pattern1" -e "pattern2" file`   |
| `-f`         | 从文件中读取模式，每行一个                                   |

# ps命令

**ps**（process status）是Linux系统中用于查看进程信息的常用命令，功能类似于Windows的任务管理器。它可以显示**进程ID（PID）**、**所属用户**、**CPU/内存占用**、**运行状态**、**启动时间**以及**执行命令**等信息，对于系统监控、故障排查和进程管理非常重要。	

**常用选项**

- **-a**：显示所有终端上的进程，包括其他用户的进程
- **-u**：显示详细信息（用户、CPU、内存占用等）
- **-x**：显示无控制终端的进程
- **-e** 或 **-A**：显示系统中所有进程
- **-f**：显示完整格式，包括命令行参数(包含 UID、PID、PPID、C、STIME、TTY、TIME、CMD 等字段）。
- **输出字段含义**（`ps -ef`）
  - **UID**：进程所属用户
  - **PID**：进程ID
  - **PPID**：父进程ID
  - **%CPU / %MEM**：CPU与内存占用率
  - **STAT**：进程状态（R运行、S睡眠、T停止、Z僵尸等）
  - **CMD**：启动该进程的命令
- **-l**：显示更详细的长格式信息
- **`| grep`**：管道符将 `ps` 的输出传递给 `grep` 命令，用于过滤包含特定关键字（如进程名、PID）的行。

**常见用法示例**

````bash
# 1. 查看当前用户的进程
ps

# 2. 查看系统所有进程
ps -e
ps -A

# 3. 查看详细进程信息
ps -ef

# 4. 查找特定进程
ps -ef | grep nginx

# 5. 查看指定用户的进程
ps -u root
````

**配合其他命令的应用**

- **查找并结束进程**

```bash
ps -ef | grep nginx

kill -9 1608
```

- **实时监控进程**：使用 *`top`* 或 *`htop`*
- **查看进程占用端口**：

`netstat -nlp | grep 8080`

**总结** *`ps`*命令是`Linux`运维和开发中必备的进程管理工具，结合*`grep`*、*`kill`*、*`top`*等命令，可以高效完成**进程查询、监控与管理**任务。熟练掌握其参数和组合用法，将显著提升系统维护效率

# 16-1 最大文件描述符数

==（参见原书324-325页）==

文件描述符限制分为两个级别：

- **用户级限制**：单个用户运行的所有进程总共能打开的文件描述符数。
- **系统级限制**：所有用户总共能打开的文件描述符数（即内核全局限制）。

## 用户级文件描述符数限制

### 查看当前限制

```bash
ulimit -n	
```

### 临时修改（仅当前会话有效）

```bash
ulimit -n <max-file-number>
```

### 永久修改

通过 PAM 模块的 `limits.conf` 文件配置。编辑 `/etc/security/limits.conf`，添加以下两行（注意 `soft` 而非 `sort`）：

```bash
<username|*>  soft  nofile  <max-file-number>
<username|*>  hard  nofile  <max-file-number>
```

- `soft`：软限制，内核强制的上限值，可通过 `ulimit -n` 临时增大，但不能超过 `hard` 限制。
- `hard`：硬限制，软限制的上限。

**生效方式**：修改后需要**重新登录该用户**或重启相关服务（因为限制是在用户会话建立时由 PAM 读取并应用的）。重新登录后可用 `ulimit -n` 验证。

## 系统级文件描述符数限制

系统级限制由内核参数 `fs.file-max` 控制，它规定了系统范围内所有进程可打开的文件描述符总数。

### 临时修改

使用 `sysctl` 命令：

```bash
sysctl -w fs.file-max=<max-file-number>
```

或直接写入 `/proc/sys/fs/file-max`：

```bash
echo <max-file-number> > /proc/sys/fs/file-max
```

### 永久修改

编辑 `/etc/sysctl.conf`（或 `/etc/sysctl.d/` 下的 `.conf` 文件），添加：

```bash
fs.file-max = <max-file-number>
```

然后执行以下命令使修改立即生效（重启后也自动加载）：

```bash
sysctl -p
```

# 16-2 调整内核参数

==（参见原书325-326页）==

Linux 内核的大部分模块（核心模块和驱动程序）在 `/proc/sys` 虚拟文件系统下提供了可调参数接口。每个参数对应一个文件，文件名即为参数名，文件内容为参数值。

## `sysctl` 命令

`sysctl` 是管理内核参数的命令行工具，它提供统一的点分格式（如 `net.core.somaxconn`）来访问 `/proc/sys` 下的文件。

### 核心功能

- **查看**：列出当前所有内核参数的值。
- **临时修改**：立即生效，重启后失效。
- **持久化配置**：将设置写入配置文件，重启后仍有效。

### 常用用法

| 命令                            | 说明                                                         |
| :------------------------------ | :----------------------------------------------------------- |
| `sysctl -a`                     | 显示所有可配置的内核参数及其当前值（可结合 `less` 分页查看） |
| `sysctl <parameter>`            | 查看指定参数的值，例如 `sysctl net.ipv4.ip_forward`          |
| `sysctl -w <parameter>=<value>` | 临时修改参数，例如 `sysctl -w net.core.somaxconn=1024`       |
| `sysctl -p`                     | 从默认配置文件 `/etc/sysctl.conf` 加载设置                   |
| `sysctl -p /path/to/file`       | 从指定文件加载设置                                           |

## 重要内核参数

### 16-2-1 `/proc/sys/fs` 目录下的部分文件

- **`fs.file-max`**：系统级文件描述符总数限制（==见16-1节==）。
- **`fs/epoll/max_user_watches`**：单个用户可注册到 `epoll` 实例的事件总数上限。对于高并发网络服务器，可能需要适当调大。

### 16-2-2 `/proc/sys/net` 目录下的部分文件

网络相关参数主要位于 `core`、`ipv4`、`ipv6` 等子目录。

- **`net.core.somaxconn`**
  系统级全连接队列（已完成三次握手、等待 `accept()` 的连接）的最大长度上限。应用程序调用 `listen(sockfd, backlog)` 时传入的 `backlog` 参数将被内核限制为不超过此值，即实际全连接队列长度 = `min(backlog, net.core.somaxconn)`。
  *补充*：在 Linux 2.2 之后，`backlog` 专指已完成连接队列的长度，与半连接队列（由 `tcp_max_syn_backlog` 控制）分离。==见本书76页==
- **`net.ipv4.tcp_max_syn_backlog`**
  半连接队列（`SYN_RECV` 状态）的最大长度。当 SYN 泛洪攻击发生时，增大此值可缓解影响。
- **`net.ipv4.tcp_wmem` 和 `net.ip.tcp_rmem`**
  分别控制 TCP 发送缓冲区和接收缓冲区的内存大小，包含三个值：最小值、默认值、最大值。==见本书49页==
- **`net.ipv4.tcp_syncookies`**
  是否开启 SYN Cookies 机制（0 关闭，1 开启）。开启后可在半连接队列满时防止 SYN 泛洪攻击。

## 内核参数的修改方法

### 临时修改

- 直接写文件：`echo <value> > /proc/sys/path/net/parameter`   如：									`echo 2048 > /proc/sys/net/core/somaxconn`
- 使用 `sysctl -w`：`sysctl -w net.core.somaxconn=2048`

### 永久修改

编辑 `/etc/sysctl.conf`（或 `/etc/sysctl.d/` 下的自定义 `.conf` 文件），按行添加：

```bash
net.core.somaxconn = 2048
net.ipv4.tcp_syncookies = 1
```

然后执行 `sysctl -p` 使更改立即生效，重启后也自动应用。

------

**注意事项**：

- 修改用户级文件描述符限制（`limits.conf`）后无需执行 `sysctl -p`，只需重新登录。
- 内核参数的调整应结合服务器硬件和应用需求谨慎进行，不当的设置可能降低系统性能或稳定性。

### 发生：ptrace: 不允许的操作 原因

- 你通过 `./a.out &` 启动的进程（PID 24443）是由当前 shell 直接创建的子进程。
- 但 GDB 本身是一个独立的进程，并不是该进程的父进程，所以默认的 `ptrace` 权限不允许它附加。
- 相关内核参数 `/proc/sys/kernel/yama/ptrace_scope` 控制了这一行为。它的常见取值：
  - **0**：允许任何进程附加（传统行为，不安全）。
  - **1**（默认）：只允许进程附加到其直接子进程（且子进程需处于可跟踪状态）。
  - **2**：仅允许具有 `CAP_SYS_PTRACE` 权限的进程附加（如 root）。
  - **3**：禁止任何附加（通常不启用）。

你的系统上该参数的值很可能为 **1**，所以附加被拒绝。

### 解决方法

#### 1. 临时修改 ptrace_scope 为 0（推荐测试用）

```bash
sudo sysctl -w kernel.yama.ptrace_scope=0
```

然后再次运行 `gdb -p 24443`。
**注意**：这会降低系统安全性（允许任意进程调试其他进程），调试完成后建议恢复：

```bash
sudo sysctl -w kernel.yama.ptrace_scope=1
```

#### 2. 以 root 用户运行 GDB

```bash
sudo gdb -p 24443
```

但以 root 运行 GDB 存在风险，不建议作为常规操作。
