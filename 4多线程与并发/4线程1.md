# 线程

前面讲到进程：为了**并发执行**`任务`（**程序**），现代操作系统才引进 `进程` 的概念

分析：

- **创建开销问题**：创建一个进程开销：大 
  - 子进程需要拷贝父进程的整个地址空间

- **通信开销问题**：进程间的通信 
  - 需要用第三方（如：**内核**）
  -  `P1 -> copy -> 内核 -> copy -> P2`
  -  进程间通信代价或者开销也是很大的。进程的地址空间是独立，要通信的话需要用第三方的空间。

于是，就有人提出能不能在 同一个（**同一个进程内部**）进程地址空间中进行任务的并发：**线程/轻量级进程**

# 线程Thread

线程是一个比进程更小的**活动单位**。它是进程中的**执行路径**（执行分支），线程也是并发的一种形式。 进程内部可以存在多个线程，它并发执行，但是进程内部的所有的线程**共享整个进程的地址空间**。是操作系统能够进行**调度和分派**的最小单位。

| 特性         | 进程                                                | 线程                                                   |
| :----------- | :-------------------------------------------------- | :----------------------------------------------------- |
| **资源拥有** | **资源分配的独立单位**，拥有独立的代码、数据空间。  | **共享进程的资源**，**所有线程共享同一片内存空间。**   |
| **切换开销** | 大。切换进程需要保存和恢复整个内存空间、寄存器等。  | 小。只需保存和恢复少数寄存器、栈等少量状态。           |
| **通信**     | 复杂。需要进程间通信（`IPC`），如管道、消息队列等。 | 简单。因为它们共享内存，可以直接读写同一变量。         |
| **健壮性**   | 高。一个进程崩溃不会影响其他进程。                  | 低。一个线程崩溃可能导致整个进程崩溃（因为共享资源）。 |
| **比喻**     | 一个独立的“工厂”                                    | 工厂里的“流水线”                                       |

# 线程特点

- 创建一个线程要比创建进程开销要小很多
  - 创建一个线程，不需要拷贝进程的地址空间

- 实现线程间的通信会更加方便
  - 因为**进程内部所有线程共享整个进程地址空间**
- 线程也是一个动态概念：
  - ## 线程(进程)状态图
    
    - 就绪态： `ready` 
    - 运行态： `running`
    - 阻塞态： `blocking`

# OS为什么要引入进程和线程

**引入进程**的目的：更好的使多道批处理程序并发执行，提高资源利用率和系统吞吐量。

**引入线程**的目录：减少进程在并发执行时所付出的时空开销，提高操作系统的并发性能。

**线程最直接的理解就是轻量级进程**

有了线程的概念后，

- **资源分配的单位还是进程**。

- 系统的**调度单位**就从 进程变成**线程** 

线程是进程内部的一个指令的**执行分支**，多个线程就是多个**指令序列**的**并发执行**。这些指令必须在函数 内部，线程的指令部分肯定是封装一个函数的内部的。这个函数，就称之为：**线程函数**，一个线程在创建之后，要执行的指令全部封装在该函数内部，这个线程函数执行完毕之后，该线程的任务也就执行完了。

# 进程和线程的区别

![6f5ce5e64edada25c3998f00380fec8](D:\Typora\typora_work\4多线程与并发\6f5ce5e64edada25c3998f00380fec8.png)

- 调度：
  - 在引入内核线程后，进程不再是调度的最小单位
  - 线程是调度的最小单位
- 并发性：
  - 多个进程之间可以并发执行
  - 一个进程的多个线程也能够并发执行
- 拥有资源：进程始终是资源分配的最小单位，而线程只拥有很少的资源用来确保自身能够独立运行 
  - 如：每个线程都有用来控制线程运行的	线程控制块 （thread control block ,`TCB`）
  - 线程除了拥有自己的少量资源外，还允许多个线程共享它们共属的进程所拥有的资源
- 独立性：
  - **进程之间** 独立性很高，每个进程都拥有独立的地址空间和其他资源。进程间除了共享**全局变量**外，不允许自身以外的进程访问自己地址空间的地址
  - **同一进程的不同线程之间** ，这些线程 往往是为了提高并发性以及满足进程间的合作需求而创建的，它们可以**共享进程的内存地址空间和资源**
- 系统开销：
  - 进程的通信、切换开销大
  - 线程的通信、切换开销小
- 多处理机：
  - 传统的进程，即单线程进程 ，一个进程只能在一个处理机上
  - 引入线程的进程，即多线程进程，一个进程可以在不同处理机上并发执行

# 线程的实现

## 内核支持线程

内核支持线程（kernel supported thread，`KST`）

- ### 优点

  - 在多处理机上，内核能够同时调度同一进程中的多个线程并发执行

  - 如果进程中的一个线程被阻塞，则内核可以调度该进程的其他线程在占有处理机并运行，也可以运行其他进程的线程(**一个线程被阻塞，对其他线程无影响)**

- ### 缺点

  - **内核级线程切换**：需要用户态↔内核态切换，保存/恢复更多状态，开销较大。
  
  - 但对于用户的线程切换而言，内核级线程的切换开销较大
  - 创建和管理线程时需要系统调用，代价较高

## 用户级线程

用户级线程(user level thread,`ULT`)，

- ### 特点

  - 在用户空间中实现的，

  - 对线程的创建、撤销、同步和通信 等功能无序内核支持，即`ULT`与内核无关，内核完全不知道`ULT`的存在
  - 对于设置了`ULT`的系统，其调度的单位依然是**进程**

- ### 优点

  - **用户级线程切换**：完全在用户态进行，仅需少量寄存器操作，开销很小。
  - 线程的切换不需要转换到内核空间，节省了模式切换的开销

- ### 缺点

  - 当线程执行一个系统调用时，不仅该线程会被阻塞，而且**进程中的所有线程均会被阻塞**

## 两种线程的组合方式

- 多对一模型
  - 多个`ULT`映射到一个`KST`上
- 一对一模型
  - 每个`ULT`映射到一个`KST`上
- 多对多模型

### 线程的取消`pthread_cancel`

被别人干掉 

- `cancel` ：被别人取消（其他线程调用 `pthread_cancel` ） 
  - `t1:pthread_cancel(t2)` 
  - `t1` 调用取消函数，取消 `t2` , `t2` 不一定会被取消 
    - 因为 t2 能不能被其他线程取消，取决于 t2 线程的一个属性： `取消属性` 
    - 它是否可以被 `cancelled`

### 资源分离属性 `pthread_detach`

`detachstate` ：分离属性：

- `PTHREAD_CREATE_JOINABLE` ：指定线程是可被回收的 （**线程创建时的默认属性**）
- `PIHREAD_CREATE_DETACH` ：调用线程脱离与进程中其他线程的同步。（脱离与其他线程的同步的线程叫做 “ 脱离线程 ”）
  - 脱离线程在推出时自行释放其占用的系统资源。
  - 可以使用 `pthread_detach`函数直接将线程设置为 脱离线程


```c++

PTHREAD_DETACH(3)
NAME
	pthread_detach - detach a thread
SYNOPSIS
```

### pthread_join和pthread_detach函数对比

| 特性         | pthread_join             | pthread_detach             |
| :----------- | :----------------------- | :------------------------- |
| **资源回收** | 手动调用，显式回收       | 自动回收                   |
| **同步**     | 阻塞调用，等待线程结束   | 不等待，立即返回           |
| **返回值**   | 可以获取线程返回值       | 无法获取返回值             |
| **线程状态** | 用于可连接线程           | 用于分离线程               |
| **调用次数** | 每个线程只能被 join 一次 | 每个线程只能被 detach 一次 |

#### ==示例1：`pthread_detach(`资源分离==

```c++
#include<iostream>
#include<pthread.h>
#include<unistd.h>

//我定义的线程函数
void *MyDefineThreadFunction(void *args)
{   
    //设置资源分离
    pthread_detach(pthread_self());  // 子线程将自己设置为分离状态
    
    std::cout << "子线程开始执行（已分离）" << std::endl;
    for(int i = 0;i<10;i++)
    {
        std::cout << "子线程 " << i << std::endl;
        sleep(1);
    }
    std::cout << "子线程退出（自动清理资源）" << std::endl;
    return nullptr;//结束线程
}

int main()
{
    pthread_t tid;
    pthread_create(&tid,NULL,MyDefineThreadFunction,NULL);

    for(int i = 0;i<5;i++)
    {
        std::cout<<"主线程:"<<i<<std::endl;
        sleep(1);
    }
   
    // 测试：尝试 join 来等待和回收tid指定的线程
    std::cout << "尝试 join来等待和回收tid指定的线程 ..." << std::endl;
    int join_result = pthread_join(tid, nullptr);// pthread_join成功返回0
    if (join_result != 0) {//pthread_join 失败返回-1
        std::cout << "证明线程确实已被分离" << std::endl;
        std::cout << "分离状态的线程在终止时，系统会自动回收该线程占用的资源，"
        <<"而不需要其他线程调用 pthread_join 来等待和回收。" << std::endl;
    }

    // 给分离线程足够时间执行完毕
    // 因为进程会等待所有线程（包括分离线程）结束后才完全退出
    sleep(6);  // 确保子线程能执行完10次循环

    std::cout<<"主线程退出"<<std::endl;

    return 0;
}
```

**当子线程循环10次，而父线程循环5次时，**

主线程不会因为其他线程的结束而结束，但是其他线程的结束会因为主线程的结束的结束而结束，因为主进程结束后会退出进程，所以进程的其他线程都会终止结束。

所以为了正常运行程序，一般会让主线程等待其他线程的结束后再结束。

````c++
#include<iostream>
#include<pthread.h>
#include<unistd.h>
#include "assert.h" 

void *pthread_fun(void *arg)
{
````

**主线程等待其他线程的结束后再结束。:使用`ptheread_join()`**

其他线程没有结束的话，主线程会在pthread_join()处阻塞。所以主线程会在其他线程结束之后再结束，程序正常退出。

```c++
#include<iostream>
#include<pthread.h>
#include<unistd.h>
#include "assert.h" 

void *pthread_fun(void *arg)
{
    for(int i = 0; i < 10; i++)
    {
        std::cout<<"子线程"<<i<<std::endl;
        sleep(1);
    }
    std::cout<<"子线程退出"<<std::endl;
    return nullptr;//结束线程
}

int main()
{

    pthread_t tid;
    int res = pthread_create(&tid,NULL,pthread_fun,NULL);
    assert(res == 0);

    for(int i = 0; i < 5; i++)
    {
        std::cout<<"父线程"<<i<<std::endl;
        sleep(1);
    }

    char *s = NULL;
    pthread_join(tid,(void**)&s);

    std::cout<<"主线程退出"<<std::endl;
    exit(0);
}
```
